# 우리 반 비밀친구 개인정보 처리방침 초안

**작성일:** 2026-09-27  
**상태:** 운영 주체·처리 근거·보유 기간·위탁 및 국외 이전·권리 처리 절차 확인 전 초안. 정식 개인정보 처리방침으로 게시하거나 실제 학생 데이터를 받는 근거로 사용하지 않는다.

이 초안은 현재 코드의 처리 흐름을 정리한 검토 문서다. 실제 학생에게 서비스를 제공하기 전에 아래 `확정할 사항`을 결정하고, 학교 또는 서비스 운영자의 개인정보 담당자 검토를 거쳐 시행일을 붙인 최종본을 누구나 쉽게 찾을 수 있는 위치에 공개한다. 개발 Firebase 프로젝트 `manito-938cc`와 Vercel 사이트는 현재 가상 학생 데이터 검증용이다.

## 1. 개인정보 처리자와 문의

`[개인정보처리자 명칭]`은(는) 우리 반 비밀친구의 교사 계정, 학급과 회차 운영, 학생 카드 로그인과 안전 대응에 필요한 개인정보를 처리한다. 개인정보 보호책임자 또는 담당 부서는 `[담당자/부서]`, 연락처는 `[공식 이메일·전화]`이다.

**확인 필요:** 학교가 학급 운영을 결정하고 서비스 개발자가 위탁받는 구조인지, 서비스 운영자가 독립적으로 목적·수단을 결정하는지 먼저 정해야 한다. 교사가 계정을 만든다는 이유만으로 운영 주체가 자동 결정되지는 않는다.

## 2. 처리 목적과 항목

| 대상·목적 | 현재 코드에서 처리하는 주요 항목 | 수집·생성 경로 |
|---|---|---|
| 교사 로그인·승인 | Google/Firebase 인증 UID, 이메일, 표시 이름, 프로필 정보, 승인 상태 | Google 로그인, Firebase Authentication, 운영자 승인 |
| 학급·학생 카드 | 학급 이름·학년도·학년군·학급 코드, 학생 표시 이름·내부 UID, 카드 검증용 해시·재출력용 암호문·잠금·세션 버전, 마지막 로그인 시각 | 교사 등록, 학생 카드 로그인·담당 교사 재출력 |
| 회차·매칭·활동 | 참가 여부, 제외 관계, 비밀 배정, 미션 상태, 쪽지 원문·전달 상태·발신자, 도움 요청·신고·회고·감사 반응 | 교사 설정 및 학생 활동 |
| 안전·권리 대응 | 교사의 민감 정보 열람·카드 재발급 등 감사 기록, 학생의 정보 열람·정정·삭제 요청 내용과 상태 | 서비스 사용 및 요청 접수 |
| 접속·오류 처리 | 호스팅·인증·서버 제공업체가 처리할 수 있는 접속 시간, IP 주소, 기기·브라우저 정보, 오류·운영 로그 | Vercel·Firebase 인프라. 구체 항목·보존 기간 확인 필요 |

학생에게 이메일·휴대전화·SNS 계정을 요구하지 않는다. 신규·재발급 카드의 코드는 검증용 해시와 재출력을 위한 서버 전용 암호문으로 보관한다. 담당 교사가 재출력할 때 권한을 확인하고 열람 감사 기록을 남기며, 기존 암호문이 없는 카드는 원문 복원이 불가능해 확인 후 재발급한다. 표시 이름이 별칭이어도 학급에서 학생을 식별할 수 있으면 개인정보로 취급한다. 교사는 안전 대응을 위해 배정 전체와 쪽지의 발신자·원문을 별도 권한 검사를 거쳐 열람할 수 있고, 이 열람은 감사 기록으로 남긴다.

## 3. 처리 근거와 아동 안내

학생 데이터의 적용 근거는 `[학교·운영 주체가 확정할 근거]`이다. 동의를 근거로 해야 하는 처리라면 만 14세 미만 아동의 법정대리인 동의를 받고 이를 확인하는 절차를 마련한다. 교사가 학생을 등록하거나 학생이 카드를 사용한 사실만으로 법정대리인 동의를 받은 것으로 간주하지 않는다. 학생에게는 쉬운 문장으로 무엇을 기록하고 누가 보는지 별도 안내한다.

## 4. 보유 기간과 파기

| 기록 | 운영 확정 전 기입할 기간·기산점 |
|---|---|
| 교사 계정·승인 이력 | `[기간·종료 조건]` |
| 학급·학생 카드·명부 | `[학급 종료 또는 철회 후 기간]` |
| 회차·배정·미션·쪽지·도움·회고 | `[회차 또는 학년도 종료 후 기간]` |
| 권리 요청·감사 기록 | `[처리 완료 후 기간과 예외 보존 근거]` |
| 호스팅·인증·백업 로그 | `[제공업체별 기간 및 삭제 반영 지연]` |

목적이 끝나거나 보유 기간이 지나면 정해진 절차에 따라 삭제한다. 현재 구현은 **학급 전체 삭제**를 지원하지만 학생 한 명의 모든 관계 문서·다른 학생의 수신함 사본·백업을 삭제하는 기능은 완성되지 않았다. 따라서 개별 삭제 완료나 백업 즉시 삭제를 약속하지 않는다. 법령상 별도 보존이 필요하면 근거·항목·기간을 구분해 적는다.

## 5. 제3자 제공, 처리 위탁과 국외 이전

학생 간에는 배정된 친구에 한해 승인된 메시지를 익명으로 보여준다. 담당 교사는 안전 대응을 위해 발신자를 확인할 수 있다. 외부 제3자 제공이 있는지는 실제 운영 계약과 업무 흐름을 확인해 `[해당 없음 또는 제공받는 자·목적·항목·기간]`으로 기재한다.

현재 개발 구성은 **Google/Firebase(Authentication, Firestore, Cloud Functions)**와 **Vercel(웹 배포)**을 사용한다. 각 제공업체에 맡기는 업무, 계약 주체, 처리 항목, 국외 이전 해당 여부·이전 국가·보존 기간·거부 방법은 계약 및 실제 설정을 확인한 뒤 표로 공개한다. Firestore와 Functions를 서울 리전으로 설정한 것만으로 전체 데이터가 국내에서만 처리된다고 단정하지 않는다.

## 6. 권리 행사와 안전 대응

학생은 서비스 안에서 열람·정정·삭제 요청을 접수하고 본인의 접수 상태를 볼 수 있다. 법정대리인은 `[공식 연락 경로]`로 요청할 수 있다. 운영자는 본인 또는 법정대리인 여부를 확인한 뒤 `[처리 절차·기한]`에 따라 결과를 안내하며, 이의 제기 방법은 `[방법]`이다. 현재 앱의 `접수됨`은 요청 처리 완료를 뜻하지 않는다.

학생은 불편한 쪽지를 숨기고 교사에게 도움을 요청할 수 있다. 학생에게 전체 명단·전체 배정표·발신자 신원을 공개하지 않는다. 교사 및 학생별 권한 검사, 카드 실패 잠금, 세션 버전, 서버 매칭, 비밀 문서 분리, 공용기기 로그아웃·메모리 인증을 적용한다. 구체적인 내부 접근 권한과 침해사고 대응 절차는 운영 주체가 확정한다.

## 7. 자동 수집 장치와 변경

앱 코드는 광고·방문 분석 도구와 영구 Firestore 오프라인 캐시를 넣지 않았다. Google 로그인 및 호스팅 과정에서 제공업체의 쿠키·접속 기록이 처리될 수 있으므로 실제 사용 항목과 거부 방법을 확인해 기재한다. 최종 방침에는 시행일과 개정 내역을 표시하고, 중요한 변경을 알리는 방법을 정한다.
