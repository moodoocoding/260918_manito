# 전문가 검토 기록: 교사·학생 로그인 입구 통일

## 검토 정보

- 날짜/대상: 2026-10-30, 교사 로그인 시각 보완 v1.
- 수행 주체·방식: Codex 단일 에이전트가 여섯 가상 프로파일로 역할별 검토. 외부 전문가 참여 없음.
- 요청·범위: 사용자는 첨부 화면의 교사 로그인이 학생 로그인과 너무 다르다고 지적했다. 교사 로그인 표시만 승인된 학생 입구 배경/프레임/카드/버튼 체계로 통일한다. 공통 학급 인증 계층이며 마니또 회차와 무관하다.
- 자료: 사용자 첨부 교사 로그인 화면, 최신 AGENTS, class-platform-architecture, world-design-system 및 world-interior-approved.png, StudentLogin.tsx/student-login.css와 승인 student-login-world.webp, main.tsx, 전문가 운영 지침/여섯 프로파일/양식.
- 유지 범위: 기존 Google 팝업/리다이렉트 callback, busy/오류 상태, 교사 확인/정지, 기존 DB·UID·classId·카드·권한·서버 계약. 학생 로그인 컴포넌트와 인증 로직은 수정하지 않는다.

## 사용자와 설계안

- 과업: 교사는 상위 플랫폼 입구에서 Google 계정으로 로그인해 학급 공통 관리와 독립 서비스로 이동한다.
- 현재 문제: 교사 미인증 분기만 기존 entry-layout/흰 둥근 카드/붉은 버튼을 사용한다. 학생 입구의 픽셀 풍경과 직각 종이 카드와 연속성이 없다. 기능 소개가 길어 핵심 로그인 행동도 아래로 밀린다.
- 구성: 기존 공통 역할 선택 헤더 → 승인된 학생 로그인 배경/브랜드 환영 카드 → 교사 로그인 종이 카드(역할/짧은 과업 안내/Google 주 행동/리다이렉트 보조 행동/기존 계정 안내).
- 공통 원본: student-login.css의 기존 pixel-login 장면·카드·입력·버튼을 공유한다. 학생 범위에 교사 입구 선택자만 추가해 기존 학생의 선택자 우선순위를 보존한다. 교사 CSS는 설명과 보조 버튼의 배치만 정의한다.
- 디자인 예외: 로그인은 world-design-system 문서가 보존하도록 한 별도 승인 장면이다. 기능 내부용 WorldPageFrame으로 바꾸지 않고 기존 로그인 자산·pixel-login-submit의 승인 색/프레임을 실제 HTML에 적용한다. 학생 입구의 색·그림자·버튼 값을 교사 CSS에 복사하지 않는다.
- 상태: 기본/Google 확인 중/disabled/전역 오류·재시도와 기존 학생/교사 전환을 유지한다. 디자인 검증에서 실제 계정 로그인이나 권한 변경을 실행하지 않는다.
- 반응형: 학생 입구와 같은 768px 한 열, 420/340px 축소 배치. 긴 리다이렉트 버튼은 여러 줄, 본문16px·조작48px 이상. 키보드 주 버튼→보조 버튼, 보이는 초점·aria-busy·폼 submit을 제공한다.

## 구현 후 검증

- 실제 브라우저 검증은 현재 Work 설정의 Local browser use disabled 응답으로 실행하지 못했다. Browser 스킬의 문서대로 연결을 시도했고 다른 브라우저 도구로 우회하지 않았다.
- 구현: TeacherLogin은 `busy`, `onLogin`, `onLoginRedirect` 세 prop만 받고 기존 main의 task(teacherLogin)/task(teacherLoginRedirect)에 연결한다. 별도 Firebase import·저장소·인증 상태는 없다. 학생 컴포넌트를 수정하지 않고 기존 CSS 선택자를 `:is(.student-entry-app, .teacher-entry-app)`로 확장했다. 기존 학생 선택자와 같은 specificity를 유지하며 시각 값은 복사하지 않았다.
- 컴포넌트 비교 fixture: `web/preview/teacher-login-qa.html`. 실제 TeacherLogin/StudentLogin을 번갈아 표시하고 busy·가상 오류·callback을 확인할 수 있다. Firebase를 import하지 않고 외부 쓰기를 하지 않는다. production 기본 index 빌드의 진입점에 넣지 않았다.
- 검증 증거: 웹 TypeScript/Vite 빌드 성공(기존 큰 JS 청크 경고), fixture 별도 TypeScript 검사 통과, 개발 서버의 fixture HTTP200 확인. 이는 화면 렌더·반응형·키보드 검증의 증거로 계산하지 않는다.

## 부모 채팅의 후속 실제 화면 검증

- 수행: `/root` 한 에이전트의 가상6역할 재검토다. 담당 채팅의 Work 브라우저 제한과 별개로 부모에 허용된 Cua/IAB 연결을 정상 사용했다. 초기의 비활성 옛 브라우저 참조는 현재 인벤토리 확인 뒤 같은 IAB에서 열어 해결했으며 다른 계정/브라우저 정책을 변경하지 않았다.
- 실제 TeacherLogin/StudentLogin을 사용하는 Firebase없는 비교fixture에서 확인했다. 부모는 fixture에 `?text=200` root글자 확대helper만 추가했다. 실제인증·운영코드·교사권한은 변경하지 않았다. 이후5174담당이기존cloud고정빌드에동일fixture를포함해localhost주소로복구했다.
