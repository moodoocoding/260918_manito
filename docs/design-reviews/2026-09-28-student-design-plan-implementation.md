# 학생 디자인 계획 v2.0 적용 검토

## 검토 정보와 설계

- 날짜: 2026-09-28. 수행: Codex 한 에이전트가 여섯 **가상 역할**로 독립 판단. 외부 전문가·실제 아동 참여 없음.
- 자료: `docs/design-revision-plan.md` v2.0, 여섯 프로파일과 운영 지침, `web/src/main.tsx`, `StudentRound.tsx`, `StudentMail.tsx`, `style.css`, `functions/src/students/getStudentHome.ts`.
- 대상: 학생 홈·미션·우편함·지난 활동. 교사 메뉴와 서버 집계 계약은 변경하지 않는다.
- 현재 문제: 홈의 시즌·요약·주 행동이 카드 셋으로 갈라져 아래로 밀린다. 미션 필터 결과 0건에서 복구 버튼이 없고 더 보기의 초점이 새 항목으로 가지 않는다. 지난 활동 목록에는 제목만 있다. 쪽지는 두 관계별 대화가 구현되어 있으나 작성 영역이 대화 아래에 묻힌다.
- 과업 구조: 홈에서 시즌 상태와 내 다음 미션을 한 카드에서 읽고 완료·미션 이동, 미션에서 필터→8개 탐색→상세→목록 복귀, 우편함에서 관계 선택→해당 대화·작성, 지난 활동에서 제목·시작 날짜·상태→읽기 전용 상세. 홈·미션·우편함·우리 반은 별도 화면이다.
- 상태: 로딩/빈/실패, 진행/중지/공개, 제출 중/저장 후 재조회 실패, 미션 0/80개와 쪽지 0/다수, 초점 복귀를 본다. 미션/쪽지 서버 동작과 개인 비밀 경계는 유지한다.
- 배치: 학생 콘텐츠 최대 760px, 320/360/390px 한 열, 768/1280px 읽기 한 열; 긴 문장은 자연 줄바꿈. 주 행동 48px, 보조 행동 44px, 200% 확대에서 클리핑 금지.

## 문제와 조치

| ID·심각도 | 문제 → 근거 → 영향 | 수정안 → 확인 방법 |
|---|---|---|
| SDI-01 P1 | 주 행동이 세 카드 뒤에 있음 → H6/H8 → 학생이 첫 행동을 찾기 어려움 | 시즌·내 요약·다음 미션을 한 카드로 통합, 완료·미션 이동을 이어 배치 → 390×844 첫 화면과 200% 확인 |
| SDI-02 P2 | 필터 0건에서 선택만 다시 해야 함 → H9 → 복구 부담 | 전체 보기 버튼 → 0건 가상 상태에서 실행 |
| SDI-03 P2 | 더 보기 후 초점이 버튼에 남음 → H3 → 추가 항목 발견 어려움 | 새 항목 첫 버튼으로 초점 → 키보드 확인 |
| SDI-04 P2 | 지난 시즌 제목만 있음 → H6 → 같은 제목 시즌 식별 어려움 | 서버가 이미 주는 시작일·상태 표시 → 두 시즌 목록 확인 |
| SDI-05 P2 | 작성 영역이 대화 끝에 묻힘 → H7 → 긴 대화에서 반복 스크롤 | 대화 상단에 작성 이동 버튼, 분리된 작성 영역 제목 → 다수 쪽지 확인 |

- 의견 차이: 계획서의 받은/보낸 전체 탭은 사용자가 이후 명시한 ‘내가 맡은 친구/나를 맡은 친구’ 두 대화 구조와 충돌한다. 관계별 대화를 유지하고 각 메시지의 보냄/받음 표식을 사용한다. 숫자 학급 집계는 공개 계약·추론 안전 검증이 없어 구현하지 않는다.
- 착수 판정: 여섯 관점 통과. P1은 통합 카드 설계로 해결했고 미해결 P0/P1 없음. P2는 모두 이번 구현에서 처리하며 위 확인 방법으로 재판정한다.

## 구현 후 재검토

구현: 홈의 세 카드를 첫 과업 카드로 통합하고 요약은 한 줄로 줄였다. 네 메뉴는 실제 경로 링크와 `aria-current`를 쓰고 이동 뒤 페이지 제목으로 초점을 보낸다. 미션 0건 복구와 추가 8개 첫 항목 초점, 우편함 작성 위치 이동, 지난 활동의 한국 날짜·상태, 저장 후 재조회 실패 문구를 적용했다. Firebase API·권한·학생 비밀 필드는 바꾸지 않았다.

| 환경·폭·입력 방식 | 상태·기대 | 실제 결과와 한계 |
|---|---|---|
| 로컬 Vite 가상 콘텐츠, 320/360/390/768/1280px | 긴 시즌·미션·쪽지에서 가로 넘침과 버튼 잘림이 없어야 함 | 다섯 폭 모두 문서 가로 넘침 0. 390×844px에서 홈 주요 버튼 하단 796px. 320px은 하단 843px로 첫 화면 경계에 걸친다. 가상 화면은 임시 파일을 삭제했다. |
| 로컬 가상 콘텐츠, 320px·기본 글자 크기 200% | 긴 제목·메뉴·글이 가로로 잘리지 않아야 함 | 문서 넘침 0, 검사한 제목·본문·버튼 중 `scrollWidth > clientWidth` 없음. 이는 글자 크기 모사이며 실제 브라우저 확대 조작과 별개다. |
| 실제 로컬 Vite 첫 화면 | 앱이 정상 로드되고 오류가 없어야 함 | 학생 입장 폼과 입력·버튼이 보이며 브라우저 error 로그 0. 인증된 학생 내부 화면은 이 세션에서 열지 못했다. |
| 자동 회귀 | 빌드, 함수·Rules·가상 두 시즌 흐름 | 전체 빌드, 함수 12건, QR 1건, Rules 13건, 통합 3건 통과. 프런트 상호작용 자체의 자동 테스트는 아님. |

| 프로파일 | 구현 후 개별 판단 | 판정 |
|---|---|---|
| WD-01 | 첫 카드에 기간→내 요약→다음 미션→행동 순서를 두고 여러 강조 카드를 줄였다. 390px 화면에서 주 행동을 육안으로 확인했다. | 로컬 통과 |
| WD-02 | 다섯 폭과 200% 글자 모사에서 긴 텍스트의 재배치·넘침을 확인했다. 320px 첫 화면 버튼은 하단 경계라 높이가 작은 기기는 스크롤이 필요하다. | 확인 범위 내 통과 |
| UX-01 | 홈·미션·우편함·우리 반 메뉴를 링크로 유지하고 관계별 두 대화와 지난 시즌 목록을 분리했다. | 코드·로컬 통과 |
| UX-02 | 미션 0건 복구, 지난 시즌 식별, 작성 바로가기, 저장 후 재조회 실패 안내를 구현했다. 실제 학생의 이해는 관찰하지 못했다. | 코드·로컬 통과 |
| UI-01 | 추가 항목·목록 복귀·작성 위치·페이지 제목 초점이 코드 경로에 있다. 실제 인증 화면 키보드 조작은 미확인이다. | 코드 통과, 실사용 미확인 |
| UI-02 | `aria-current`, 단일 페이지 H1, 프로그램 초점 테두리, 가상 확대·넘침을 확인했다. VoiceOver와 실제 200% 브라우저 확대는 미확인이다. | 확인 범위 내 통과 |

- 완료 판정: 이번 변경 범위의 SDI-01~05 설계·구현과 로컬 화면 결함은 처리했다. 실제 인증 학생 종단 간 이동/초점·80개 미션 탐색, VoiceOver, 실제 아동 과업 관찰은 미확인이다. 수치형 학급 집계는 공개 계약과 안전 검증 전까지 제공하지 않는다.
