# R4 모바일 탐색·명부 접근 수정 · 구현 전 6개 관점 검토

## 검토 정보와 사용자 과업

- 날짜: 2026-09-27. 대상: `main`의 R1~R3 디자인 수정 구현.
- 수행: Codex 한 에이전트가 저장소의 6개 가상 전문가 프로파일을 각각 적용했다. 외부 전문가의 참여나 실제 교사·학생 관찰은 없었다.
- 입력: `docs/design-revision-plan.md`, 기존 R0·구현 검토, 로컬 `demo-manitto`의 가상 교사 40명 학급을 390px에서 조작한 화면, `web/src/main.tsx`와 `web/src/style.css`.
- 사용자 과업: 교사는 모바일에서 다른 관리 페이지로 이동하고, 기존 학생의 카드를 검색·관리하며, 필요할 때 학생을 추가한다.

## 현재 문제와 설계

1. 관찰: 390px에서 `학급 메뉴`를 열고 다른 페이지를 선택해도 펼친 메뉴가 유지된다. 본문 첫 화면 약 200px을 가려 선택한 페이지의 일을 찾기 어렵다.
2. 관찰: 학생 40명의 `학생·입장 카드` 페이지에서는 새 학생 등록 폼이 검색·명부보다 앞에 펼쳐져, 일상적인 카드 관리가 화면 아래로 밀린다.
3. 추가 관찰: 카드 관리의 검색·상태 필터는 중첩된 교사 레이아웃에서 폼 스타일이 적용되지 않아 작은 기본 입력으로 나타났다. axe-core 검사에서 40개 `입장 가능` 상태 글자가 흰 바탕 대비 4.24:1로 기준에 못 미쳤다.
4. 추가 관찰: `/student/history` 주소에서 가상 학생으로 인증 상태가 전환될 때 URL은 지난 활동인데 본문은 오늘 화면이었다. 인증 시 화면 상태 초기화와 주소 복원이 어긋났다.
5. 추가 관찰: 빈 학급에서 학생 40명을 등록하면 성공 안내가 뜨지만 앱이 `운영 요약`으로 이동한다. 막 발급한 카드 원문은 등록 세션에서만 볼 수 있으므로 인쇄까지 이어지는 과업이 끊긴다.
6. 추가 관찰: 가상 카드 40장을 PDF로 인쇄하면 40쪽으로 나뉘지만 기본 도구는 Letter 크기였다. CSS A4를 적용한 인쇄 엔진에서는 A4 40쪽이 됐으나 첫·마지막 쪽의 빈 영역에 화면용 크림 배경이 남았다.
4. 변경: 교사 페이지가 **실제로 바뀐 뒤** 모바일 메뉴를 닫는다. 미저장 이탈 확인에서 취소하면 기존 페이지와 열린 메뉴를 유지한다. 학급 메뉴 6개 구성과 데스크톱 사이드 메뉴는 유지한다.
5. 변경: 학생이 없는 학급은 등록 폼을 바로 보여준다. 기존 학생이 있는 학급은 `새 학생 등록` 펼침 영역에 폼을 넣고 기본 닫힘으로 둔다. 학급 코드 다음에 이 조작을 두고, 검색·상태 필터·명부 제목을 바로 볼 수 있게 한다. 펼친 상태에서 입력·오류·등록 버튼은 현재 동작을 따른다.
6. 변경: 카드 검색·상태 필터를 44px 이상 높이의 한 열 또는 두 열 입력으로 맞추고 상태 보조 글자를 충분히 어둡게 한다. 학생 인증 뒤에는 허용된 `/student` 하위 주소에서 현재 페이지를 복원하고, 다른 주소였다면 `/student`와 오늘을 함께 설정한다. 학생 등록 성공 뒤에는 카드 관리 페이지에 그대로 머물러 인쇄할 수 있게 한다. 인쇄 CSS에는 A4 크기·여백과 흰 용지 바탕을 명시한다. 반응형·상태는 320·390·768px과 긴 학생 이름·40명을 확인한다. 메뉴와 펼침은 키보드로 조작하고 미저장 이탈 취소·승인도 회귀 검증한다.

## 개별 사전 판단

| 프로파일 | 판단과 근거 | 판정 |
|---|---|---|
| WD-01 · 시각 구성 | 펼친 메뉴와 등록 폼이 본문 위계를 압도했다. 이동 뒤 메뉴 닫기와 선택적 폼으로 현재 페이지 제목·과업을 위로 올린다. 등록 직후 카드 인쇄가 같은 화면에 보이고 인쇄 용지의 빈 영역은 흰색으로 둔다. | 통과 |
| WD-02 · 반응형 레이아웃 | 390px 실측에서 메뉴는 2열, 등록 폼은 한 열이다. 닫힌 영역은 높이를 줄이고 검색 입력도 320px에서 가용 폭을 사용한다. 인쇄는 A4 한 장당 카드 한 장을 목표로 한다. | 통과 |
| UX-01 · 정보 구조 | 기존 학급의 주 과업은 카드 검색·관리이고 등록은 필요할 때 수행한다. 학생이 0명이면 등록이 주 과업이며, 등록→카드 확인·인쇄를 한 흐름으로 둔다. 학생 URL과 실제 페이지를 맞춘다. | 통과 |
| UX-02 · 인지 부담 | 메뉴 이동 후 현재 페이지가 즉시 보이고, 새 학생 추가 조작은 명시적 문구로 남는다. `새 학생 등록`은 닫힌 폼의 목적을 설명한다. 등록 성공 직후 카드 인쇄가 가능해 다음 행동이 분명하다. | 통과 |
| UI-01 · 조작·상태 | 메뉴를 클릭 시점에 닫으면 미저장 이탈 취소와 상태가 어긋날 수 있다. 페이지 상태가 변경된 뒤 닫고, 등록 입력·오류 시 폼은 유지한다. 인증 뒤 주소 기반 학생 상태를 맞춘다. 등록 성공 시 `students` 경로를 유지하며 카드 원문은 기존 1회 노출 규칙을 따른다. | 통과 |
| UI-02 · 접근성·품질 | native `details/summary`로 키보드와 상태 의미를 보존한다. 검색·필터의 터치 크기와 상태 글자 대비를 바로잡고 axe 및 실제 키보드·폭별 조작으로 재검증한다. 인쇄 페이지 크기·쪽수도 PDF로 확인한다. | 통과 |
