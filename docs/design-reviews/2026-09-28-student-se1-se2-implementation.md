# 전문가 검토 기록: 학생 화면 기반과 개인 미션 탐색

## 검토 정보

- 날짜/대상: 2026-09-28, 개발 계획 v2.3 §6.6~6.8 및 디자인 계획 v2.0 SE-1·SE-2.
- 범위: 학생 홈·미션·우편함 탐색, 개인 미션 요약·범주/상태 필터·8개씩 보기·상세/복귀, 기존 기능의 반응형 정리. 학급 집계 숫자·교사 안내 게시·정기 발행은 별도 SE-3 검토 대상으로 남긴다.
- 수행: Codex 한 에이전트가 여섯 가상 전문가 역할로 문서·코드를 검토했다. 실제 사람 여섯 명의 승인이나 학생 관찰이 아니다.
- 자료: `docs/experts/README.md`와 여섯 프로파일, 기존 [기획 검토](2026-09-28-student-experience-plan.md), `web/src/main.tsx`, `web/src/StudentRound.tsx`, `web/src/style.css`, `functions/src/rounds/activity.ts`, `functions/src/rounds/missions.ts`.

## 사용자와 설계안

- 이용자: 초등학생 1~6학년, 교실 공용기기와 모바일. 과업은 시즌 상태 이해 → 원하는 미션 찾기 → 상세 확인 → 해냈어요/쉬기, 또는 쪽지·도움이다.
- 현재 문제: 홈에 시즌 패널과 모든 미션 조작이 붙어 있고, 전체 목록은 최대 80개를 한꺼번에 펼친다. `다른 미션`이 탐색인지 실제 교체인지 불명확하다. 학생 헤더와 본문의 너비·여백 규칙이 다르다.
- 구조: 공통 상단 `선생님 도움`·`활동 마치기`; 기본 메뉴 `홈/미션/우편함/우리 반`; 홈에 지난 활동 링크. 이번 범위에서는 우리 반에 검토된 배려 예시만 보여 주고 숫자·학생별 정보는 보내지 않는다.
- 홈: 짧은 인사→시즌 제목·상태·기간→내 미션 상태 수→할 수 있는 미션 하나→미션·우편함·지난 활동 이동. 미션 변경 폼과 우편함 작성 폼은 홈에 두지 않는다.
- 미션: 본인 상태 요약→상태와 범주 필터→8개 목록→상세. 목록 열기와 필터는 서버 변경 없음. 상세에서 완료·쉬기와 실제 교체를 분리하고 교체에는 확인을 둔다. `replaced` 원본은 현재 목록/요약에서 빼며 구 데이터에서 범주 불명은 `기타 미션`이다.
- 우편함: 기존 발송/받음 기능을 유지하되 받은 목록·보낸 목록·새 쪽지 단계를 분리한다. 실패 시 입력 내용을 지우지 않는다.
- 상태: 로딩/빈/오류/저장 중/저장 후 재조회 실패를 해당 과업 안에 표시. 권한 상실과 학생 전환에는 메모리 상태 폐기. 공개 이름은 기존 승인 후 가림 규칙을 유지한다.
- 반응형: 학생 상단·본문 최대 760px, 모바일 16px 바깥 여백(320px에서 12px), 한 열; 큰 글자에서는 메뉴 2열. 100자 미션과 200자 쪽지, 80개 목록, 키보드 초점, 200% 확대를 검증한다.

## 문제와 조치

| 심각도 | 문제 → 근거 → 영향 → 수정안 → 확인 | 처리 |

- 기존 기획 검토의 WD-01/02/UI-02 근거 부족은 이번 **SE-1·SE-2 범위**에서 구체 배치·실제 문구·입력 상태와 비공개 대안을 정해 해소했다. SE-3 숫자 공개는 착수 판정에 포함하지 않는다.
- 의견 차이: 홈에 모든 버튼을 두면 이동은 줄지만 핵심 다음 행동이 묻힌다. 홈에는 미션 한 개와 화면 이동만 둔다.
- 착수 판정: 여섯 관점 모두 위 범위 통과, 이번 범위의 미해결 P0/P1 없음. 구현 후 실제 화면과 저장 복귀를 다시 판정한다.

## 구현 후 검증

- 수행: 같은 Codex 에이전트가 여섯 가상 역할로 배포 웹의 가상 학생 화면과 코드·테스트 결과를 다시 확인했다. 실제 전문가나 아동의 평가가 아니다.
- WD-01: 배포 학생 홈에서 시즌 카드→본인 미션 기록→이번에 해볼 미션 순서를 시각적으로 확인했다. `우리 반`은 배려 예시 두 개와 게시된 안내 하나로 구성되며 빈 안내 카드는 나타나지 않는다. **확인한 폭은 인앱 브라우저의 약 635px 한 가지**다.
- WD-02: 그 폭에서 헤더·메뉴·카드의 좌우 정렬, 긴 미션 문장의 자연 줄바꿈, 가로 넘침 없음(`scrollWidth=innerWidth=635`)을 확인했다. 브라우저의 명시적 390/768/1280px 뷰포트 설정이 반영되지 않아 해당 폭과 200% 확대는 미확인이다.
- UX-01: 배포 학생 계정으로 홈→미션 목록→상세→목록 복귀, 홈→우리 반, 우편함을 확인했다. 목록은 10개 중 8개를 먼저 보여 주고, 남은 2개 버튼 문구를 바로잡았다. 80개 실화면 탐색은 미확인이다.
- UX-02: 홈의 수치는 본인 기록만 표시하고, 미션 상세의 선택 저장 뒤 `이번에 해볼 미션으로 골랐어요` 피드백을 확인했다. 상대 이름·목록·보기 버튼이 나타나지 않았다. 구 기록의 상태가 불명확하면 추정 수치를 표시하지 않도록 후속 수정했다.
- UI-01: 배포 미션 선택 버튼의 저장 중 비활성·저장 후 선택됨 상태, 우편함의 받은/보낸/작성 분리, 교사 안내 초안·미리보기·게시→학생 화면 표시를 확인했다. 오류·연결 끊김의 수동 화면 재현은 미확인이다.
- UI-02: 실제 브라우저에서 학생/교사 메뉴와 미션 조작을 Enter로 사용했고, 두 화면 콘솔 오류는 0건이었다. 함수 단위 10건·Rules 13건·두 시즌 통합 3건으로 소속/직접 읽기/게시 경계를 검증했다. VoiceOver와 실제 200% 확대는 미확인이다.
- 후속 P2: 390/768/1280px, 80개 목록, 200% 확대와 VoiceOver를 별도 브라우저·실기기에서 확인한다. 담당 WD-02/UX-01/UI-02. 확인 방법은 각 폭의 가로 넘침·줄바꿈·초점 순서와 80개 목록 필터/더 보기/복귀 실측이다.
- 판정: 확인한 가상 학급·브라우저 범위에는 미해결 P0/P1 없음. 위 미확인 사항을 전체 화면·접근성 검증 완료로 간주하지 않는다.
