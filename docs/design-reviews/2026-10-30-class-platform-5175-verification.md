# 5175 통합 학급 구조·자리바꾸기 실제 화면 검증

## 범위와 자료

2026-10-30 사용자가 실제 화면의 ‘진행 중인 회차에서만’ 오류를 제시하고 자리바꾸기가 마니또와 무관한 기능임을 다시 명시했다. 상위는 통합 학급 공간, 마니또는 하위 서비스다. 기존 Firebase 학급/학생/코드/카드/마니또 기록을 계승하며 다른 기능에 회차를 요구하지 않는다.

이 채팅은 부모의 메인/브랜드 수정과 게시판 담당의 학급 독립 서버 수정본을5175 고정 cloud 빌드에 반영하고 실제 읽기 경로만 확인한다. 서비스 코드를 중복 수정하지 않았다. 자료는 최신 AGENTS, class-platform-architecture.md, 부모의 계층/메인 검토와 balance-game-missing-questions.md, StudentClassroom/main/StudentCommunity/StudentBalanceGame 및 학급 balance 함수/계약이다. 수행은 Codex 한 에이전트의 가상6역할이며 외부 전문가·학생 사용성 검증이 아니다.

## 반영 결과

- cloud TypeScript/Vite 빌드 성공. 기존 JS 청크 크기·외부 outDir 미비움 안내만 발생했다. 번들에 기존 manito-938cc/통합 APP_NAME/학급 game 계약이 있고 demo-manitto는 없음을 확인했다.
- 최종 고정 빌드: `/private/tmp/manitto-cloud-preview-frldp45z`, 로컬5175 preview(session49530). 기존 envcloud/envlocal/DB·카드·마니또·Schooldoc 미션 상태를 변경하지 않았다. 서비스/권한 배포는 게시판 담당, 메인/브랜드 수정은 부모의 결과와 구분한다.
- 갱신 전 실제 탭은 `/student`, 선택0·질문 단계 없음·리뷰 없음·textarea 초안 없음으로 안전하게 한 번 reload했다. 현재 로그인 화면에서 새 상위 브랜드 표시를 확인했다. 로그인 화면의 구 시즌 문구 부재만으로 마을 검증을 완료했다고 주장하지 않는다.
- 실제 학생 세션은 로그아웃 상태여서 사용자에게 기존 카드 재입장을 요청했다. 실제 게시판 첫 질문/10문항 표시 확인은 대기 중이다. 학생 이름이나 카드 코드를 받아 파일에 저장하거나 재로그인 우회하지 않는다.

1. 기존 카드로 로그인 성공. 실제 마을 제목 표시, 로그인 폼 미표시, 구 ‘마니또 시즌2’ 문구 미표시를 신원 없이 확인했다.
