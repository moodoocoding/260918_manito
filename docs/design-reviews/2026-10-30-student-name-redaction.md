# 전문가 검토 기록: 공개 전 학생 관계 이름 비공개 복구

## 검토 정보

- 날짜: 2026-10-30. 수행: `/root/teacher_mail_backend`가 여섯 가상 프로파일을 개별 적용한다. 부모 `/root`가 통합 검증을 담당한다. 외부 인간 전문가 참여/승인은 없다.
- 발견: 새 교사 우체통 통합 검증 중 기존 `rounds.integration`의 새 시즌 `studentData.targetDisplayName` 부재 검사가 실패했다. 읽기 조사 결과 `startRound`가 이름을 저장하고 `getStudentActivity`가 진행/일시정지/공개대기에서 이름을 복원·그대로 반환하므로 오래된 시험이 아니라 실제 P0 비공개 정책 위반이다. 우체통 구현에서 이 두 코드를 변경한 이력은 없다.
- 근거: AGENTS의 공개 전 양쪽 관계 이름 차단, `docs/functions-api.md`의 `getStudentActivity` 공개 전 두 이름 `null`, `firestore.rules`의 학생 데이터 부모 직접 읽기 거부.
- 자료: 전문가 운영 지침/여섯 프로파일, `flow.ts`, `activity.ts`, `getStudentHome.ts`, `reveal.ts`, `teacherStudentStatus.ts`, Rules와 기존 두 시즌 통합 시험.
- 범위: `startRound`의 공개 전 이름 저장 제거, `getStudentActivity`의 자동 복원/저장 제거와 공개 상태에 따른 양쪽 이름 반환, 기존 검증 강화. `getStudentHome`와 Rules는 이미 계약에 맞아 수정하지 않는다. 원본 배정·담당 교사 감사 열람·공개 후 본인 관계·화면 배치는 유지한다.

## 요구사항·사용자 과업·상태·화면 계획

- 학생은 진행/일시정지/공개대기 중 미션·쪽지·도움을 사용하며 배정된 친구의 이름은 받지 않는다. 담당 교사의 공개 승인 뒤에만 본인 관계 이름을 받는다.
- `getStudentHome`: 회차 요약에 관계 이름 키가 없다. 유지한다.
- `getStudentActivity`: `active|paused|reveal_pending`에서는 `targetDisplayName:null`, `incomingDisplayName:null`. 레거시 이름이 원래 문서에 있어도 가린다. `revealed|archived`에서만 공개 함수가 저장한 본인 두 이름을 반환한다. 수신 UID나 전체 관계표는 반환하지 않는다.
- 새 회차의 `studentData`에는 생성시각만 기록한다. 배정은 `assignmentSecrets`에 유지한다. 읽기 함수는 이름을 복원하거나 문서를 수정하지 않는다.
- 공개 함수의 활성 관계만 저장하는 기존 절차를 유지한다. 본인 회차/참여/카드 버전 검증과 타인 직접 읽기 거절도 유지한다.
- 페이지/섹션/반응형/최대 항목: 새 UI가 없는 응답 경계 수정이다. 기존 미션·우편함·도움 레이아웃과 48px 조작은 바꾸지 않는다. 공개 전 이름 문자열이 화면과 네트워크에 나타나지 않아야 한다.
- 새 저장·로딩·오류·취소 상태 없음. 기존 응답의 `null` 계약으로 복구하므로 프런트엔드가 새 상태를 해석할 필요가 없다.
