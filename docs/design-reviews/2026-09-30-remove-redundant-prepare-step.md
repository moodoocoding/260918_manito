# 전문가 검토 기록: 시즌 시작 전 불필요한 '조건 확인' 단계 제거 및 원클릭 '매칭하고 시작' 통합

## 검토 정보

- **날짜 / 대상 설계 버전 또는 커밋**: 2026-09-30 / v3.3 (시즌 시작 원클릭 워크플로우 혁신)
- **요청과 변경 범위**:
  - 사용자 질문 및 요구: "'조건 확인' 버튼이 필요한 이유는? 개선해."
  - 기존 문제: 시즌 초안 저장(`draft`) 후 선생님이 곧바로 시작하지 못하고 `[조건 확인]` 버튼을 눌러 `ready` 상태로 바꾼 뒤에야 비로소 `[매칭하고 시작]` 버튼을 누를 수 있었던 2단계 중복 조작 문제.
  - 개선 범위: `[조건 확인]` 버튼을 화면에서 제거하고, `draft` 및 `ready` 상태에서 바로 `[매칭하고 시작]` 버튼을 노출. 클릭 시 내부에서 조건 검증(`prepareRound`)과 매칭 시작(`startRound`)을 원클릭 트랜잭션으로 자동 연계 처리.
- **수행 주체·방식**: 6인 전문가 프로파일(`WD-01`, `WD-02`, `UX-01`, `UX-02`, `UI-01`, `UI-02`) 역할 기반 설계 검토.
- **입력 자료**: `web/src/TeacherRounds.tsx`, `functions/src/rounds/flow.ts`.
- **검토 단계**: 사전 설계 검토.

## 사용자와 설계안

- **대상 사용자**: 초등학교 교사 (시즌 설정을 저장하고 바로 학급 마니또를 시작하려는 교사).
- **핵심 과업**:
  - 준비 내용 저장 후 지체 없이 학생들의 비밀친구 매칭을 시작.
- **개편 설계안**:
  1. `TeacherRounds.tsx`의 액션 바에서 `current.status === "draft"` 전용 `[조건 확인]` 버튼 제거.
  2. `["draft", "ready"].includes(current.status)`일 때 **`[매칭하고 시작]` 단일 Primary 버튼** 노출.
  3. 교사가 `[매칭하고 시작]` ➔ 확인 팝업 승인 시:
     - `current.status === "draft"`라면 클라이언트가 백엔드 `prepareRound`를 먼저 호출하여 수학적 매칭 가능 여부와 입장 차단 학생 여부를 검증하고 최신 `rosterVersion`을 확보.
     - 검증 성공 즉시 `startRound`를 연속 호출하여 단 한 번의 액션으로 시즌을 `진행 중(active)`으로 전이.
     - 조건 불만족 시(예: 제외 조건 과다로 1:1 불가능) 친절한 에러 메시지를 띄우고 초안 상태 유지.

## 발견 사항과 조치

1. **P1: draft 상태에서 연속 호출 시 rosterVersion 불일치 가능성 방지**:
   - `prepareRound`의 반환값에서 최신 `rosterVersion`을 받아 `startRound`에 전달하여 버전 불일치 에러(`failed-precondition`) 방지.
2. **P2: 조건 불충족 시 에러 피드백 명확화**:
   - 제외 조건이 너무 많아 매칭이 불가능한 경우 "이 제외 조건으로는 모두를 배정할 수 없어요." 메시지가 화면 상단 에러 영역에 확실히 렌더링되도록 보장.

**착수 판정**: 6개 관점 모두 통과, 미해결 P0/P1 없음. 구현 착수 승인.
