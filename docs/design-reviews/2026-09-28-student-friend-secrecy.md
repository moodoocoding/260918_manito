# 전문가 검토 기록: 진행 중 시즌의 친구 이름 비공개

## 검토 정보

- 날짜 / 대상: 2026-09-28, `1634962` 기준 학생 화면·학생 API·Firestore Rules
- 요청: 사용자는 진행 중 시즌 내내 학생에게 상대 이름을 보이지 않도록 명시했다. 교사의 공개 승인 뒤 결과 확인은 기존 과업으로 유지한다.
- 수행 주체·방식: Codex 한 에이전트가 저장소의 6개 가상 전문가 프로파일을 각각 적용했다. 외부 전문가나 실제 학생의 참여는 없다.
- 입력 자료: 사용자 제공 `/student/mail` 화면, `web/src/main.tsx`, `web/src/StudentRound.tsx`, `functions/src/students/getStudentHome.ts`, `functions/src/rounds/activity.ts`, `functions/src/rounds/flow.ts`, `functions/src/rounds/reveal.ts`, `firestore.rules`, 제품 계획·함수·데이터 계약.

## 사용자와 사전 설계

- 대상: 입장 카드로 로그인한 학생. 과업은 오늘의 미션 수행, 배정된 친구에게 익명 쪽지 전송, 받은 쪽지 답장, 필요할 때 교사에게 도움 요청.
- 현재 문제: 진행 중 시즌의 `targetDisplayName`을 홈/활동 API가 보내며 `studentData/{uid}` 직접 읽기로도 얻을 수 있다. 학생 화면은 이름을 가려도 `친구 보기` 버튼이 있고 오늘 카드가 핵심 과업보다 앞에 놓인다. 첨부 화면은 우편함 URL에서 친구 카드가 보이는 상황이다. 이름 노출은 학생 본인 또는 주변 학생에게 관계를 공개할 수 있다.
- 페이지 구성: 오늘은 시즌 상태와 미션, 우편함은 쪽지, 선생님 도움은 도움 요청, 지난 활동은 공개 승인된 과거 기록. 진행·일시정지·공개 대기에는 상대 이름이나 보기 버튼을 어느 페이지에도 두지 않는다. 공개 완료/보관 후에만 오늘·지난 활동의 공개 결과에서 본인 관계를 확인한다. 우편함과 도움에는 관계 공개 영역이 없다.
- 상태: 로딩·오류·빈 상태에는 이름을 포함하지 않는다. 쪽지 대상은 서버 배정으로 결정한다. 교사 공개 승인 전에는 학생 API 응답에서 관계 이름을 `null`로 반환하며 학생의 부모 `studentData` 문서 직접 읽기는 모든 상태에서 차단한다. 자식 미션·쪽지·도움 문서는 기존 본인 읽기 규칙을 유지한다. 신규 시즌 시작 시 이름은 학생 문서에 쓰지 않고 공개 승인 시 활성 관계만 기록한다. 기존 진행 시즌의 이름 필드는 남더라도 Rules와 API에서 차단한다.
- 반응형/접근성: 이름 카드 제거로 좁은 화면의 첫 과업 도달 거리가 짧아진다. 공개 결과는 기존 카드형 구조와 버튼 초점·가리기 동작을 유지한다. 320·360·390·768·1280px, 긴 시즌 제목, 키보드 Tab/Enter를 확인한다.

- 의견 차이: 기존 계획서는 학생이 챙길 상대를 시즌 중 확인하도록 했으나, 이번 사용자 지시가 우선한다. 쪽지 자동 라우팅과 일반 미션은 유지한다. 현장 미션의 해석은 실제 학생·교사 테스트에서 확인한다.
- 착수 판정: 6개 관점이 위 설계에 통과했고 설계상 미해결 P0/P1은 없다. 구현 중 발견한 S-03 전환 상태를 반영해 관련 UX/UI 관점을 재검토했다. 구현 후 실제 결과가 다르면 통과 판정을 철회한다.
