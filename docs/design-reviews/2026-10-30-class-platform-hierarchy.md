# 전문가 검토 기록: 통합 학급 플랫폼과 마니또 서비스의 경계

## 검토 정보·요구·현재 문제

- 2026-10-30 사용자가 ‘마니또 시즌2’ 전역 표시와 반복되는 마니또 종속을 지적했다. 기존 마니또 DB는 계승하되 상위 제품은 더 큰 학급 시스템이라는 직접 요구다.
- 수행: `/root` 한 에이전트가 전문가 운영 지침·여섯 프로파일·양식을 읽고 개별 역할로 검토한다. 외부 전문가 참여가 아니다.
- 자료: 사용자 요구, 실제 StudentClassroom/main/미리보기, AGENTS/제품계획/README, getStudentHome의 class검증과 optional round, 진행 중 학급독립 게시판/교사방 작업이다.
- 현재 문제: 메인마을이 roundTitle을 prop으로 받아 학급 전체를 특정 마니또 시즌으로 표시한다. 공통 브랜드/카드/문서가 ‘우리 반 비밀친구’/반복형 마니또 서비스이며, 새 기능 구현이 회차 active조건을 상속한 결함이 실제 발생했다.

## 설계·과업·상태·반응형

1. 상위 제품은 ‘우리 반으로, 같이 떠나요’. 공통 영역은 교사/학생인증·학급·학생명부·입장코드/카드·권한·마을·공통디자인이다. 기존classId/UID/코드/데이터를 같은원본으로 계속사용한다.
2. 마니또/오늘할일/비밀우체통/게시판·자리바꾸기는 학급 아래의 별도서비스다. round/시즌/매칭/공개는 마니또 내부 상태이며 전역 마을 제목·진입조건으로 사용하지 않는다. 각 기능은 자기 활성/제출/안전조건을 검사한다.
3. 메인마을의 roundTitle prop/시즌chip/fallback대기문구와 CSS를 제거한다. 마을은 학급명·우리반월드·장소이동을 유지한다. 해당 건물은 ‘마니또’로 명명해 이 서비스의 위치를 명확히 한다. 기존2배지도/캐릭터/상호작용/복귀위치/로그아웃은 바꾸지 않는다.
4. 공통 이름을 작은상수로 관리하고 로그인상단·문서제목·새출력카드에 같은이름을 사용한다. 기존에배부한카드의코드/서버자격은변경하지않는다. 메인에삭제했던별도브랜드바를재도입하지않는다.
5. AGENTS/제품정의/새아키텍처문서/공통디자인에 계층·서비스별데이터범위·신규서비스추가규칙을 고정하고 작업채팅에 실제 전달한다. 기존 마니또 안전·반복운영 규칙은 마니또 모듈의 정책으로 보존한다. 기존 getStudentHome의 optional round는 호환필드이며 전역활동상태로 해석하지않는다. API·DB경로/인증은 이번부모변경에서바꾸지않는다.
6. 반응형은 기존 승인 도트마을을 사용한다. 칩 제거로 헤더높이를 줄이고 긴 학급명은 줄바꿈한다. 320/390/768/1280·긴학급명·키보드이동/진입·마을복귀를 실제 가상화면으로 확인한다. 서버/실학생/유료AI를 QA에 사용하지않는다.

### 구현과 실제 확인

- 로비컴포넌트에서 roundTitle prop과시즌chip을제거했고 실제/미리보기호출부에도회차를전달하지않는다. 관련CSS와프런트의옛공통브랜드문구검색결과0이다. 마니또는같은마을의명시적한건물이다.
- APP_NAME 원본과로그인상단·문서제목·새출력카드표시를통합이름으로맞췄다. 인쇄자격/기존카드코드는변경하지않았다. 상위브랜드가긴경우의상단메뉴줄바꿈을유지했다.
- AGENTS최우선규칙, class-platform-architecture.md, 제품계획v2.4, README/공통디자인/데이터/API문서의계층정의를갱신하고오늘할일/게시판/선생님방세채팅에직접전달했다. 신규서비스가마니또round를접근조건으로가져오지않게고정했다.
- 기존getStudentHome소스는class/member/sessionVersion으로공통자격을검증하고회차가없어도학급정보를반환함을확인했다. optional round는레거시마니또문맥으로보존했으며서버/API/DB경로를이번부모변경으로바꾸지않았다.
- IAB의별도cloud가상마을에서1280/768/390/320px와긴학급명,390px글자200%(root32px)를실제캡처/DOM으로확인했다. 320긴학급명의기존nowrap가page330px를만드는문제를찾아자연줄바꿈으로고쳤고최종page320px다. 최종지도viewport/scene은1280에서1066/2132,768에서714/1428,390에서356/712,320에서286/572px로2배를유지한다.
- 390/200%의기존표지상단잘림을찾아지도높이기준상한을반영한@supports보완을적용했다. 최종8표지모두상단8px이상이며본문/버튼을숨기지않고페이지가로넘침0을확인했다. 미지원브라우저는기존표지위치이므로그환경의200%품질은미확인이다.
- 실제건물선택→이동완료→E로마니또진입→공통마을복귀에서h1/초점‘우리반월드’·아바타40위치(left20%)보존을확인했다. 새스타일적용뒤동일흐름을재확인했다.
- 320/390의빈로그인표면에서통합브랜드/입장필드·버튼과가로넘침없음을확인했다. 실제학생자격은입력/조회하지않았다.
