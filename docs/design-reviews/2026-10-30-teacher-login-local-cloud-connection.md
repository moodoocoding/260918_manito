## IPv6 localhost 연결 보완 사전 검토

- 추가 사용자 재현: Chrome/Safari 새 탭 localhost 진입에도 연결 거부가 계속된다고 답했다. 서버의 HTTP200만으로 해결 판정하지 않는다.

### IPv6 보완 결과와 개별 사후 판정

- 기존IPv4 PID47635를 유지하고 별도IPv6 loopback PID57155를 시작했다. 저장소 밖 IPv6 임시 preview 설정만 추가했으며 같은 cloud 고정 빌드를 그대로 제공한다. `127.0.0.1:5174`와 `[::1]:5174` 두 listener를 확인했다.
- HTTP 확인: 숫자IPv4/IPv6 교사 진입은302/no-store→허용 localhost이고 localhost 교사 입구는200이다. 세 주소 index.html의SHA가 일치한다. 직접 IPv6의 ECONNREFUSED는 더 이상 발생하지 않았다. 기존IPv4/5173/5175의 프로세스 종료·재시작은 없었다.
- WD-01: 동일 index/빌드이므로 시각 변경 없음, 범위 통과. WD-02: CSS/반응형 변경 없음, 범위 통과. UX-01: localhost의 두 loopback 주소가 같은 교사 진입을 제공하며 기존UID/classId보존, 범위 통과. UX-02: 재현한 IPv6 결함을 고쳤으나 사용자 실제원인 확정과 구분, 범위 통과. UI-01: IPv6 전후 네트워크 응답·두 listener·동일자산 확인은 통과, 사용자 실제 진입/Google인증은 결과 대기. UI-02: loopback만 추가하고 권한·자격/학생데이터·LAN범위변경없음, 범위 통과.
- 사용자에게 같은 localhost 교사 화면의 새 요청을 안내한다. 이번 수정으로 실제 사용자 문제가 해결됐거나 Google 인증이 완료됐다는 판정은 사용자 결과까지 보류한다.


### 실제 사용자 접속 후속 확인

- IPv6 보완 후 `http://localhost:5174/teacher?retry=2` 재현 질문에 사용자가 ‘교사 화면이 열려요’라고 답했다. 교사 진입의 연결 거부 해소는 사용자 결과로 확인했다. 실제 브라우저가IPv6를 선택했는지까지 확인한 것은 아니다.
- UI-01의 실제 교사 입구 표시는 통과로 갱신한다. 같은 화면에서 Google 로그인을 진행한 결과를 추가 요청했으며, Google 계정 선택/기존 학급 목록·세션 복원은 아직 미확인이다. 이전에 요청했던 연결 재시도를 반복하지 않는다.
