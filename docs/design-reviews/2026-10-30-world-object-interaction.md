# 전문가 검토 기록: 캐릭터 이동 후 건물과 상호작용해 페이지 진입

## 검토 정보

- 날짜/범위: 2026-10-30. 도트 월드의 이동·건물 상호작용·페이지 전환을 교정한다. 인증/데이터/API 계약과 생성 이미지는 변경하지 않는다.
- 요구: 사용자는 캐릭터를 이동시킨 뒤 건물·물체를 클릭하거나 버튼/키를 눌러 해당 페이지로 들어가길 원한다.
- 수행: `/root` 한 에이전트의 여섯 가상 프로파일별 검토이며 외부 전문가 자문이 아니다.
- 자료: 사용자 요구, 현재 열린 로컬 월드, `StudentClassroom.tsx`, `web/preview/world.tsx`, 전문가 운영 지침·6개 프로파일, React 품질 스킬.
- 단계: 사전 설계. 사후 검토는 구현 후 별도 기록한다.

## 요구·문제·사용자 과업·설계

- 현재 문제(코드/사용자 보고): 표지 링크는 캐릭터가 멀리 있어도 즉시 진입하며 실제 건물 그림에는 클릭 영역이 없다. 현재 미리보기 콜백은 안내문만 바꿔 페이지 전환을 확인할 수 없다.
- 과업: 캐릭터 이동 → 건물/물체 가까이 도착 → 해당 건물 클릭 또는 ‘상호작용’/E·Enter → 목적지 페이지 → 마을 복귀.
- 이동: 좌우 방향키/A·D와 터치 방향 버튼은 누르고 있는 동안 이동한다. 길 클릭은 클릭 위치까지 이동한다. 먼 건물을 선택하면 그 건물 앞으로 걸어가며 자동으로 입장하지 않는다.
- 상호작용: 모든 진입 경로에서 같은 거리/정지 조건을 검사한다. 가까이 도착한 건물/물체는 테두리·표지 상태로 구분하고 클릭 또는 상호작용 버튼/키로 입장한다. 멀리서 표지/건물을 눌렀을 때는 이동만 한다. 목적지 이름과 상태를 현재 컨트롤 옆에 계속 표시한다.
- 구성: 기존 도트 풍경/캐릭터 → 실제 랜드마크에 맞춘 클릭 영역과 이름 표지 → 현재 장소·상호작용 버튼 → 방향 컨트롤. 도움이 필요한 경우 기존 상단 도움/로그아웃을 이용한다.
- 페이지: 실제 로그인에서는 기존 `onNavigate`와 Schooldoc URL로 전환한다. 로컬 미리보기에서는 query `place`에 따라 별도 예시 미션/우편함/게시판 페이지를 보여주고 브라우저 뒤로가기·마을 복귀를 지원한다. 예시 페이지는 인증이나 실제 데이터/API를 사용하지 않음을 표시한다.
- 저장: 월드 위치는 현재 입장 동안의 메모리만 사용하고 로그아웃/학생 전환에서 초기화한다. 복귀 시 같은 장소 앞에 돌아온다.
- 상태: 이동 중/가까운 장소/이동 가능한 빈 길/상호작용 불가/상호작용 가능/페이지 진입/마을 복귀. 중복 animation loop를 만들지 않고 키 해제·포인터 취소·창 비활성화·컴포넌트 해제에서 정리한다.
- 반응형/접근성: 360/390/768/1280px에서 지도 안 가로 탐색을 유지한다. 실제 건물 영역은 포인터 경로이고 동일 동작의 명명된 표지는 Tab/Enter로 조작한다. 지도에 초점이 있으면 방향키/E·Enter로 조작한다. 48px 버튼과 가시 초점, reduced-motion, 텍스트 상태를 유지한다.

## 전체 흐름 검증 기록

- 사용한 스킬: `vercel:verification`, `vercel:react-best-practices`.
- 검증한 이야기: 캐릭터 이동 → 클라이언트 근접/정지 검사 → 건물/버튼/E 상호작용 → 화면 라우트 및 페이지 렌더 → 마을 복귀.
- API/데이터 경계: 신규 API·데이터 저장은 없다. 실제 App은 기존 `openStudentPage`/Schooldoc URL에 연결하며 인증 경계를 우회하지 않는다. 미리보기 목적지는 예시 콘텐츠로만 구성했다.
- 기준 증거: Vite Node 프로세스가 127.0.0.1:5173을 LISTEN하고 브라우저가 현재 소스를 렌더했다. 기존 서버 터미널 세션 ID는 회수되지 않아 stdout은 확인하지 못했다. 이는 새 서버/API 기능 검증으로 대체하지 않았다.
- 최종 앱 `npm run build`, 미리보기 TSX 별도 TypeScript 검사, `git diff --check` 모두 통과했다. 기존 큰 JS 번들 경고는 남아 있다.
