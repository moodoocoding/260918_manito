# 전문가 검토 기록: 신규 학급 첫 시즌 설정 시 학생 명단 등록 및 2단계 UI 전면 개편

## 검토 정보

- **날짜 / 대상 설계 버전 또는 커밋**: 2026-09-30 / v3.2 (시즌 2단계 명단 등록 UX 혁신)
- **요청과 변경 범위**:
  - 사용자 보고 문제 1: 학생이 아직 한 명도 등록되지 않았는데 [이미지1](표시 이름 검색, 참가 학생 0명, 필수 제외 관계 0쌍 및 빈 셀렉트박스)이 화면에 노출됨.
  - 사용자 보고 문제 2: 학생을 등록하는 과정에 "⚠️ 등록된 학생이 아직 없어요!"라는 불필요하고 경고성 짙은 배너와 불필요한 '명단 등록 닫기' 토글 버튼이 노출됨 ("등록된 학생이 없으니까 등록하는 건데 왜 이런 걸 보여주는지").
  - 사용자 보고 문제 3: 학생 명단 자동 등록 카드 내부의 '닫기' 버튼 위치가 텍스트 아래 왼쪽에 어색하게 떨어져 있어 UI 완성도가 심각하게 훼손됨.
- **수행 주체·방식**: 6인 전문가 프로파일(`WD-01`, `WD-02`, `UX-01`, `UX-02`, `UI-01`, `UI-02`) 역할 기반 설계 검토.
- **입력 자료**: `web/src/TeacherRounds.tsx`, `web/src/StudentRosterImporter.tsx`, `web/src/style.css`, 사용자 업로드 스크린샷 2건.
- **검토 단계**: 사전 설계 검토.

## 사용자와 설계안

- **대상 사용자**: 초등학교 교사 (신규 학급 생성 후 첫 시즌을 준비 중인 교사 및 기존 학급 교사).
- **핵심 과업**:
  1. 첫 시즌 준비 2단계에서 복잡한 수작업 없이 우리 반 학생 명단을 엑셀/PDF/한글/복사로 10초 만에 일괄 등록.
  2. 명단 등록이 완료된 즉시 자동으로 참가자로 지정되어 참가자 확인 및 제외 관계 설정으로 매끄럽게 연결.
- **개편 설계안**:
  1. **조건부 분기(Zero-State vs Active-State) 완벽 분리**:
     - `members.length === 0` (학생 0명인 초기 상태):
       - 제목: `2. 학생 명단 등록`
       - 설명: `새 시즌을 시작하기 위해 우리 반 학생 명단을 등록해 주세요. 엑셀, PDF, 한글 파일 또는 명단을 복사해 넣으면 이름을 자동으로 찾아 즉시 등록해요.`
       - 불필요한 경고 배너("⚠️ 등록된 학생이 아직 없어요!") 및 상단 "명단 등록 닫기" 토글 버튼 **완전 제거**.
       - 하단 [이미지1] 영역(학생 검색, 전체 선택, 참가 학생 0명, 필수 제외 관계 0쌍) **완전 숨김** (등록된 학생이 없으면 검색·제외도 불필요).
       - `<StudentRosterImporter>`를 화면의 주 과업으로 **자동/기본 노출**하되, 학생이 없으므로 `onCancel` 없이 온전히 등록에 집중하도록 구성 ('닫기' 버튼 미노출).
     - `members.length > 0` (학생 등록 완료 상태):
       - 제목: `2. 참가자와 필수 제외 관계`
       - 설명: `{participants.length}명 선택 · {members.length - participants.length}명 미선택`
       - 참가자 목록 체크박스 및 필수 제외 관계 설정([이미지1]) 정상 노출.
       - 상단에 깔끔한 보조 버튼 `[+ 새 학생 명단 추가/가져오기]`를 배치하여 필요 시에만 서랍형으로 열고 닫을 수 있게 지원.
  2. **'닫기' 버튼 레이아웃 버그 수정 및 헤더 플렉스 정돈**:
     - `StudentRosterImporter.tsx`의 헤더 클래스를 CSS와 일치시키고 `display: flex; justify-content: space-between; align-items: flex-start; gap: 16px;`를 적용.
     - `onCancel`이 제공될 때만 우측 상단에 단정한 `✕ 닫기` 버튼으로 정렬하여 텍스트 아래로 떨어지던 레이아웃 붕괴 문제 해결.

## 6개 관점의 사전 판단

| 프로파일 | 검토 내용과 근거 | 판정 |
|---|---|---|
| **WD-01 · 시각 구성과 브랜드** | 빈 박스와 비활성 셀렉트박스들이 가득했던 0명 상태의 지저분한 화면([이미지1])을 완전히 걷어내고, 학생 명단 임포터 카드를 주인공으로 세워 단정하고 목적 지향적인 캔버스를 형성함. 상단 경고성 배너와 중복 닫기 버튼이 사라져 시각적 소음이 완전히 제거됨. | **통과** |
| **WD-02 · 반응형 레이아웃과 타이포그래피** | 잘못된 block 배치로 본문 텍스트 아래로 뚝 떨어져 줄바꿈되던 '닫기' 버튼을 flex 우측 상단 정렬로 교정함. 모바일과 데스크톱 모두에서 카드의 헤더 영역과 탭 영역이 올바른 수직 리듬을 유지함. | **통과** |
| **UX-01 · 정보 구조와 과업 흐름** | 0명일 때는 [명단 등록] 단일 과업에만 집중시키고, 등록이 완료되는 즉시 [참가자 선택 & 제외 관계]로 자연스럽게 상태가 전환되는 프로그레시브 디스클로저(Progressive Disclosure) 구조 확립. 불필요한 뒤로가기/닫기 루프 차단. | **통과** |
| **UX-02 · 인지 부담과 사용자 이해** | 사용자가 지적한 "등록된 학생이 없으니까 등록하러 온 건데 왜 경고를 하느냐"는 지적을 100% 수용. "등록된 학생이 아직 없어요!"라는 죄책감/경고성 표현을 제거하고 친절한 온보딩 안내로 전환하여 인지 부하 제로화. | **통과** |
| **UI-01 · 조작과 컴포넌트 상태** | 학생이 0명일 때는 '닫기'를 눌러도 갈 곳이 없으므로(빈 화면만 남음) 불필요한 '닫기' 액션을 제거. 학생이 이미 있을 때만 추가 등록 모달/서랍의 `✕ 닫기`를 우측 상단에 정렬하여 명확한 인터랙션 상태 모델 완성. | **통과** |
| **UI-02 · 접근성과 화면 품질** | 학생 0명 상태에서 의미 없는 빈 `fieldset`과 빈 `<select>` 요소들이 스크린리더나 탭 네비게이션에 걸리던 웹 접근성 결함 해결. 각 단계에 필수적인 양식 컨트롤만 DOM에 렌더링됨. | **통과** |

## 발견 사항과 조치

1. **P0: 0명일 때 빈 참가자/제외 컨트롤 노출로 인한 사용자 혼란([이미지1])**:
   - `members.length === 0`일 때는 참가자 목록, 검색, 필수 제외 관계 폼을 숨기고 `StudentRosterImporter`만 표시.
2. **P1: 중복 배너 및 비논리적 '명단 등록 닫기' 버튼 노출([이미지2])**:
   - `members.length === 0`일 때 상단 안내 배너(`.roster-import-trigger-box`) 제거.
3. **P1: '닫기' 버튼 레이아웃 깨짐(위치 어색함)**:
   - `roster-importer-header`에 flex 레이아웃을 부여하고, `members.length === 0`일 때는 닫기 버튼을 비활성화(미제공).

**착수 판정**: 6개 관점 모두 통과, 미해결 P0/P1 없음. 구현 착수 승인.

## 구현 후 실제 검증

- **빌드 및 단위 테스트**: TypeScript 컴파일 및 Vite 프로덕션 빌드 성공, 함수 12건 통과, QR 1건 통과.
- **학생 0명 상태(Zero-State) 확인**:
  - `members.length === 0`일 때 [이미지1]의 빈 검색창, 0명 참가자 체크박스, 0쌍 필수 제외 폼이 완전히 숨겨짐 확인.
  - "⚠️ 등록된 학생이 아직 없어요!" 배너와 상단 "명단 등록 닫기" 토글 버튼이 제거되고, `StudentRosterImporter`가 기본 오픈 상태로 부드럽게 렌더링됨.
  - 학생이 0명이므로 '닫기' 버튼이 노출되지 않아 의도치 않게 빈 화면으로 돌아가는 루프가 차단됨.
- **학생 등록 완료 후 상태(Active-State) 전환 확인**:
  - 학생 명단을 등록하면 `members`가 갱신되어 자동으로 [2. 참가자와 필수 제외 관계] 화면으로 전환됨.
  - 상단에 `[📋 학생 명단 추가 / 가져오기]` 버튼이 배치되며, 클릭 시 열리는 임포터 카드의 우측 상단에 `✕ 닫기` 버튼이 정렬되어 텍스트 밑으로 떨어지던 버그가 완벽히 해결됨.
- **6개 관점 사후 판정**:
  - `WD-01`: 통과 (시각적 군더더기 및 빈 컨트롤 제거, 정돈된 임포터 캔버스 형성)
  - `WD-02`: 통과 (헤더 flex 정렬로 '닫기' 버튼 위치 정상화)
  - `UX-01`: 통과 (0명 단계에서 명단 등록에만 집중시키는 흐름 완성)
  - `UX-02`: 통과 (불필요한 경고 문구 배제로 사용자 친화적 온보딩 달성)
  - `UI-01`: 통과 (0명 시 닫기 액션 비노출, 등록 후 추가 시 닫기 정상 작동)
  - `UI-02`: 통과 (빈 양식 컨트롤 제거로 키보드 및 스크린리더 접근성 향상)
