# 전문가 검토 기록: 학생 화면 완성도와 시즌 참여 정보 개선

## 검토 정보

- 날짜 / 대상: 2026-09-28, 디자인 수정 계획서 v2.0·개발 계획서 v2.3. 코드 근거는 검토 시작 시 `1634962` 이후 작업 트리이며 당시 공개 전 이름 비노출의 별도 미커밋 작업을 포함했다. 문서 작성 중 해당 별도 작업의 `c0798d0` 커밋·배포가 작업일지에 기록됐고 이 문서는 그 변경을 보존했다.
- 요청: 학생 화면의 간격·사용성·완성도 재검토, 다른 학생들의 미션 실천 현황 등 도움이 되는 정보를 기획하고 두 계획서를 갱신.
- 범위: 읽기 전용 코드 진단·정책/화면/상태/계약 후보·검증 계획 작성. 제품 구현·배포·실제 학생 자료 열람은 포함하지 않음.
- 수행 주체·방식: Codex 한 에이전트가 6개 가상 전문가 프로파일을 각각 적용한 역할 기반 검토. 외부 전문가 6명이나 실제 학생이 참여한 검토가 아님.
- 입력: 사용자 보고, [6개 프로파일과 운영 지침](../experts/README.md), [디자인 계획](../design-revision-plan.md), [개발 계획](../manitto-development-plan.md), [작업일지](../work-log.md), `web/src/main.tsx`, `StudentRound.tsx`, `style.css`, `functions/src/rounds/activity.ts`, `missions.ts`.
- 단계: **사전 설계 준비·문서 검토**. 이번 턴에서 브라우저·스크린샷·계산 스타일 측정·실제 아동 관찰·자동 기능 테스트는 수행하지 않음.

## 사용자와 설계안

- 대상: 1~2/3~4/5~6학년 학생, 교실 공용 PC·태블릿과 좁은 모바일 화면. 교사는 우리 반 소식의 공개 여부·짧은 안내를 관리한다.
- 주요 과업: 시즌/내 기록 이해 → 미션 고르기·실천·쉬기 → 쪽지·답장 → 학급의 배려 소식에서 아이디어 얻기 → 도움·마치기 → 다음 시즌.
- 사용자 보고: 간격 불균형·불편·낮은 완성도, 다른 친구의 실천 정보를 볼 수 없음. 보고된 모든 시각 문제를 이번에 실측 재현한 것은 아니다.
- 코드 확인: 일반/학생 CSS 규칙의 중첩, 680px 본문과 1180px 헤더, 첫 todo/전체 목록 전환, `다른 미션`의 교체 API 연결, 같은 패널의 작성/수신/발신, 개인·학급 요약 계약 부재.
- 구성: 홈/미션/우편함/우리 반, 공통 도움·마치기, 홈의 지난 활동 링크. 실제 배치는 디자인 계획 §3, 간격·폭은 §4·6, 상태·복귀는 §5에 명세했다.
- 저장: 목록 탐색은 무변경, 개인 선택은 편의 상태, 완료/쉬기/교체는 명시적 기록 변경. 학급 집계는 본인 요약과 분리된 서버 발행본.
- 주요 상태: 미참가/활동 없음/진행/비활동일/일시정지/공개 대기/공개/보관, 집계 미제공/조회 실패, 저장 중/실패/성공 후 조회 실패, 권한 상실.
- 반응형: 학생 공통 폭 760px, 320~390 단일 열, 4메뉴가 큰 글자에서 2×2로 재배치. 1~80개·100자 미션·200자 쪽지·긴 제목·키보드·200% 확대 포함.

## 6개 관점의 개별 판단

### WD-01 · 시각 구성과 브랜드

**현재: 수정 필요.** 인사·페이지 제목·시즌 패널을 연속 배치하고 미션·쪽지 행동을 동일한 패널 언어로 다룬다. 이미 일부 학생 CSS가 있어 ‘학생 디자인 변경이 전혀 없었다’고 단정할 수는 없지만, 코드의 중복 계층과 사용자 보고는 다음 행동의 시각적 우선순위를 다시 설계할 근거다. SD-01·02·07.

**계획: 근거 부족.** 짧은 인사·시즌 맥락·개인 기록·미션의 순위와 단일 주요 행동, 8/16/24/32 간격 체계는 개선 방향을 구체화했다. 그러나 실제 색·텍스트·줄바꿈이 들어간 대표 시안은 아직 없다. SE-0에서 진행/빈/오류/공개 상태의 390·768·1280 시안을 보고 과한 공백·카드 강조 경쟁을 판단한다. 귀여운 장식을 더하는 것으로 완료 처리하지 않는다.

### WD-02 · 반응형 레이아웃과 타이포그래피

**현재: 수정 필요.** 헤더/본문의 폭 차이, gap과 margin이 여러 계층에 있는 CSS, 모바일 버튼 flex-grow에 따른 마지막 버튼 확장, 최대 80개 전체 목록은 배치 일관성을 해치는 구조적 요인이다. 실제 현재 화면의 몇 px가 틀렸는지는 미측정이다. SD-01·02·03·07.

**계획: 근거 부족.** 같은 최대 폭·관계별 간격 소유·미션 8개씩 탐색·긴 문구 높이 자동·메뉴 재배치를 정의했다. SE-0의 실제 콘텐츠 시안에서 320px/긴 한국어/확대 상황을 보완하고, 구현 후 관계별 간격과 시각 균형을 함께 확인해야 한다. 숫자상 넘침 0만으로 통과시키지 않는다.

### UX-01 · 정보 구조와 과업 흐름

**현재: 수정 필요.** 지금 미션 하나와 전체 목록 사이에 선택을 돕는 흐름이 없고, 시즌·내 기록·학급 소식이 연결되지 않는다. 탐색처럼 보이는 교체 버튼은 서로 다른 목적을 합친다. SD-03·04·05·06·08·10.

**계획: 통과(문서의 흐름 설계 범위).** 네 메뉴의 목적·홈 미리보기 범위·상세 복귀·현재/지난 시즌을 구분했다. 도움/로그아웃은 메뉴 증가와 무관하게 접근 가능하다. 미션 탐색·편의 선택·기록 변경의 저장 범위를 분리했고, 기존 history 경로도 보존한다. 실제 사용성과 새 경로 구현이 통과했다는 뜻은 아니다.

### UX-02 · 인지 부담과 사용자 이해

**현재: 수정 필요.** ‘다른 미션’의 실제 효과, 현재 미션 목록의 의미, 기록과 실제 실천의 차이를 학생이 추측해야 한다. 다른 학생 정보의 필요를 채우면서 비교 압박을 만들지 않는 표현이 필요하다. SD-04·05·06·11.

**계획: 통과(문구·선택 설계 범위).** 미션 골라보기/바꾸기/쉬기의 결과를 구분하고, 개인 요약에 의무 완료나 점수를 붙이지 않았다. 학급 요약이 나를 포함한 대략적 기록임을 명시하고, 예시는 실제 인기 미션으로 가장하지 않는다. 저학년 문장·예시와 고학년의 과한 유아화 방지를 함께 지정했다. 학년군별 이해는 아직 가정이며 SE-4의 관찰로 검증한다.

### UI-01 · 조작과 컴포넌트 상태

**현재: 수정 필요.** 공통 busy/error 위치는 실행한 항목의 결과를 연결하기 어렵게 만들 수 있고, 다수 쪽지·미션에서 탐색/저장/교체를 더 명확히 분리해야 한다. SD-04·07·08·09.

**계획: 통과(상태 명세 범위).** 카드/폼의 처리·성공·실패·결과 확인 중, 저장 성공 후 재조회 실패, 일반 이탈과 유휴 로그아웃의 입력 처리, 목록 초점 복귀를 분리했다. 없는 읽음 계약이나 todo 복귀 기능을 UI에서 먼저 약속하지 않는다. 신규 함수 후보는 구현 전 확정이 필요하며 버튼 상태 구현은 미검증이다.

### UI-02 · 접근성과 화면 품질

**현재: 수정 필요.** 과거 자동 검사·일부 폭의 통과는 새 학생 전체 과업의 키보드·보조기기·긴 콘텐츠·집계 비밀 유지의 증거가 아니다. SD-11·12.

**계획: 근거 부족.** 터치 목표, native 컨트롤·초점·메뉴 의미, 확대와 reflow 구분, 자동·수동 검증 분리는 적절하다. 다만 실제 시안의 대비·긴 버튼/오류 배치와 학급 집계의 차분·희소 정보 추론 가능성에 대한 가상 데이터 분석이 남아 있다. 인원 10/기여자 5/합계 10 기준만으로 익명성을 통과시킬 수 없다. SE-0에서 해당 위험과 응답 경계를 검토하고 안전하지 않으면 숫자 기능을 보류한다.

### 의견 차이와 설계 선택

- ‘친구들의 성공 현황을 풍부하게 보여주기’와 ‘비밀·비교 부담을 줄이기’ 사이에서 개인 현황표 대신 학급 요약+실천 아이디어를 선택했다. 소규모 학급을 빈 화면으로 두지 않는다.
- 많은 미션을 한눈에 보여주는 안과 한 과업 집중 사이에서 홈에는 선택한 한 개, 미션 화면에는 필터와 8개씩 탐색을 선택했다. 숨겨진 자동 추천으로 학생의 선택권을 줄이지 않는다.
- 네 메뉴가 늘어나는 부담은 홈의 입력 폼 제거·일관된 링크·확대 시 재배치로 대응한다. 메뉴 4개라는 숫자 자체가 최적이라는 주장은 하지 않는다.
- 예쁜 시안만으로 통과하는 문제를 막기 위해 빈/오류/최대 항목·실제 브라우저·학생 이해를 별도 판정한다.

### 착수 판정

**문서 갱신 완료, 구현 착수 판정은 보류.** 흐름·문구·상태의 서면 명세는 정리했지만 WD-01·WD-02·UI-02가 근거 부족이며, 대표 시안과 SD-11의 가상 추론 위험 검토가 남았다. SE-0에서 보완한 뒤 6개 관점 모두 통과하고 미해결 P0/P1이 없는 범위부터 구현한다. 이번 사용자의 요청은 계획서 갱신이므로 문서를 미완료로 남기거나 별도 사용자 승인을 요구할 이유는 없다.

P2는 표의 담당과 단계에서 해결하고 이번 변경 범위의 P2를 다음 과제로 숨겨 완료 처리하지 않는다. 학급 집계의 추정 가능성은 기능을 축소하는 대안까지 열어 둔다.
