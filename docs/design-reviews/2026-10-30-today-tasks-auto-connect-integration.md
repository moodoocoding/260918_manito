# 전문가 검토 기록: 오늘 할 일 본인 자동 연결 통합

## 검토 정보·설계

- 날짜2026-10-30. 수행은 `/root` 한 에이전트가 여섯 가상 역할을 적용한 최소 통합 검토이며 외부 전문가 승인을 뜻하지 않는다.
- 입력은 오늘 할 일 사용자 채팅의 직접 요청(이중 로그인 제거, 현재 한 학급·동명이인 없음), 담당 채팅의 `autoConnect`/`authorize` 계약, 기존 main의 getStudentHome/세션 generation 검사와 preview의 가상 client, 전문가 운영 지침과 여섯 프로파일이다.
- 범위는 부모 소유 main/preview의 두 연결부다. 컴포넌트 자동 연결·상태/오류/200% 재배치는 오늘 할 일 담당 채팅에서 별도 검토/검증한다. Schooldoc 원본·서버·DB·권한은 이 통합에서 변경하지 않는다.
- 학생은 마을→오늘 할 일→최신 서버검증 본인 이름으로 자동 조회→미션을 확인한다. main은 `autoConnect`를 주고 authorize가 기존 getStudentHome 응답의 displayName을 반환한다. 이미 유지 중인 generation 비교 뒤에만 반환한다. preview는 가상 학생 이름만 반환한다.
- 화면 구조는 기존 도트 배경/나무 헤더/종이 내용이며 입력폼 대신 연결 중/실패 재시도/도움과 결과 목록이다. 실제 학생 이름을 URL·저장소에 추가하지 않는다. 권한 실패 시 기존 exit를 유지하고 재인증 전에 외부 조회를 시작하지 않는다. 동명이인/다른 학급 확장은 별도 식별 계약이 필요하다.
- 반응형 공통 틀은 직전 공통 검토를 따른다. 새 긴 문구/로딩/오류는 담당 채팅이320/390/768/1280 및 글자 확대 상태로 확인한다.

## 문제·착수 판정

- A-01 P1: 본인 displayName을 오래된 home 상태에서 가져오면 다른 세션 이름을 사용할 수 있음 → H5/공용기기 보호 → 잘못된 학생 조회 → 최신 getStudentHome 반환값과 generation 검사 뒤에만 반환 → 코드 대조와 가상 자동진입 확인. 사전 설계에서 해소.
- A-02 P2: 동명이인/여러 학급에서 이름 자동연결을 일반화하면 불일치 위험 → 정확한 식별 필요 → 현재 사용자가 명시한 한 학급/동명이인 없음 범위에 한정, 확장 전 담당 연동 개발자가 별도 식별 계약을 설계·검증. 기존 Schooldoc 계약을 보편적 SSO로 보고하지 않는다.
- 여섯 관점 통과, 미해결 P0/P1 없음. 부모 통합 구현에 착수할 수 있다.
- 검증 조건 보완: 실제 main과 같은 React StrictMode를 world preview에도 적용한다. WD-01/WD-02는 최종 배치 영향 없음, UX-01/UX-02는 중복진입/멈춤을 재현해 과업 일관성을 확인할 수 있음, UI-01은 effect 정리/재실행 조건 일치, UI-02는 전환 뒤 제목 초점 검증 조건 일치를 각각 근거로 통과했다. 가상 client만 사용하며 운영 데이터 제출은 없다.

## 사후 확인

- main/preview의 `autoConnect`와 최신 이름 반환을 연결했다. 실제 main의 기존 인증 실패 종료·generation 검사·마을/종료/도움 callback을 유지했다. preview에는 StrictMode를 적용했다.
- `/root`가 실제 IAB live5173 world preview의1536×1024에서 reload→로딩→가상 본인 미션 목록 자동 표시를 확인했다. 이름입력 필드0개, 제목 초점 ‘오늘 할 일’, 페이지 가로 넘침 없음이다. StrictMode 적용 후 reload에서도 자동조회가 완료됐다.
- 웹 TypeScript/Vite 빌드, world/teacher-mailbox preview strict tsc, 기존 Schooldoc API/취소/lifecycle 단위9/9와 diff공백 검사를 통과했다. 큰 JS 청크 경고는 남는다.
