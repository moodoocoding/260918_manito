# 학생 쪽지 두 대화창 검토

## 검토 정보

- 날짜/기준: 2026-09-28, `aef7a8c` 기준 학생 우편함·쪽지 함수
- 요청: `내가 맡은 친구`와 `나를 맡은 친구`의 대화 분리, 쪽지가 두 사람에게 동시에 가는 것처럼 보이는 혼란 해소
- 수행: Codex 한 에이전트가 여섯 가상 전문가 프로파일을 각각 적용한 역할 기반 사전 검토. 실제 외부 전문가·학생 참여는 없다.
- 입력: 사용자 보고, `web/src/StudentRound.tsx`, `functions/src/rounds/activity.ts`, 통합 테스트, 개발 계획 §1108과 여섯 프로파일

## 사용자와 설계

- 학생 과업: 관계의 실제 이름을 모르는 상태에서 대화 방향을 선택하고 단 한 명에게 쪽지를 보낸다. 받은 쪽지를 숨기거나 교사에게 알릴 수 있다.
- 코드 확인 결과, 첫 쪽지는 서버가 자신의 배정 상대 한 명에게 보내고 답장은 자신이 실제로 받은 쪽지의 발신자 한 명에게만 보낸다. 동시 전달 사례는 확인하지 못했다. 현재 UI의 받은/보낸/새 쪽지 탭은 두 관계의 쪽지가 섞여 보여 수신자를 오해할 수 있다.
- 우편함 구성: `내가 맡은 친구` / `나를 맡은 친구` 두 탭. 각각 그 관계에서 주고받은 쪽지를 시간순으로 보여준다. 이름·UID는 표시하지 않는다. 첫 탭의 새 쪽지는 맡은 친구 한 명에게 간다. 둘째 탭은 그 친구에게서 실제로 받은 쪽지가 있을 때에만 해당 쪽지의 익명 답장으로 전송한다.
- 관계 분류: 학생 본인의 보낸 첫 쪽지로 시작한 연결과 그 답장은 첫 탭, 자신이 받은 첫 쪽지로 시작한 연결과 그 답장은 둘째 탭. 두 역할이 우연히 같은 학생이어도 시작 방향으로 두 대화를 분리한다. 기존 쪽지도 본인 사본의 답장 연결을 따라 분류한다. 연결이 손상되어 분류할 수 없는 쪽지는 별도 읽기 영역에 놓고 송신 동작은 제공하지 않는다.
- 각 탭의 작성 문구·직접 작성 초안은 분리해 입장 중 메모리에만 둔다. 탭 전환이 상대를 바꾸거나 쪽지를 자동 전송하지 않는다. 보내기 전 `한 명에게만 전달`을 표시한다. 일일 10건·200자·수업일 제한, 숨김·신고·교사 모니터링은 유지한다.
- 상태: 대화 없음·둘째 관계의 답장 가능 쪽지 없음·로딩·한도 소진·전송 성공/오류·숨김/신고를 명확히 표현. 모바일 단일 열, 긴 200자 문장 줄바꿈, 320·360·390·768·1280px, 키보드와 초점 확인.

## 발견 사항·조치

| ID·심각도 | 문제 → 근거 → 영향 | 수정안 | 확인 방법 |
|---|---|---|---|
| M1·P1 | 두 관계의 받은/보낸 쪽지가 섞임 → H2/H6 → 둘 모두에게 보내진다고 오해 | 관계별 대화창과 단독 수신 설명 | 두 방향의 실제 쪽지 흐름 |
| M2·P0 예방 | 수신자 판단을 UI에 맡김 → 비밀 관계·권한 원칙 → 타인 전송 가능 | 서버의 기존 첫 쪽지/받은 쪽지 답장 결정 유지, 두 방향·두 사람 일치/불일치 테스트 | 에뮬레이터 권한/전달 검사 |
| M3·P1 예방 | 탭 사이 작성 내용 공유 → H5 → 다른 방향에 잘못 보낼 위험 | 탭별 독립 초안과 명시적 수신 설명 | 탭 왕복·전송 |
| M4·P1 예방 | 기존 답장 연결/두 역할 동일인이면 잘못 분류 → H1 → 대화 혼합 | 첫 쪽지의 본인 송·수신 방향을 답장 체인 끝까지 상속, 불명 시 안전한 별도 영역 | 기존 사본·동일인 시나리오 |

- 의견 차이: 둘째 대화에 자유롭게 새 쪽지를 시작하는 안은 현재 서버의 `받은 쪽지에만 답장` 제한과 충돌한다. 익명 수신자를 서버가 확정할 수 있는 받은 쪽지가 있을 때 그 중 최신 쪽지에 답장하는 흐름을 선택했다.
- 사전 판정: M1~M4 수정안에서 여섯 관점 모두 통과, 미해결 P0·P1 없음. P2·P3 없음. 구현 착수 가능.
