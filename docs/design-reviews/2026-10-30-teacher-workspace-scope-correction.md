# 전문가 검토 기록: 선생님 방 통합 운영 허브 확정

## 검토 정보

- 날짜: 2026-10-30 / 사전 설계 v2. Codex 단일 에이전트가 여섯 가상 프로파일로 개별 검토했다. 외부 전문가 참여는 없다.
- 사용자 정정: 같은 목재 허브 이미지를 다시 제시하며 ‘이런걸 원한다니까..? 전체를 조율할 수 있는?’라고 명시했다. 이미지는 원하는 통합 운영 구조의 기준이다. 이전에 이 이미지를 디자인 거절로 추정한 준비 판단은 철회한다. 교사 목재 프레임을 제거하거나 단일 마니또 대시보드로 복원하지 않는다.
- 자료: 사용자 기준 이미지/정정, 최신 AGENTS·공통 디자인/기준 이미지·상위 구조, 여섯 프로파일/양식, 기존 teacher-room-service-hub 검토, 현재 main.tsx/teacher-room.css 및 실제 제공 cloud 빌드. 부모는 공통 문서에 이번 사용자 기준을 반영했다.
- 범위: 선생님 방의 기존 프레임/좌측 공통관리/학급 문맥/서비스 카드를 유지하고 진입·관리 연결을 완성한다. 학급/명부/카드는 공통, 마니또는 네 서비스 중 하나다. 기존 API/권한/DB·UID/classId·카드와 학생 화면은 보존한다.

## 사용자와 설계안

- 핵심 과업: 기존 교사 계정으로 같은 학급의 공통 정보와 서비스별 운영/연결 상태를 한 선생님 방에서 확인하고 이동한다.
- 현재 문제: 기본로그인후 학급목록만 보여 통합 허브 진입이 드러나지 않음. 마니또/우체통 외 서비스는 비활성 카드라 상태/관리범위를 탐색할 수 없음. 이전 응답이 기준 이미지를 거절로 오해함.
- 진입: 인증된 교사의 기존학급이 하나면 그classId의서비스허브로바로연결한다. 0개는공통개설, 여러개는명시적으로학급을선택한다. 기존학급상세직접링크는자동선택으로덮어쓰지않는다. `/teacher`의학급목록버튼으로돌아온경우는자동재선택하지않는다.
- 구성: 승인된목재헤더/종이, 좌측공통관리·서비스별메뉴, 상단현재학급, 네서비스카드유지. 네서비스모두운영화면또는연결상태화면으로이동가능하다. 마니또/우체통은기존실제운영, 오늘할일/게시판은학생제공범위와교사관리미연결을설명하는전용상태화면을제공한다.
- 상태화면: 제공중인학생기능/선생님방에서아직연결되지않은관리행동을분리해표시한다. 서버저장API없는ON/OFF·가짜건수·전체기능운영완료표현은추가하지않는다. 공통명부와서비스모음으로복귀가능하다.
- 페이지명세: 기존services/overview/mailbox/students/settings/마니또내부페이지유지, today-tasks/class-board두읽기전용교사상태라우트추가. 공통카탈로그에서사이드바/카드/상태화면을파생한다.
- 상태·저장: 기존교사승인·로딩/오류·회차이탈확인·카드보호를유지한다. 새화면은외부조회/저장없다. Google인증의실제완료여부와UI허브구현을별개로기록한다.
- 반응형: 기존최대1200/좌측메뉴와2열카드,900이하1열·모바일메뉴를유지한다. 긴학급명/서비스제목줄바꿈, 본문16px이상·48px조작과현재초점표시를유지한다. 상태화면의행동은줄바꿈가능한actions영역에묶는다.

### P1-4 · 우체통 배포 의존성

- 문제 → 근거 → 영향: 선생님 방 채팅의 읽기 전용 배포 메타데이터 조사에서 `manito-938cc`에 우체통 Callable 5개가 없음을 확인했다. 허브의 ‘운영 가능’·‘우체통 열기’가 실제 서버 가용성과 다르므로 사용자가 호출 오류를 만난다(H1/H5/H9).
- 조치 담당/시점: 선생님 방 배포 담당이 Git/Vercel 스냅샷 확정 전에 미연결 상태 안내와 API 호출 보류를 검토한다. 이번 UI 검증은 Firebase 배포를 허가하거나 실행한 것이 아니다. 서비스 제공 요청과 서버 배포 범위는 해당 채팅의 직접 사용자 지시로 확인한다.
- 확인 방법: 수정 뒤 학생 진입/교사 카드·메뉴·직접 URL에서 미배포 API를 호출하지 않는지, 이유와 복귀 동작이 보이는지 재검증한다. 서버를 별도로 배포하게 된다면 권한·학급 격리·접수/조회/처리와 공개 차단까지 별도 검증한다.
- 현재 완료 판단: 허브의 반응형/탐색 검증은 수행했지만 P1-4가 미해결이므로 현재 상태의 제품 배포 완료 판정은 보류한다. 실제 Google 인증·현재 학급 데이터 동작은 여전히 미확인이다.

### P1-4 수정 뒤 부모의 실제 브라우저 재확인

선생님 방 담당의 `teacherMailServerReady=false` 분기와 최종 cloud 고정 빌드 갱신 뒤, 부모가 같은 허용 IAB에서 새 임시 탭으로 확인했다. 기존 사용자 탭을 새로고침하지 않았다.

- 허브의 우체통 배지는 ‘서버 연결 준비 중’, 행동은 ‘연결 상태 보기’, 메뉴는 ‘우체통 연결 상태’다. 카드와 메뉴 모두 준비 상태 페이지로 이동하고 h2 초점을 받는다. 접수/교사 조회 폼이 없으며 서비스 모음으로 복귀한다. `assets/teacher-hub-mail-pending-1280.png`.
- `?view=student-mail`은 실제 `StudentTeacherMailboxPending`을 렌더링한다. 390×844에서 도트 배경/목재/종이를 확인했고 문서 폭390px, form/input/textarea0개다. ‘아직은 여기서 편지나 신고를 보낼 수 없어요’, ‘도움이 필요하면 선생님께 직접 말씀해 주세요’를 표시한다. native Enter로 마을 복귀/활동 마치기 callback의 각각 다른 안내를 확인했다. 실제 세션 종료를 실행하는 fixture는 아니다. `assets/student-mail-pending-390.png`.
- 코드 조회로 학생 `/student/mail`과 교사 mailbox 분기 모두 동일한 false 설정을 사용해 실제 접수/조회 컴포넌트 대신 준비 상태를 마운트함을 확인했다. 배포 JS에서 함수 이름이 제거됐다는 검사는 배포 담당의 빌드 검사 결과이며 부모의 네트워크 계측 결과로 표현하지 않는다.
- 여섯 관점 재판정: WD-01은 공통 재질과 상태 배지 유지, WD-02는 짧은 학생 안내의 모바일 줄바꿈, UX-01은 카드/메뉴/직접 경로의 같은 상태 도착, UX-02는 접수 불가·직접 도움 경로의 명시, UI-01은 접수 폼 보류·복귀/종료 callback, UI-02는 native 키보드·제목 초점·읽을 수 있는 실제 HTML 근거로 **노출 보류 범위 통과**다. 이 변경으로 P1-4의 ‘실제로 운영 가능한 것처럼 표시하고 미배포 API를 호출하는 문제’는 해결했다.
- 우체통 서비스 자체는 서버 미배포/미제공 상태다. 실제 접수·조회·처리·공개 차단은 완료로 판정하지 않으며 향후 선택 배포와 별도 전체 흐름 검증이 필요하다. 실제 Google 인증/현재 학급 조회·저장/스크린리더·실기기 제한도 유지한다. Git/Vercel 배포 여부는 담당 채팅의 별도 결과를 따른다.


### 배포 실행 환경 보강의 추가 사전 검토
