- 날짜 / 대상 설계 버전 또는 커밋: 2026-10-30 / 학생 로그인 및 로그인 후 첫 화면 개편 설계
- 요청과 변경 범위 / 범위 밖 항목: 기존 학생 카드 인증 화면과 로그인 후 메인 공간을 첨부 참조의 레트로 픽셀 아트·횡스크롤 게임 분위기로 다시 구성한다. 기존 Firebase 로그인·보안·기능/API/데이터 계약은 유지한다. 교사 화면, 외부 학교 문서 페이지, 게임 점수·재화·랭킹 기능은 범위 밖이다.
- 수행 주체·방식: Codex 한 에이전트가 여섯 가상 프로파일의 기준을 각각 적용해 사용자가 첨부한 이미지, 요구사항, 학생 로그인·공간 코드와 기존 작업 기록을 검토했다. 외부 전문가 자문은 없었다.
- 입력 자료: 사용자 첨부 `codex-clipboard-6ff5656f-44fa-410a-9a73-c249b2659985.png`, `AGENTS.md`, `docs/experts/README.md`와 여섯 프로파일, `web/src/main.tsx`, `web/src/StudentClassroom.tsx`, `web/src/style.css`, `docs/design-reviews/2026-10-30-class-space-main.md`
- 검토 단계: 사전 설계

## 사용자와 설계안

- 대상 사용자·이용 환경·핵심 과업: 1~6학년 학생이 공용 교실 기기나 개인 기기에서 학급 코드와 개인 입장 카드로 로그인한 뒤, 캐릭터가 있는 학급 월드에서 오늘 할 일·미션·우편함·우리 반 공간을 찾아 이용한다.
- 현재 문제와 재현 조건: 첨부 이미지는 HUD가 있는 횡스크롤 픽셀 월드와 이동 가능한 캐릭터·건물 입구를 보여준다. 현재 구현은 일반 로그인 폼과 위에서 내려다본 교실 바닥 지도여서 원하는 게임형 분위기와 다르다. 이는 사용자 설명 및 첨부 이미지에 근거한다.
- 페이지·섹션 구성과 이동 경로:
  - 학생 입장 `/student`: 현재 카드 인증 필드(학급 코드, 카드 코드, 공용기기 자동 로그인 선택)와 입장 버튼을 유지하고, 하늘·구름·픽셀 풍경과 픽셀 프레임으로 재구성한다. 교사 로그인 전환은 그대로 둔다.
  - 로그인 후 `/student`: 상단에 학급·회차 문맥과 기존 도움/활동 마치기를 두고, 가로로 펼쳐진 풍경·지면·캐릭터·기능 건물을 보여준다. ‘오늘 할 일’은 기존 사용자가 지정한 Schooldoc URL, 나머지는 기존 내부 기능 화면으로 이동한다.
  - 화면을 360px 이하에서 가로로 탐색 가능한 장면으로 재배치하되 각 기능은 이름 있는 버튼/링크로 직접 실행한다. 키보드 좌우, 터치 화살표와 장면 가로 이동을 제공한다.
- 각 화면의 목적·주요 행동·저장 범위: 입장은 기존 서버 인증만 수행한다. 월드는 탐색·기능 진입 허브이며 자체 저장은 없다.
- 기본·빈 상태·로딩·오류와 복귀: 기존 인증 대기·오류 메시지를 유지한다. 회차가 없으면 월드는 표시하고 회차 준비 안내를 노출한다. 로그아웃·도움은 모든 학생 화면의 상단에 계속 보인다. 외부 링크는 같은 탭 이동이다.
- 반응형·긴 텍스트·최대 항목·키보드 설계: 1280/768px에서는 전체 장면이 가능한 한 한눈에 보이고, 390/360px에서는 월드의 가로 스크롤과 명명된 직접 링크를 제공한다. 버튼은 48px 이상 터치 목표, 포커스 링, 색 이외의 텍스트 라벨을 유지한다. 동작 애니메이션은 `prefers-reduced-motion`을 따른다.

- 의견 차이와 선택 이유: 정적인 카드 UI만 유지하면 사용자가 원하는 횡스크롤 월드 감각이 부족하다. 반대로 실제 게임식 점수/보상 HUD는 서비스 목적과 아동 안전 원칙에 맞지 않는다. 자체 풍경·캐릭터와 명명된 기능 입구로 시각 분위기만 재해석한다.
- 수정 후 6개 관점 재판정: P2-01·P2-02 수정안을 설계에 포함해 여섯 관점 모두 통과.
- 착수 판정·시점: 2026-10-30, 여섯 관점 모두 통과하고 미해결 P0·P1 없음. 구현 착수 가능.
- 남긴 P2·P3의 처리 계획: P2-01·P2-02는 구현 중 처리하고 실제 브라우저에서 확인한다. 실제 아동 사용성은 별도 시범 운영에서 확인한다.
