# 전문가 검토 기록: 학생 카드 재출력과 시즌 설정

## 검토 정보

- 날짜/대상: 2026-09-27, `main`의 교사 카드·회차 화면과 Firebase 카드/회차 계약.
- 수행 방식: Codex 한 에이전트가 여섯 가상 프로파일을 각각 적용. 외부 사람 여섯 명의 자문이나 승인이 아니다.
- 입력 자료: 사용자 스크린샷 두 장과 요구사항, `web/src/main.tsx`, `web/src/TeacherRounds.tsx`, 카드/회차 Functions, `docs/experts/` 운영 지침·프로파일, 개발 계획서·데이터·함수 계약.

## 사용자·문제·설계

- 사용자: 학급을 개설해 4~40명에게 입장 카드를 배부하고 시즌을 시작하는 교사. 공용기기에서 학생을 전환하는 학급.
- 현행 문제: 최초 발급/재발급 직후에만 코드가 응답으로 오며 화면을 다시 열면 사라진다. 학생 목록은 인쇄 가능 여부에 따라 조작이 달라지고, 재발급·확인·인쇄 버튼이 한 줄에 몰린다. `회차`와 시각 입력은 교사의 시즌/일자 과업과 맞지 않는다.
- 정보 구조: 운영 요약 → **시즌 설정** → 학생·입장 카드 → 안전 확인 → 지난 활동 → 학급 설정. 시즌에는 주제·시작/종료일, 참가자/제외, 미션/쪽지, 확인/저장의 기존 네 단계를 둔다. 학생 카드에서는 학급 코드와 함께 **전체 출력·선택 출력**, 학생별 선택·입장 차단/해제·재발급을 한곳에서 제공한다.
- 카드 보안/복구: 새 발급 카드 원문은 서버에서 AES-GCM으로 암호화해 서버 전용 자격 문서에 저장한다. 키는 Firebase Secret Manager에 두고 관련 Functions에만 바인딩한다. 교사 소유권을 확인한 Callable에서만 복호화·출력 응답을 허용하며 열람 감사 기록을 남긴다. 브라우저 저장소·URL·로그에는 원문을 두지 않고 화면 전환/숨김 때 메모리의 인쇄용 값을 정리한다. 기존 카드의 원문은 복원할 수 없으므로 필요한 카드에 한해 **기존 카드가 무효화됨을 알리는 확인 뒤 재발급**하고 즉시 인쇄한다. 재발급은 학생 세션 버전을 올린다.
- 카드 상태: 목록은 기본적으로 이름·번호·입장 상태·선택 체크만 보여준다. 카드가 출력 가능한지/재발급이 필요한지 텍스트로 표시한다. 전체 출력은 입장 가능한 전체 학생, 선택 출력은 체크한 학생만 대상으로 한다. 출력 대상에 기존 카드가 있으면 확인 창에서 영향·대상 수를 알리고 재발급 후 이어서 출력한다. 빈 선택은 출력하지 않는다. 재발급은 해당 학생의 확인 창 → 서버 성공 → 바로 한 장 인쇄 순서다. 실패 시 기존 카드 상태와 선택은 유지하고 재시도 안내를 보인다.
- 시즌 날짜: 새 시즌 시작일은 한국 시간의 오늘, 종료일 기본값은 시작일부터 5일째(시작일 포함)다. 5/10/15/20일 버튼은 종료일을 시작일 포함 해당 일수로 정하고 기간 안의 월~금 수업일을 자동 선택한다. 교사는 시작·종료일 및 수업일을 조정할 수 있다. 서버에는 시작일 00:00, 종료일 23:59:59.999(KST)의 ISO 시각을 보내 기존 서버 시간 검사를 유지한다. 미션 세 개를 진행할 수 있도록 수업일은 3~20개, 전체 기간은 기존 상한 30일이다. 부족한 수업일은 기간·학교 일정을 조정하도록 오류를 보여준다.
- 반응형/키보드: 카드 도구 모음과 학생 목록은 1280px 2열, 768px 이하 1열로 재배치한다. 학생 선택은 행 전체 라벨, 버튼은 별도 조작 영역이다. 360·390·768·1280px에서 40명/긴 이름·카드 A4 다중 인쇄, Tab/Space/Enter·초점·오류·로딩을 검증한다.

## 구현 후 실제 검증

- 검증 환경: `demo-manitto` 격리/개발 에뮬레이터, 가상 교사 1명·가상 학급 23→40명과 긴 가상 이름 1명. Chrome 1280·768·390·360px, `agent-browser` 조작과 Chrome 인쇄 엔진. 실제 학생 이름·카드 데이터는 사용하지 않았다.
- 카드 과업: 이름 옆 선택 체크로 2장만 출력, 새 카드 재조회, 구 카드 1장과 새 카드 1장의 선택 출력에서 사전 영향 안내→구 카드만 재발급→2장 출력, 이름 옆 재발급→1장 출력, 전체 23장·40장 출력을 확인했다. `Page.printToPDF(preferCSSPageSize:true)` 결과는 각각 A4 23·40쪽이며 인쇄 후 비밀 코드 DOM이 0개였다. 인쇄 완료 이벤트가 누락될 때를 대비해 2분 후 메모리/DOM 정리도 추가했다(실제 브라우저 대기 시간 만료는 미확인). 다른 교사 호출과 학생의 자격 문서 직접 읽기는 거부되고, 구 카드는 재발급 뒤 로그인 거부됨을 통합 테스트에서 확인했다. 기존 카드 암호문이 없는 40명 전체를 일괄 재발급해 다시 40장을 조회하는 에뮬레이터 경로도 통과했다.
- 시즌 과업: 메뉴 순서 `운영 요약 → 시즌 설정`, 한국 날짜 2026-09-27 시작·10-01 종료 기본값, 5·10·15·20일 빠른 선택의 종료일 10-01·10-06·10-11·10-16과 월~금 4·7·10·15개를 실제 클릭으로 확인했다. 23명 가상 시즌의 날짜·미션·명단을 저장하고 재진입했을 때 날짜가 유지됐다. 서버 값은 시작 `2026-09-26T15:00:00.000Z`, 종료 `2026-10-01T14:59:59.999Z`여서 각각 한국 날짜의 00:00과 23:59:59.999다. 20일 시즌의 10개 초과 수업일은 통합 테스트에서 저장·매칭했고, 미래 시작일 전의 조기 시작은 거절됐다.
- 반응형/접근성: 카드 목록은 1280px 2열, 768·390·360px 1열이었다. 40명과 긴 이름에서 문서 폭이 화면 폭과 같고 이름·버튼 겹침은 없었다. 카드 선택은 Space, 다음 재발급 버튼은 Tab으로 이동하고 `:focus-visible`이 적용됐다. 재발급·차단 버튼의 측정 높이는 44px이다. 시즌 모바일 390px의 문서 폭도 390px이고, 실제 화면 확인 중 발견한 날짜 추가 버튼 과도한 높이는 48px로 보정했다. 브라우저 페이지 오류는 없었다.
- 자동 검증: TypeScript·Vite 전체 빌드, 함수 단위 10건, Firestore Rules 11건, 통합 3건 통과. 선택 출력·구 카드 이행·40명 인쇄는 실제 브라우저에서 추가 확인했다. 대량 이행·감사 대상 기록·미래 시작일 거부는 통합 테스트에서 확인했다.
