# 6인 전문가 검토 기록: 학생 일괄 등록 API 파라미터 불일치 결함 수정

- **일자**: 2026-09-30
- **대상 기능**: 시즌 설정 및 카드 관리 화면의 학생 일괄 등록(`registerBatchStudents`) 파라미터 매핑 및 최신 명단 동기화
- **관련 파일**: `web/src/main.tsx`

---

## 1. 개요 및 요구사항

### 현황 및 문제점
- 사용자가 시즌 설정 2단계에서 '텍스트 직접 붙여넣기'로 이름을 추출한 뒤 `[학생 23명 등록하고 카드 만들기]` 버튼을 눌렀으나, 학생 이름이 저장되지 않고 다음 단계로 넘어가지 못하는 결함 발생.
- **원인 분석**:
  - 백엔드 `registerStudents` Callable 함수는 `displayNames` (배열)를 요구하지만, 프런트엔드 `registerBatchStudents`에서 `names` 키로 잘못 전송하여 백엔드 인자 검증(`invalid-argument: 학생은 한 번에 1명 이상 40명 이하로 등록해 주세요.`)에서 실패함.
  - 반환값 구조(`result.students`) 불일치 및 등록 완료 후 `selectClass`를 통한 Firestore 최신 명단(`members`) 재로드가 누락되어 부모-자식 컴포넌트 간 명단이 갱신되지 못함.

### 사용자 과업
- 교사가 텍스트 붙여넣기나 파일 업로드 후 등록 버튼을 누르면, 백엔드에 즉시 23명의 학생이 등록되고 최신 명단이 반영되어 시즌 설정 2단계의 참가자 및 제외 관계 설정 화면으로 자동 전환된다.

## 2. 6개 전문가 관점 개별 검토

### WD-01 · 시각 구성과 브랜드
- **판단**: 승인
- **근거**: 등록 성공 즉시 Zero-State(명단 등록기)에서 Active-State(참가자 체크박스 그리드 및 제외 관계 셀렉트박스)로 자연스럽게 화면 상태가 전이되며, 상단에 성공 알림 메시지가 표시되어 브랜드 신뢰도를 확보함.

### WD-02 · 반응형 레이아웃과 타이포그래피
- **판단**: 승인
- **근거**: 23명의 학생이 등록되었을 때 참가자 그리드가 화면 너비에 맞추어 2열~4열로 반응형 정렬됨.

### UX-01 · 정보 구조와 과업 흐름
- **판단**: 승인
- **근거**: 등록 완료 후 `await selectClass(selected.classId, teacherPage, false)`를 통해 최신 학생 목록을 즉시 fetch하여, 교사가 새로고침을 하거나 다른 메뉴로 나갔다 올 필요 없이 그 자리에서 바로 다음 단계(제외 관계 설정)로 직진할 수 있음.

### UX-02 · 인지 부담과 사용자 이해
- **판단**: 승인
- **근거**: 등록 버튼 클릭 시 "23명의 학생을 등록하고 4자리 카드를 만들었어요." 알림 피드백을 제공하여 교사에게 성공 여부를 확신시킴.

### UI-01 · 조작과 컴포넌트 상태
- **판단**: 승인
- **근거**:
  - `task` 래퍼를 통해 등록 중에는 버튼 `busy` 상태 및 스피너가 유지되어 중복 클릭을 방지함.
  - 파라미터를 백엔드 스펙(`displayNames: names`)과 일치시켜 400 에러를 원천 차단함.
  - 학급 최대 인원(40명) 초과 여부를 클라이언트 단에서 1차 검사하여 친절한 에러 안내 제공.

### UI-02 · 접근성과 화면 품질
- **판단**: 승인
- **근거**: 스크린리더를 통해 상태 변경 알림이 낭독되며, 포커스가 등록된 참가자 영역으로 매끄럽게 연결됨.
