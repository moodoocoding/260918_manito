# 전문가 검토 기록: 마니또 회차와 독립된 게시판 진입 통합

## 요구·원인·설계

- 2026-10-30 실제 사용자에게 자리바꾸기 질문이 나타나지 않는 문제를 게시판 담당이 조사했다. 새 API가 마니또 회차 active/미만료를 강제한 것이 근본원인으로 확인돼 학급별 독립기능으로 보강한다. 기존마니또 회차/기록·학급·카드는 그대로 보존한다.
- 이 문서는 `/root` 한 에이전트의 여섯 가상역할 최소 통합검토다. 전문가운영지침/여섯프로파일과 게시판담당의 `2026-10-30-balance-game-missing-questions.md`, 기존공통디자인검토를 입력으로 삼는다. 외부전문가 검증이 아니다.
- 부모범위는 main.tsx의 학생 community 진입조건과 바깥프레임fallback뿐이다. class-level API/Rules/문서/명부/홀수제출조건과 StudentCommunity/BalanceGame 구현은 게시판담당이 담당한다. 교사화면·인증은 별도 선생님방 채팅이 담당한다.
- 학생은 마을→게시판→자리바꾸기로 진입한다. 마니또 회차가없거나종료돼도 게시판/질문탐색은 제공한다. 실제제출가능성과전체제출/짝생성조건은 서버권한/독립상태에따라 안내한다. 마니또용 교사안내가 회차를필요로하면 해당내용만빈상태로구분하며 게시판전체를막지않는다.
- 자식은 기존 onBack/onExit/classLabel과 optional roundId 계약을 제공할예정이다. 부모는 회차없는경우의 별도헤더/프레임fallback을 제거해 항상 자식공통프레임 하나만 표시한다. 이름/명부/응답을 URL이나 전역저장소에추가하지 않는다. 최종props확인뒤구현한다.
- 반응형/과업/상태: 기존 교실배경/나무프레임/양피지/단일제목을 유지한다. 게시판 로딩/안내/자리바꾸기 진입과 질문/오류/제출불가를분리한다. 실제가상회차없음/종료/진행조건에서 중복제목과진입/복귀,320/390/768/1280을 확인한다. 운영학생의선택/제출이나유료AI호출은부모검증에서수행하지 않는다.

## 통합진행

- 최종 optional roundId 계약을 실제 StudentCommunity 소스에서 확인했다. roundId가없으면 getStudentCommunity를 호출하지않고 기본안내와자리바꾸기진입을표시하며, BalanceGame에는roundId를전달하지않는다.
- main.tsx에서 community항상렌더와 legacyStudentContexts만사용하도록두곳을수정했다. 마을/종료callback과classLabel을유지하고 roundId변경에따른강제key리마운트를없앴다. 다른교사/학생/인증분기는수정하지않았다.
- 웹 TypeScript/Vite빌드·world/teacher-mailbox preview strict tsc·diff검사통과. 기존큰청크경고유지.
- 이후학급독립3함수선택배포와5173/5175고정화면갱신이완료됐다. 서버/권한의정확한배포·테스트범위는게시판담당검토와작업일지를따른다.
