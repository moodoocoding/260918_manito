# 전문가 검토 기록: 2D 학급 공간 메인 화면

## 검토 정보

- 날짜 / 대상 설계 버전 또는 커밋: 2026-10-30 / 학급 공간 메인 화면 초안
- 요청과 변경 범위 / 범위 밖 항목: 학생 로그인 뒤 첫 화면을 탐색형 2D 학급 공간으로 바꾸고, 미션·우편함·우리 반·오늘 활동으로 이동하는 입구를 제공한다. 교사 화면, 백엔드·데이터 계약, 실제 캐릭터 에셋 제작은 범위 밖이다.
- 수행 주체·방식: Codex 한 에이전트가 여섯 가상 프로파일의 역할 기준을 각각 적용해 요구사항·현재 학생 홈 코드와 기존 검토 지침을 바탕으로 사전 검토했다. 외부 전문가 자문은 없었다.
- 입력 자료: `AGENTS.md`, `docs/experts/README.md`, 6개 프로파일, `web/src/main.tsx`, `web/src/style.css`, `web/src/StudentCommunity.tsx`, `docs/design-revision-plan.md`, `docs/work-log.md`
- 검토 단계: 사전 설계

## 사용자와 설계안

- 대상 사용자·이용 환경·핵심 과업: 1~6학년 학생이 공용 교실 기기와 개인 기기에서 입장 후 학급 공간을 이해하고, 오늘 활동·미션·우편함·우리 반 소식을 찾으며, 교사 도움과 로그아웃에 접근한다.
- 현재 문제와 재현 조건: 현재 학생 메인은 홈/미션/우편함/우리 반의 텍스트 탐색 바와 홈 카드다. 사용자가 새 서비스 전체를 학급 공간으로 만들고, 이동 캐릭터를 통해 장소별 기능에 들어가고 싶다고 명시했다. 이는 사용자 요구다.
- 페이지·섹션 구성과 이동 경로:
  - 학생 메인 `/student`: 얇은 학급 문맥 헤더 → 2D 교실/마당 장면 → 접근 가능한 장소 버튼(오늘 할 일, 미션, 우편함, 우리 반) → 키보드·화면 버튼 이동 안내.
  - 오늘 할 일은 현재 홈의 `StudentRound view="home"`를 장면 아래에서 열고 닫는다. 미션·우편함·우리 반은 기존 하위 화면으로 이동한다. 도움과 활동 마치기는 상단 공통 헤더에 남긴다.
  - 내부 화면은 기존 상단 메뉴를 유지하고 ‘홈’으로 공간에 복귀한다.
- 각 화면의 목적·주요 행동·저장 범위: 공간은 탐색·진입 허브이며 자체 데이터 저장은 없다. 기존 기능의 API 호출 및 저장 범위는 바꾸지 않는다.
- 기본·빈 상태·로딩·오류·완료와 취소·복귀: 기존 인증 로딩 및 전역 오류 유지. 회차가 없어도 지도가 유지되고 오늘 활동 영역에서 다음 활동 준비 안내와 지난 활동 경로를 제공한다. 장소 진입은 기존 화면 전환이며 홈으로 복귀할 수 있다.
- 반응형·긴 텍스트·최대 항목·키보드 설계: 큰 화면에서 넓은 장면과 2열 장소 영역, 작은 화면에서 장면·장소를 세로 재배치한다. 장소는 장식 그림과 별개로 이름이 붙은 48px 이상 버튼/링크다. 화살표/WASD와 화면 방향 버튼으로 캐릭터 이동, Tab/Enter로 모든 장소에 접근한다. 색상 이외에 아이콘과 텍스트로 목적을 전달한다.

| UI-01 · 조작·상태 | 장소는 명확한 링크/버튼이며 키보드와 방향 버튼은 캐릭터 이동만 수행한다. 장면 안을 클릭하는 것만으로 데이터 작업을 실행하지 않는다. 오늘 활동 확장에는 열림 상태가 표시된다. | 없음 | 통과 |
| UI-02 · 접근성·품질 | 의미 있는 제목·랜드마크, 보이는 초점, 텍스트가 포함된 장소 이름을 제공한다. 이동에 키보드 단축키와 터치 방향 버튼을 모두 두고 reduced-motion 설정을 지원한다. 실제 화면·키보드 검증은 구현 후 진행한다. | 없음 | 통과 |

## 발견 사항과 조치

| ID · 심각도 | 위치·발생 조건·문제 | 휴리스틱/근거·사용자 영향 | 수정안 | 담당 역할·처리 시점 | 확인 방법·결과 |
|---|---|---|---|---|---|
| P2-01 | 학생 메인에서 지도 움직임만으로 목적지를 찾아야 한다면 초심자·키보드·터치 사용자에게 진입이 어렵다. | H6·H7, 아동 사용자는 장면 탐색을 기능 진입의 필수 절차로 오해할 수 있다. | 명명된 장소 버튼을 항상 보이게 하고 직접 열기를 지원한다. 키보드/터치 이동은 보조 경로로 둔다. | UX-01/UI-01, 구현 전 설계 반영 | 각 장소를 탭과 키보드로 바로 실행하는 시나리오로 확인 예정 |
| P2-02 | 오늘 할 일의 기존 완료 동작이 사라지면 핵심 미션 흐름이 끊긴다. | H3·H7, 학생이 미션을 완료할 수 없거나 과업을 못 찾을 수 있다. | 현재 `StudentRound view="home"`를 오늘 활동 장소 안에서 제공한다. | UX-01, 구현 중 | 기존 완료·쉬기·도움 상태가 유지되는지 코드 경로 확인 |
| P2-03 | 작은 화면의 큰 장면이 첫 화면을 차지하면 장소를 찾기 위해 스크롤이 길어질 수 있다. | H8 및 모바일 첫 화면 기준, 주요 진입이 과도한 장식 아래로 밀릴 수 있다. | 장면 높이를 뷰포트 폭에 맞춰 제한하고 모바일에서 간결하게 재배치한다. | WD-02, 구현 중 | 390px 및 360px 화면 렌더 확인 |

- 의견 차이와 선택 이유: 이동형 공간의 몰입감을 위해 장소를 장면 안에 배치하되, 모든 장소는 일반 버튼으로도 직접 선택 가능하게 한다. 이동만 강제하면 어린 학생과 키보드/접근성 사용자에게 불필요한 장벽이 되기 때문이다.
- 수정 후 6개 관점 재판정: 위 P2-01~03 수정안을 설계에 포함해 여섯 관점 모두 통과.
- 착수 판정·시점: 2026-10-30, 6개 관점 모두 통과하고 미해결 P0·P1 없음. 구현 착수 가능.
- 남긴 P2·P3의 처리 계획: P2-01~03을 현재 변경 범위에서 구현하고 실제 브라우저 확인한다. 실제 학생 사용성은 별도 현장 확인 대상이다.
