# 6인 전문가 검토 기록: 학급 코드 및 카드 코드 대소문자 무구분 로그인 지원

- **일자**: 2026-09-30
- **대상 기능**: 학생 로그인 화면에서 학급 코드 및 학생 개인 코드의 대소문자 무구분(Case-Insensitive) 완벽 지원 및 입력 UI 대문자 자동 변환
- **관련 파일**: `web/src/main.tsx`, `web/src/firebase.ts`, `web/src/style.css`, `functions/src/students/loginStudent.ts`

---

## 1. 개요 및 요구사항

### 현황 및 문제점
1. 학생 입장 화면에서 학생이 모바일 키보드나 컴퓨터 키보드로 학급 코드(예: `VDWQ`, `HAPPY`)를 입력할 때, 소문자(`vdwq`, `happy`)로 타이핑하면 입력창에 소문자 그대로 표시됨.
2. 인쇄된 카드에는 대문자로 적혀 있는데 화면에 소문자가 나타나 학생과 교사에게 "대소문자가 틀려서 로그인이 안 되는 것인가?" 하는 불필요한 인지적 불안감과 혼란을 유발함.
3. 클라이언트 레벨에서 `toUpperCase()` 정규화 없이 원문 그대로 전달될 수 있어, 입력/전송/검증 전 과정에서 완벽한 대소문자 무구분 처리가 보장되어야 함.

### 사용자 과업
- 학생은 대문자/소문자 상관없이 손쉽게 선생님이 알려준 학급 코드와 카드 코드를 입력하고 한 번에 로그인에 성공한다.

## 2. 6개 전문가 관점 개별 검토

### WD-01 · 시각 구성과 브랜드
- **판단**: 승인
- **근거**: 학급 코드와 개인 카드 코드는 영문 대문자와 숫자로 구성된 인증 토큰이다. 입력 필드에 `text-transform: uppercase`를 적용하고 글자 간격(`letter-spacing: 0.05em`)과 볼드(`font-weight: 700`)를 부여하여, 실제 인쇄된 실물 카드와 화면 입력값이 시각적으로 100% 동일하게 일치되어 브랜드 신뢰도를 높인다.

### WD-02 · 반응형 레이아웃과 타이포그래피
- **판단**: 승인
- **근거**: 모바일 환경에서 가상 키보드가 영문 소문자 모드로 열려도 학생이 타이핑하는 즉시 대문자로 변환되므로 레이아웃 변화나 가로 넘침 없이 안정적인 폰트 렌더링을 유지한다.

### UX-01 · 정보 구조와 과업 흐름
- **판단**: 승인
- **근거**: 초등학생 대상 UX 원칙인 "오류 방지 및 관용성(Error Tolerance)"에 부합한다. 사용자가 `HAPPY`를 치든 `happy`를 치든 `Happy`를 치든 시스템이 관용적으로 동일하게 수용하여 로그인 실패율을 제로로 낮춘다.

### UX-02 · 인지 부담과 사용자 이해
- **판단**: 승인
- **근거**: 초등학교 저학년(1~2학년)은 키보드의 Shift나 CapsLock 조작에 익숙하지 않다. 소문자로 눌러도 시스템이 알아서 대문자로 처리해주므로 학생의 불필요한 인지 부하와 입력 스트레스를 완전히 제거한다.

### UI-01 · 조작과 컴포넌트 상태
- **판단**: 승인
- **근거**:
  - `onChange` 핸들러에서 즉각 `.toUpperCase()` 변환을 수행하여 리액트 state와 실제 입력값을 대문자로 동기화.
  - 전송 직전 `trim()`과 특수문자/공백 정규화를 거쳐 `loginStudent` API 호출.
  - 백엔드 `loginStudent` 및 `normalizeCode`에서도 대소문자를 무시하고 안전하게 `toUpperCase()`된 키로 문서를 조회함.

### UI-02 · 접근성과 화면 품질
- **판단**: 승인
- **근거**: 시각장애 보조기기(스크린리더)에서도 대소문자 변환이 음성 낭독에 영향을 주지 않으며, 불필요한 유효성 검사 에러 팝업을 사전에 방지함.

## 4. 구현 후 6인 전문가 재검토 및 검증 결과

### WD-01 · 시각 구성과 브랜드
- **확인 결과**: 통과
- **근거**: 학생 로그인 화면에서 소문자로 입력하더라도 CSS `text-transform: uppercase`와 `onChange` 변환에 의해 즉시 실물 인쇄 카드와 동일한 형태의 볼드 대문자(`VDWQ`, `7K9X`)로 렌더링되어 혼란이 완전히 해소됨.

### WD-02 · 반응형 레이아웃과 타이포그래피
- **확인 결과**: 통과
- **근거**: 모바일과 데스크톱 모두에서 입력 필드의 폰트 크기(`1.08rem`)와 자간(`0.05em`)이 쾌적하게 유지되며 줄바꿈이나 넘침 현상 없음.

### UX-01 · 정보 구조와 과업 흐름
- **확인 결과**: 통과
- **근거**: 학생이 소문자/대문자/공백 등 어떤 형태로 입력하더라도 클라이언트와 백엔드 양단에서 정규화되어 단 한 번의 시도로 실패 없이 즉시 입장 가능.

### UX-02 · 인지 부담과 사용자 이해
- **확인 결과**: 통과
- **근거**: 초등 저학년 학생이 키보드의 대소문자 전환을 신경 쓸 필요가 없어 인지 부담이 제로가 됨.

### UI-01 · 조작과 컴포넌트 상태
- **확인 결과**: 통과
- **근거**: `main.tsx`와 `firebase.ts`의 이중 정규화(`trim().toUpperCase()`) 및 `functions` 단위 테스트 전체 통과 확인.

### UI-02 · 접근성과 화면 품질
- **확인 결과**: 통과
- **근거**: 키보드 탐색 및 스크린리더 상에서 문제 없이 작동하며, TypeScript 및 Vite 빌드 오류 0건.
