# 우리 반 게시판 · 자리바꾸기 사전 설계 검토

## 검토 정보

- 날짜 / 대상 설계 버전: 2026-10-30 / 자리바꾸기 v1 사전 설계
- 요청과 변경 범위: 우리 반 게시판에 10개 밸런스 질문 응답, 제출 완료 학생 이름의 실시간 공개, 전원 제출 후 AI 기반 짝 생성. 좌석표 편집, 평가·순위·보상, 교사별 운영도구는 제외.
- 수행 주체·방식: Codex 한 명이 6개 가상 프로파일별로 개별 판단했다. 외부 전문가 참여 없음.
- 입력 자료: `AGENTS.md`, 개발 계획 v2.3, 작업일지, Firestore·Functions 계약, 6개 프로파일과 검토 양식, `docs/design-revision-plan.md`, 첨부 PDF/PPTX, `StudentCommunity.tsx`, `main.tsx`, `preview/world.tsx`, 현재 월드 화면.
- 검토 단계: 사전 설계

## 사용자와 설계안

- 대상·환경·핵심 과업: 1~6학년 학생이 공용 교실 기기로 게시판에 접근해 질문 10개의 A/B 중 하나를 선택하고 제출한다. 교사는 기존 회차 명단·활동 상태를 관리한다.
- 현재 문제와 재현 조건: 게시판에는 교사 안내와 배려 예시만 있고 자리바꾸기 화면·응답·완료 상태가 없다(코드 관찰).
- 참고 자료: 첨부 PDF는 A/B 중 하나를 선택하는 질문 10개를 한 장 표로 제시한다. PPTX는 소개·선택 규칙·한 질문씩 제시하는 카드·짝 정하기 순서(왼쪽으로 줄을 서서 인접 학생과 짝)를 담은 14장 이미지 슬라이드다. 일부 원문은 외모·돈·연애 관련 주제라 아동 안전 정책과 맞지 않아 학교 일상 질문으로 대체한다.
- 페이지·영역: 우리 반 게시판 → `자리바꾸기` 전용 과업 화면. ① 활동 설명/진행 상태, ② 한 질문씩 선택 입력, ③ 제출 전 자기 선택 확인, ④ 제출 완료와 같은 학급의 완료 이름 목록, ⑤ 전원 완료 뒤 개인별 본인 짝 확인.
- 주요 행동·저장 범위: 학생은 A/B 라디오 선택과 제출만 한다. 질문 응답 및 짝 관계는 서버 전용. 별도의 안전한 공개 문서는 `완료한 학생 이름`과 완료/참가 인원, 단계만 실시간 제공한다. 결과는 각 학생이 자기 짝만 확인한다.
- 상태와 복귀: 준비·질문 이동·제출 중·제출 완료·다른 학생 입력 대기·매칭 중·결과 준비·오류/재시도를 다룬다. 제출 후 응답은 바꿀 수 없음을 저장 전에 알리고 본인 응답을 재확인하게 한다. 중복 제출은 멱등 처리한다.
- 정책: 모든 참가자의 선택 완료 전 모델 호출·결과 공개 금지. 홀수 참가자는 어떤 학생도 제외하지 않도록 짝 생성 전 안내 오류로 막고 명단 수 조정을 교사에게 요청한다. 질문은 학교에서 안전한 취향 선택으로 구성한다. AI에는 표시 이름 대신 회차 한정 임의 ID와 A/B 선택만 보낸다. AI가 생성한 짝은 참여자 전체의 단일 매칭으로 검증하고 결과는 공개 순위/관계 평가로 표현하지 않는다.
- 반응형·접근성: 질문 한 장씩 표시하고 A/B 선택은 실제 라디오 입력과 연결된 넓은 카드로 제공한다. 320~1280px 재배치, 긴 이름, 키보드 선택·제출, 초점, 로딩/오류 안내를 확인한다.

## 발견 사항과 조치

| ID · 심각도 | 위치·문제 | 근거·사용자 영향 | 수정안 | 담당·시점 | 확인 방법 |
|---|---|---|---|---|---|
| D1 · P2 | 첨부의 일부 질문이 돈·외모·연애를 소재로 함 | 아동의 가정 형편·관계 선호를 드러내거나 놀림을 부를 수 있음 | 해당 질문을 음식/수업/놀이/교실 취향으로 교체. 점수·진단 목적이 아님을 안내 | UX·구현 전 | 질문 문구 검토·UI 확인 |
| D2 · P2 | 참가자가 홀수면 두 명씩 짝을 전부 만들 수 없음 | 누구를 제외하면 소외감을 낳을 수 있음 | 자동 제외·삼인조 대신 입력·매칭을 막고 교사에게 명단 조정을 안내 | UX·구현 | 홀수 서버 데이터 시나리오 |

- 의견 차이: PPTX의 인접 줄서기 방식은 AI가 선택 유사도가 높은 짝을 만들라는 새 요구와 다르다. 제공 자료의 입력 방식·질문은 참고하되, 짝 배정은 사용자 요구의 AI 방식으로 바꾼다.
- 수정 후 사전 판정: 위 D1·D2를 설계에 반영했고 6개 관점 모두 통과. 미해결 P0·P1 없음.
- 착수 판정: 통과. 실제 브라우저 시험은 구현 후에 수행한다.
- 남은 P2/P3: 홀수 명단을 바꿀 교사 화면은 현재 요구 범위 밖이다. 학생은 교사에게 명단 확인을 요청하고 교사는 기존 학급/회차 관리 기능으로 정정한다. 완성 전에 안내 문구와 실패 복귀를 확인한다.

## 사용자 제공 ‘오늘 할 일’ 시안 반영 사전 재검토

- 추가 자료: 사용자가 2026-10-30에 제시한 픽셀 교실 화면 시안. 나무 프레임, 크림색 종이 패널, 진초록 실행 버튼과 완료 아이콘을 확인했다.
- 변경: 자리바꾸기 기능과 순서는 유지하고 같은 시각 언어를 카드 테두리·선택 상태·주요 실행 버튼에 적용한다. 기존 A/B 라디오 조작과 문구는 보존한다.
- WD-01: 크림 패널과 각진 초록 테두리가 도트 마을과 사용자의 시안에 맞고, 선택 카드는 녹색 채움+테두리로 구별한다. 색 외에 체크된 라디오와 굵은 선택지 글자도 보인다. 통과.
- WD-02: 320/390 화면에서 폭을 넘지 않고 선택지는 한 열로 쌓인다. 긴 문구도 줄바꿈한다. 통과.
- UX-01: 커뮤니티와 별도 과업을 분리한 채 보기·선택·제출·대기·결과 순서는 유지한다. 통과.
- UX-02: 핵심 질문·선택·다음 단계가 패널 경계와 초록 버튼으로 읽히며, 점수/평가 의미를 덧붙이지 않는다. 통과.
- UI-01: 기존 실제 라디오, 비활성/활성 이전·다음, 제출 CTA 역할은 보존한다. 색 적용만으로 상태를 구분하지 않는다. 통과.
- UI-02: 작은 화면 첫 질문의 CTA를 확인했고, 키보드 라디오 방향키 선택과 선택 초점 테두리를 실제 브라우저에서 확인했다. 초록 계열 외곽선과 라디오 선택 표시를 같이 유지한다. 통과.
- 발견/착수: P0·P1 없음. 시각 스타일 적용 착수 가능.

- 데스크톱 재검토 관찰(1280px): 900px 미리보기 패널 안에서 자리바꾸기 본문이 intrinsic width 약 463px로 줄어 좌우 공백이 과도했다. P2: 넓은 화면 선택지 비교와 이름 목록의 공간을 줄인다. 수정 전에 사전 재검토 결과: WD-01은 같은 픽셀 프레임 안에서 최대 820px까지 본문을 넓혀 밀도를 맞추는 데 동의; WD-02는 모바일에서 100% 폭/데스크톱 max-width로 대응하면 줄바꿈과 열 수가 안정됨; UX-01은 정보 위계 변경 없이 같은 과업 영역만 확장; UX-02는 여백을 줄여 질문/선택/다음 행동을 한눈에 유지; UI-01은 라디오/CTA 배치 관계 보존; UI-02는 1280px viewport에서 양쪽 여백과 페이지 넘침을 확인. 모두 수정 방향 통과, P0·P1 없음.
