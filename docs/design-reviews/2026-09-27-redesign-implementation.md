# 디자인 수정 R1~R4 · 구현 후 6개 관점 검토

- 날짜: 2026-09-27. 대상: `docs/design-revision-plan.md` v1.0과 `2026-09-27-redesign-r0.md`의 사전 설계.
- 수행: Codex 한 에이전트가 6개 가상 프로파일을 각각 적용했다. 외부 전문가·교사·학생의 실제 자문이나 사용성 시험은 아니다.
- 환경: `demo-manitto` 로컬 에뮬레이터의 가상 교사, 40명 가상 학급, 학생 카드 1장. 브라우저 기본 폭 1280 CSS px의 교사 화면과 학생 인증 후 화면을 조작했다. 시험용 학급·계정은 함수로 삭제해 학급 문서 부재를 확인했다.

## 구현 결과와 실제 조작

| 범위 | 확인한 결과 | 한계 |
|---|---|---|
| 교사 정보 구조 | 학급 선택 직후 운영 요약에 도움 1건·대기 쪽지 0건, 참가자 40명, 일정을 표시했다. 학생·카드/회차/안전/지난 활동/설정 메뉴가 분리됐다. | 390px 모바일 메뉴 실측 미확인 |
| 40명 참가자 선택 | 문장 클릭이 해당 체크만 바꾸고 40→39명으로 집계됐다. 같은 체크에 Space를 눌러 상태가 다시 바뀌었다. | 23명·200% 확대·VoiceOver 미확인 |
| 체크박스 배치 | 최초 변경 후 실제 화면에서 기존 `.stack label`이 새 선택 행을 덮어 체크박스가 문장 위에 남는 것을 발견했다. `.teacher-page-form label.choice-row` 우선순위를 수정한 뒤 같은 1280px 화면에서 체크박스가 문장 첫 줄 앞에 놓인 것을 확인했다. | 320·360·390·768px는 도구가 폭을 바꾸지 못해 실측 미확인 |
| 회차 준비 | 기본 정보→40명 참가자→미션 3개→최종 확인으로 이동했다. 3개 선택 시 다른 미션 선택이 비활성화됐다. `다음`을 눌렀을 때 초안이 뜻밖에 저장되는 결함을 발견해 기본 클릭 제출을 막았다. 재시도에서 최종 단계는 `아직 저장 전`이며 별도 `준비 내용 저장` 버튼이 활성화된 상태로 남았다. | 미저장 이탈 native 확인창은 자동화 브라우저가 대화상자에서 멈춰 취소·승인 결과 미확인. 수동 브라우저 검증 필요 |
| 학생 흐름 | 카드 로그인 후 오늘에 가린 친구와 미션 1개를 먼저 표시했다. 우편함에서 선택형 쪽지 1건을 보내자 `전달됨`과 당일 재전송 불가가 표시됐다. 도움 요청 뒤 `선생님 확인 중` 상태를 봤고, 로그아웃 및 뒤로가기에서 학생 정보가 사라졌다. | 공개·보관 후 재진입 가림, 저학년 선택형 회고의 브라우저 조작 미확인. 서버 통합 테스트에는 해당 데이터 계약을 포함했다. |
| 안전·요약 데이터 | `summaryOnly:true` 함수 응답은 도움·쪽지 건수와 참가 수·일정만 내리고 원문·이름을 반환하지 않는다. 다른 교사 거절을 통합 테스트로 확인했다. 안전 페이지의 원문은 개별 열기·닫기와 탭 이탈 시 닫기로 구현했다. 변경 함수 3개는 개발 Firebase에 업데이트했다. | 변경된 안전 페이지와 클라우드의 새 응답을 인증 브라우저에서 직접 재검증하지 못했다. |
| 자동 검사 | 전체 TypeScript 빌드, 함수 단위 10건, Firestore Rules 11건, 가상 학급 두 회차·40명 포함 통합 3건 통과. `git diff --check` 통과. | 자동 검사는 메뉴 이해·시각 품질·보조기기 동작을 증명하지 않는다. |

브라우저의 화면 폭 변경 기능은 390px을 지정한 뒤에도 실제 `innerWidth`가 IAB 1280px, Chrome 1512px로 남았다. 별도 `agent-browser` CLI도 버전 조회는 됐으나 로컬 페이지 열기와 진단에서 응답하지 않았다. 이 시도를 모바일 검증 통과로 계산하지 않는다.

추가로 격리된 headless Chrome의 기기 지표를 직접 320·390·768px로 고정해 **로그인 전 학생 입장 화면**을 캡처했다. 각 폭에서 실제 `innerWidth`와 문서 폭이 같고 넘치는 요소가 없음을 확인했다. 첫 빠른 캡처의 글자 잘림은 렌더링 완료 전 상태였으며, 완료 후 재촬영에서는 문장이 줄바꿈됐다. 인증 후 교사·학생 화면의 모바일 검증은 여전히 미완료다.

## 6개 관점의 구현 후 판단

| 프로파일 | 근거와 개별 판단 | 판정 |
|---|---|---|
| WD-01 · 시각 구성 | 교사 운영 요약 스크린샷에서 안전 두 카드가 첫 정보 묶음에 있고 사이드 메뉴와 본문 대비가 분명하다. 학생 오늘 화면은 가린 친구와 미션 한 개가 첫 과업이다. 공개·빈 상태의 시각 균형은 전부 보지 못했다. | 범위 내 부분 확인 |
| WD-02 · 반응형 레이아웃 | 1280px 참가자 3열과 미션 2열에서 문장·체크 정렬을 확인했다. 로그인 전 학생 화면은 320·390·768px에서 넘침과 문장 줄바꿈을 확인했다. 인증 후 320·360·390·768px, 200% 확대, 40장 인쇄는 실제 렌더링 증거가 없다. | 근거 부족 |
| UX-01 · 정보 구조 | 학급→운영 요약→회차 4단계가 실제 브라우저에서 성립했다. 명부를 지나지 않고 도움 건수를 봤다. 뒤로가기·다른 학급 이탈 복구는 미확인이다. | 범위 내 부분 확인 |
| UX-02 · 인지 부담 | 학생 오늘/우편함/도움의 업무가 분리되고, 보내기·도움 접수 상태가 행동 가까이 보였다. 저학년·교사 사용자 관찰 없이 문구 이해를 통과로 단정할 수 없다. | 근거 부족 |
| UI-01 · 조작·상태 | 긴 이름 문장 클릭과 Space 선택, 미션 3개 상한, 쪽지 전송 후 한도, 도움 접수를 확인했다. 자동 저장 결함을 수정·재검증했다. native 미저장 확인과 안전 원문·위험 작업 취소의 실제 키보드 결과는 미확인이다. | 범위 내 부분 확인 |
| UI-02 · 접근성·품질 | 활성 버튼 색을 `#b94440`으로 바꾸고 native 입력·`aria-current`·오류 역할·확인 대화상자 초점을 구현했다. 화면 폭 전환과 VoiceOver, 200% 확대의 실제 결과가 없어 전체 접근성 통과 근거는 없다. | 근거 부족 |

## 남은 검수와 판정

- **미완료 검수:** 인증 후 320·360·390·768px 및 200% 확대의 체크박스·메뉴·긴 문장, A4 카드 1·40장 인쇄, native 미저장 이탈 대화상자의 취소/승인, 안전 원문 열람·탭 이탈, 공개·지난 활동의 기본 가림, VoiceOver, 실제 교사·학년군별 학생 과업 관찰.
- **현재 판정:** 코드와 자동 테스트는 통과했지만 계획서 §10의 디자인·접근성·사용자 관찰 완료 조건은 충족하지 않았다. 확인되지 않은 항목을 통과로 표시하지 않는다. 실제 학생 데이터의 입력 제한과 개인정보 정책 미확정 상태도 유지한다.
- **다음 조치:** 실제 화면 폭과 인쇄·보조기기 접근이 가능한 환경에서 위 재현 과제를 수행하고, 확인된 결함을 고친 뒤 6개 관점의 완료 판정을 갱신한다.
