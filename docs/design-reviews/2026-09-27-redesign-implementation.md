브라우저의 화면 폭 변경 기능은 390px을 지정한 뒤에도 실제 `innerWidth`가 IAB 1280px, Chrome 1512px로 남았다. 별도 `agent-browser` CLI도 버전 조회는 됐으나 로컬 페이지 열기와 진단에서 응답하지 않았다. 이 시도를 모바일 검증 통과로 계산하지 않는다.

추가로 격리된 headless Chrome의 기기 지표를 직접 320·390·768px로 고정해 **로그인 전 학생 입장 화면**을 캡처했다. 각 폭에서 실제 `innerWidth`와 문서 폭이 같고 넘치는 요소가 없음을 확인했다. 첫 빠른 캡처의 글자 잘림은 렌더링 완료 전 상태였으며, 완료 후 재촬영에서는 문장이 줄바꿈됐다. 인증 후 교사·학생 화면의 모바일 검증은 여전히 미완료다.

GitHub `main`의 `3a15499`를 Vercel이 성공 배포한 뒤 [공개 학생 입장 390px](assets/student-login-390.png)과 [공개 교사 로그인 390px](assets/teacher-login-390.png)을 다시 캡처했다. 두 화면 모두 실제 `innerWidth=390`, `documentWidth=390`이고 오른쪽으로 넘치는 요소가 없었다. 공개 도메인의 HTML은 새 CSS 자산을 제공했고 HTTP 200을 반환했다. 이는 로그인 전 배포 화면 확인이며 인증 후 운영 화면의 390px 검증을 대체하지 않는다.

## 남은 검수와 판정

- **미완료 검수:** 인증 후 320·360·390·768px 및 200% 확대의 체크박스·메뉴·긴 문장, A4 카드 1·40장 인쇄, native 미저장 이탈 대화상자의 취소/승인, 안전 원문 열람·탭 이탈, 공개·지난 활동의 기본 가림, VoiceOver, 실제 교사·학년군별 학생 과업 관찰.
- **현재 판정:** 코드와 자동 테스트는 통과했지만 계획서 §10의 디자인·접근성·사용자 관찰 완료 조건은 충족하지 않았다. 확인되지 않은 항목을 통과로 표시하지 않는다. 실제 학생 데이터의 입력 제한과 개인정보 정책 미확정 상태도 유지한다.
- **다음 조치:** 실제 화면 폭과 인쇄·보조기기 접근이 가능한 환경에서 위 재현 과제를 수행하고, 확인된 결함을 고친 뒤 6개 관점의 완료 판정을 갱신한다.

## 2026-09-27 R4 인증 후 브라우저 재검증과 수정

이 절의 실측 결과는 위 초기 검토의 `미확인` 항목 중 **같은 과제에 해당하는 것**을 갱신한다. [R4 사전 검토](2026-09-27-r4-mobile-navigation.md)에서 발견 결함별 여섯 관점의 설계 판단을 먼저 남기고 수정했다. 수행은 Codex 한 에이전트의 가상 역할별 검토다. 실제 외부 전문가 승인이나 사용자 관찰은 아니다.

- 환경: `demo-manitto` 로컬 에뮬레이터, 별도 headless Chrome과 `agent-browser` UI 조작, 가상 교사·40명 학급의 진행→공개→보관 회차, 카드 인쇄용 가상 40명 학급. 가상 검증 학급 3개를 삭제하고 학급 문서 부재 3건을 확인했다. 실제 학생 정보와 개발 Firebase 데이터는 사용하지 않았다.
- 교사 40명 화면: 실제 `innerWidth` 320·360·390·768px에서 문서 폭이 각 화면 폭과 같았다. 320px 긴 참가자 이름과 미션 문장이 체크박스 옆에서 줄바꿈되고, 문장 클릭·Space 선택과 미션 3개 상한을 조작했다. 390px 운영 요약에서 도움·쪽지 건수를 명부보다 먼저 봤다.
- 교사 메뉴·카드: 모바일 학급 메뉴는 페이지 전환 성공 뒤 닫힌다. 학생 40명 학급에서 `새 학생 등록`은 닫힌 펼침이고 검색이 390px 첫 화면에 들어온다. 학생이 0명이면 등록 폼이 바로 보인다. 320px에서도 검색·상태 필터 높이는 44px, 문서 폭 320px이다. 메뉴·등록 펼침은 Enter로 열고 닫았다.
- 카드 발급 과업: 40명 신규 등록 직후 운영 요약으로 벗어나는 P1을 발견했다. 수정 후 `/students`에 남아 새 카드 40장 선택과 인쇄 버튼까지 이어졌다. CSS 페이지 크기 우선 인쇄 엔진으로 A4 1쪽·40쪽 PDF의 크기, 첫·마지막 장의 카드 경계·이름·문장·흰 바탕을 확인했다. 도구의 기본 PDF 명령은 CSS A4를 무시해 Letter로 출력하므로 CSS 우선 옵션을 명시해 재검증했다. 실제 물리 프린터 출력은 미확인이다. 테스트 PDF와 카드 원문은 저장소에 넣지 않았다.
- 저장·안전·학생: 미저장 3개 미션 상태에서 페이지 이탈 확인을 취소하면 입력과 현재 단계가 남았고, 승인하면 안전 페이지로 이동했다. 안전 도움·쪽지 원문은 개별 열기 전 보이지 않고 페이지 이탈·복귀 때 닫혔다. 가상 도움 1건 처리와 쪽지 1건 승인 후 활동 종료·정체 공개·보관을 교사 UI로 수행했다. 학생 오늘은 공개 뒤 두 관계가 기본 가림이고 메뉴 이탈·복귀 때 재가림, 지난 활동은 기록을 닫고 다시 열 때 두 관계가 재가림이었다. 학생 `/student/history` 직접 주소 인증 후 URL·제목·현재 메뉴가 일치하도록 수정·재검증했다.
- 접근성 자동 검사: axe-core 4.12.1의 카드 관리 40명 화면은 처음에 상태 글자 대비 4.24:1 위반 40개가 있었다. 색 보정 후 360·390px 카드 관리와 320px 학생 오늘에서 위반 0개였다. 배경 그라데이션 위의 브랜드·제목은 도구가 배경을 판정하지 못해 `incomplete`로 남았다. 키보드 Enter·Space 결과는 확인했지만 VoiceOver 읽기 순서·실제 200% 브라우저 확대는 확인하지 않았다.
- 자동 회귀: 전체 TypeScript·Vite 빌드, 함수 단위 10건, Firestore Rules 11건, 두 회차·40명 통합 3건, `git diff --check`가 통과했다. Vite 500kB 초과 청크 경고는 남는다.
