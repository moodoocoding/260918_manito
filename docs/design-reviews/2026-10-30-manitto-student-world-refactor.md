## 사용자와 설계안

- 대상 사용자·이용 환경·핵심 과업: 학급 공용기기에서 카드로 로그인하는 초등학생. 마을에서 마니또 건물에 들어가 현재 활동을 이해하고, 미션 선택/완료, 친구 쪽지, 도움 요청, 공개 승인 뒤 관계 확인과 회고, 지난 기록 열람을 수행한다.
- 현재 문제와 재현 조건: 관찰된 코드 구조상 마니또 표지가 x=40의 별도 건물에 있고 새 공간 1은 준비 중 표시다. `/student/missions`, `/student/friend-mail`, `/student/history`는 각각 직접 화면이며 새 서비스 홈/공통 서비스 진입이 없다. `loadStudent`가 공통 `getStudentHome`과 마니또 전용 `listStudentRounds`를 `Promise.all`로 기다리므로 지난 활동 조회 실패가 학생 플랫폼의 로그인/마을 진입을 막을 수 있다. 과거 화면은 공통 월드 프레임을 실제 사용하지 않고 legacy panel 형태로 렌더링된다. (위 항목은 코드에서 확인)
- 페이지·섹션 구성과 이동 경로:
  - 마을 → 새 공간 1 실제 건물/간판/상호작용 → `/student/manitto` 서비스 진입.
  - 서비스 메뉴: 활동 홈, 미션, 친구 쪽지, 도움, 지난 활동. 각 화면은 공통 `WorldPageFrame/Header/Paper/Button/PixelIcon`을 사용한다.
  - 활동 홈은 회차 상태와 내 미션 요약, 다음 미션 주 행동을 중심으로 구성한다. 비밀친구 이름은 기존 안전 타이머와 가림 동작으로만 표시한다. 공개 관계 확인과 회고는 기존 공개 완료 조건에서만 제공한다.
  - 기존 `/student/missions`, `/student/friend-mail`, `/student/history` 직접 경로를 유지하며 새 메뉴의 해당 화면으로 연결한다. `/student/space-1`은 동일 서비스 진입으로 매핑하고, `?area=east` 위치는 보존한다.
  - 뒤로/마을 복귀는 학생 월드 위치를 유지하고, 활동 마치기는 기존 세션 종료 callback을 호출한다.
- 각 화면의 목적·주요 행동·저장 범위: 활동 홈은 현재 상태 확인과 선택된 미션 완료(기존 `setMissionStatus`); 미션은 목록 탐색/선택(기존 `setStudentMissionFocus`); 친구 쪽지는 양방향 대화와 익명 답장(기존 `sendMessage`, `reactToMessage`, `hideMessage`, 도움 신고); 도움은 비공개 요청(기존 `createHelpRequest`); 지난 활동은 서비스 진입 후에만 `listStudentRounds`를 요청하고 선택한 회차의 기존 `getStudentActivity` 기록을 읽는다. 새 API·필드·저장은 추가하지 않는다.
- 기본·빈 상태·로딩·오류·완료와 취소·복귀: 활동이 없을 때 시즌이 없어도 플랫폼을 이용할 수 있음을 짧게 안내하고 미션/쪽지의 활동 없음 상태를 제공한다. 각 API 요청은 로딩, 다시 시도 가능한 오류, 서버 확인 뒤 저장 완료를 구분한다. 이동 전 친구 쪽지 작성 중 이탈 확인을 유지하고, 비밀 이름은 탭 복귀/화면 숨김/이탈 시 즉시 가린다.
- 반응형·긴 텍스트·최대 항목·키보드 설계: 1280px에서 프레임 최대 1200px 및 2열 카드가 필요한 곳만 적용, 768px 이하 한 열, 640px 이하 공통 모바일 헤더 재배치를 따른다. 320px 상당, 360/390/768/1280px, 긴 학급/회차/미션/쪽지 문장과 최대 목록, 200% 텍스트 확대를 검증한다. 메뉴는 실제 링크, 버튼은 실제 버튼으로 제공하고 지도 이동·E/Enter와 상호작용 버튼을 유지한다.

## 구현 후 실제 검증

- 검토 방식·자료: Codex 한 에이전트가 여섯 가상 프로파일을 각각 적용해 코드와 브라우저 결과를 사후 검토했다. 실제 외부 전문가, 학생, 교사의 검토는 없었다. 기준은 `docs/world-design-system.md`와 `docs/design-references/world-interior-approved.png`이며 승인된 도트 교실/목재 프레임/양피지와 구현 화면을 비교했다.

- 발견 사항과 조치: R1은 공통 학생 로더에서 회차 조회를 없애고 지난 활동 진입에서만 조회해 구조적으로 해결했다. R2는 기존 x=40 진입 표식을 없애고 공간 1만 사용해 해결했다. R3는 공통 월드 프레임/헤더/종이/버튼/픽셀 아이콘을 사용하고 중복된 활동 제목을 제거해 해결했다.
- 잔여 문제·미확인 항목·다음 조치: 활성 회차의 저장·안전·공개/회고 상태와 API 강제 오류, 스크린리더, 실제 장치는 이 검토에서 미실시다. 활성 회차의 시각/저장/보안 동작을 변경했다는 결론으로 확대하지 않는다. 학생 데이터를 사용하기 전에 실제 교실/기기 검토와 개인정보 준비 조건이 별도로 필요하다.
