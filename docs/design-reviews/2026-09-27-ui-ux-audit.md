# 전문가 검토 기록: 마니또 디자인·UX·UI 전면 개선안

## 검토 정보

- 날짜·대상: 2026-09-27, 웹 기준 커밋 `0e9275c`, [디자인 수정 계획서 v1.0](../design-revision-plan.md).
- 요청: 현행 서비스의 디자인·UX·UI 문제 검토와 실제 수정 전에 사용할 계획서 작성.
- 범위: 교사·학생 정보 구조, 화면 배치, 선택·입력·상태·오류·민감 행동, 반응형·접근성 검수 방식. 서비스 코드 수정·배포·실제 학급 운영은 범위 밖.
- 수행 주체·방식: **Codex 한 에이전트가 가상 프로파일 6개를 각각 적용한 역할 기반 검토**. 별도 에이전트 위임이나 외부 인간 전문가 자문은 수행하지 않았다.
- 읽은 프로파일: [WD-01](../experts/wd-01-visual-design.md), [WD-02](../experts/wd-02-responsive-layout.md), [UX-01](../experts/ux-01-information-architecture.md), [UX-02](../experts/ux-02-cognitive-usability.md), [UI-01](../experts/ui-01-interaction-design.md), [UI-02](../experts/ui-02-accessibility-quality.md).
- 입력 자료: 개발 계획서 v2.1, 작업일지, UI 콘셉트, `web/src` 화면·스타일, 가상 40명 학급의 실제 Chrome 화면·계산 스타일·선택 조작, W3C·NN/g 원문.
- 검토 단계: **현행 구현 진단 + 수정안 사전 설계 1차**. 리디자인 구현 후 재검토가 아니다.
- 도구: `agent-browser`·검증 스킬의 화면/조작 확인 절차를 읽었으나 실행 파일이 없어 CUA의 Chrome·DOM 관찰로 수행했다. 서버는 이미 실행 중인 로컬 Vite·Emulator를 사용했다.

## 사용자와 설계안

교사는 수업 전 명부·카드를 준비하고, 수업 중 안전 요청과 진행 상황을 확인하며, 종료 후 공개·회고·다음 회차를 운영한다. 학생은 교실의 공용기기에서도 친구·미션·쪽지를 짧게 확인하고 도움·쉬기·로그아웃을 찾을 수 있어야 한다.

현행의 기능 나열식 구조를 교사 `운영 요약 / 학생·카드 / 회차 / 안전 확인 / 지난 활동 / 학급 설정`, 학생 `오늘 / 우편함 / 지난 활동 + 공통 도움·마치기`로 재구성하는 안이다. 회차 준비는 네 단계, 안전 처리는 목록·상세, 기록은 읽기 중심으로 나눈다. 자세한 화면 목적·이동·저장은 계획서 §3~4, 배치 스케치는 §5, 상태·반응형은 §6~7, 검증은 §10을 기준으로 한다.

이 안은 제품의 매칭·권한·한도·회차 정책을 바꾸기 위한 제안이 아니다. 서버 응답 보강이 필요한 항목은 계획서 §8에서 분리했다. 화면이 스스로 오늘 날짜·전송 가능 이유·민감 정보 공개 여부를 추정하지 않게 한다.

## 6개 관점의 개별 판단

### WD-01 · 시각 구성과 브랜드

**현행 판정: 수정 필요.** 인사·설명·학급 생성·카드·회차가 비슷한 크기의 둥근 패널과 강조색을 공유한다. 첫 화면에서 교사가 먼저 처리할 안전 업무를 시각적으로 찾을 수 없고, 학생에게도 큰 인사와 여러 업무가 경쟁하는 구조다. E01~E03의 계층·배치와 코드의 공통 패널 규칙을 근거로 한다. 색 취향이 아니라 주요 행동의 발견성 문제다.

계획서 §5의 역할별 밀도, 주 행동/보조 행동 구분과 대비 보강은 타당한 방향이다. 그러나 실제 콘텐츠를 채운 시안에서 인사·봉투·미션·도움의 상대적 무게와 운영 요약의 여백을 아직 확인하지 않았다. **수정안 판정: 근거 부족.** R0에서 교사 요약·학생 오늘의 390/1280 시안과 빈/오류 상태를 재검토한다. 문제 DR-02·03·04·21 담당.

### WD-02 · 반응형 레이아웃과 타이포그래피

**현행 판정: 수정 필요.** E03의 체크박스 분리와 긴 미션 4열은 의미 단위가 시각적으로 묶이지 않은 실제 문제다. 40명 명부가 별도 과업과 세로로 결합되어 E02의 불필요한 길이를 만든다. 가로 넘침이 없더라도 적정 열 수·초점·줄바꿈이 검증된 것은 아니다.

계획서의 참가자/미션 그리드 분리, 폼 폭 제한, 내용 높이 허용과 폭별 배치 기준을 검토했다. **수정안 판정: 근거 부족.** 지정 viewport가 적용되지 않았으므로 320~1280, 긴 이름·미션·오류·40개·인쇄의 실제 배치 근거가 더 필요하다. R0 시안과 R1 선택 행 후 재검토. DR-01·05·13·15·21 담당.

### UX-01 · 정보 구조와 과업 흐름

**현행 판정: 수정 필요.** E01·E02·E05에서 학급 선택의 기본 과업이 ‘운영 확인’보다 ‘새 설정 작성’에 가깝다. 명부를 읽는 행위와 도움을 처리하는 행위의 시작점을 분리하지 않았고, 저장 전 회차 변경에 안전한 복귀가 없다. H2·H3·H6·H7·H8 관점의 문제다.

새 사이트맵과 네 단계 준비, 마지막 유효 설정 저장, 안전 상세 후 목록 복귀, 지난 회차 복사 흐름은 문제에 대응한다. **수정안 판정: 수정 필요.** R0에서 운영 요약의 서버 조회 범위, 저장 초안 재개와 인증 만료 후 복귀 경로를 구체적 화면 흐름으로 확정해야 한다. 일부 초안 자동 저장이 이미 제공되는 것처럼 구현하면 안 된다. DR-02·03·06·07·17 및 계획서 §8 계약 담당.

### UX-02 · 인지 부담과 사용자 이해

**현행 판정: 수정 필요.** 날짜 쉼표 입력, 회차/작전 혼용, 개인 로그아웃과 회차 종료의 비슷한 이름, 저학년에게도 자유 문장 회고를 요구하는 코드를 확인했다. 학생의 도움 접수 상태와 다음 쪽지 가능 시점이 충분히 표현되지 않는다. 실제 아동의 실패율은 측정하지 않았으며 인지적 워크스루에 따른 판단이다.

계획서의 행동 중심 문구, 선택형 도움·학년군별 회고, 상태별 이유와 다음 행동을 검토했다. **수정안 판정: 근거 부족.** R0에서 1~2학년 화면 문구·선택지와 3~4학년 문장 틀을 실제 콘텐츠로 채우고, R4에서 교사·학생 이해를 관찰해야 한다. DR-06·09·14·16·18·19·20 담당.

### UI-01 · 조작과 컴포넌트 상태

**현행 판정: 수정 필요.** 체크박스는 선택되지만 표시·초점 형태가 어긋난다(E03). 준비·시작·종료·공개 등 서로 다른 행동에 충분한 결과 확인이 없고, 코드의 오류·처리 중 피드백은 작업 위치와 분리돼 있다. 학급 삭제에는 확인 절차가 있으므로 ‘모든 위험 행동에 확인이 없다’고 판단하지 않는다.

계획서의 컴포넌트 상태표·위험 행동 확인·기존 입력 보존·동일 요청 재시도 원칙을 검토했다. **수정안 판정: 수정 필요.** R0에서 DR-08의 공개/참여 중단/재발급 대화상자, 전송 성공 후 재조회 실패와 재시도 상태, 미션 교체·감사 1회 상태를 동작 명세로 완성해야 한다. DR-01·06·07·08·11·12·19·20·22 담당.

### UI-02 · 접근성과 화면 품질

**현행 판정: 수정 필요.** 활성 버튼 글자 대비 2.90:1은 측정된 결함이며 체크박스 포커스 배치는 화면에서 확인했다. 학생 정보 요청의 구조·스타일 적용 범위도 추가 검증 대상이다. 현재 `:focus-visible`, 라벨 및 alert/status 사용이 일부 존재하지만 이것만으로 전체 접근성 통과를 부여하지 않는다.

계획서의 대비·터치 영역·재배치·초점·오류 연결·VoiceOver 검증표는 방향이 맞다. **수정안 판정: 근거 부족.** 실제 좁은 폭·확대·키보드 과업 전체·스크린리더·인쇄 확인이 없다. R1 및 R4에서 근거를 채운다. DR-01·04·10·11·13·22 담당.

| 학생 과업·상태 | 03·09·10·14·18·19·20 | UX-02·UI-01, R3 | 학년군, 이름 가림, 도움·회고·감사·공용기기 |
| 전체 재검토 | 01~22 | 6개 관점, R4 | 계획서 V01~V13 및 두 회차 회귀 |

P2도 해당 변경 범위에서는 완료 전에 해결한다. 이번 목록은 P1·P2이며 P3로 중대 문제를 낮춰 보류하지 않았다. P0의 실제 정보 노출·오삭제 사고를 재현한 검토는 아니지만 공개·삭제·민감 열람의 안전 기준은 후속 검수에서 필수다.

### 의견 차이와 결정 이유

- **단계가 늘면 번거롭다 / 한 화면이 과밀하다:** 처음 회차 준비는 네 단계, 반복 회차는 설정 복사 후 검토부터 시작할 수 있게 한다. 클릭 수 최소화보다 실수·저장 범위·복귀를 우선한다.
- **큰 카드가 친근하다 / 교사 화면이 길다:** 브랜드 색·아이콘은 공유하되 교사는 밀도 있는 목록과 폼, 학생은 한 과업 카드로 역할을 나눈다.
- **미션 4열이 공간을 잘 쓴다 / 긴 한국어를 읽기 어렵다:** 10개 문장형 미션은 1~2열, 짧은 참가자는 별도 그리드를 쓴다. 열 수를 통일하지 않는다.
- **쉽게 재입장 / 비밀 보호:** 저장 초안은 서버 권한 확인 후 복구하되 카드·친구·원문을 브라우저 저장소에 넣지 않는다. 이름 가림은 공개 권한과 별도로 유지한다.
- **하단 탐색 / 도움 발견성:** 학생 일반 탐색은 단순하게 유지하고 도움과 로그아웃은 공통 영역에서 따로 보이게 한다. 도움을 더 보기로 숨기지 않는다.

## 착수·완료 판정

**현행 UI 검수는 통과가 아니다. 수정안의 서비스 코드 구현 착수도 아직 통과로 기록하지 않는다.** 계획서에는 R0에서 보완할 시안·상태·계약 작업과 담당이 명시돼 있다. 그 자료를 만든 뒤 각 관점의 사전 판단을 다시 기록해야 한다. 이는 [저장소 필수 지침](../../AGENTS.md)의 “6개 관점 모두 사전 설계 검토를 통과하고 미해결 P0·P1 문제가 없어야 구현에 착수한다”는 내부 개발 절차에 따른다. 사용자에게 반복 승인을 요구하는 절차가 아니며, 이번 요청의 산출물인 진단과 계획서는 작성했다.
