# 입장 카드 명칭·선택 미션 수·가상 체험 학급 검토

## 검토 정보

- 날짜/기준: 2026-09-28, `bf56bf2` 이후 코드와 사용자 요청.
- 수행: Codex 한 에이전트가 저장소의 여섯 가상 전문가 프로파일을 각각 적용했다. 실제 외부 전문가·교사·학생이 참여한 검토가 아니다.
- 범위: 교사 메뉴·인쇄 카드 명칭, 시즌 미션 선택·시작·학생 활동, 교사·학생 접속용 가상 학급. 실제 학생 운영 정책은 범위 밖이다.
- 자료: `web/src/main.tsx`, `web/src/TeacherRounds.tsx`, `web/src/StudentRound.tsx`, `functions/src/rounds/{common,flow,missions,activity}.ts`, 기존 디자인 검토와 사용자 요청.

## 사용자 과업과 설계안

- 교사는 `입장 카드`에서 학생 명단과 코드를 확인하고, 시즌 설정의 `미션` 단계에서 원하는 개수의 미션을 선택해 저장·시작한다. 한 개 이상 선택할 수 있고 선택 가능한 개수는 기본 40개와 학급 추가 미션 최대 40개다. 화면은 현재 선택 수와 기간 안에 진행할 총량을 표시한다.
- 학생은 시즌 기간 안에 선택된 미션을 자신의 속도로 수행·쉬기·교체한다. `오늘`에는 한 미션을 먼저 보여주고 전체 목록을 펼칠 수 있으며, 전부 완료해야 쪽지나 도움 기능을 사용할 수 있게 만들지 않는다. 일별 미션 할당이나 순위는 만들지 않는다.
- 현재 3개 제한을 단순히 프런트에서 풀면 서버의 `[0,3]` 검증과 `startRound`의 `3개 아니면 기본 3개` 경로에 막힌다. 또한 40명×10개를 개별 문서로 동시에 만드는 기존 시작 트랜잭션은 Firestore 쓰기 한도를 넘는다. 선택 미션의 ID·원문을 시작 트랜잭션의 `round.missionPlan`에 한 번만 고정하고, 학생별 완료·쉬기·교체 문서만 필요할 때 만든다. 기존 시즌의 학생별 문서는 계속 읽는다. 시작의 배정·학급 잠금 원자성은 유지한다.
- `입장 카드`는 메뉴·제목·인쇄 카드의 명칭을 통일한다. 학생 등록과 코드 재발급 기능은 같은 페이지에 유지하되 페이지 목적과 인쇄 행동을 먼저 읽을 수 있게 한다.
- 가상 학급은 개발 프로젝트에만 만들고 실제 학생 이름을 쓰지 않는다. 기존 승인 교사 계정이 소유하고, 4명의 가상 학생과 미션 10개가 있는 진행 시즌을 만든다. 교사 접근은 기존 Google 로그인, 학생 접근은 가상 카드로 검증한다. 교사 계정 식별 전에는 다른 사람에게 권한을 추가하지 않는다. 카드 코드는 저장소·작업일지·URL에 남기지 않고 사용자에게만 전달한다.
- 상태·오류: 0개 선택은 다음 단계와 저장에서 이유를 알려 막는다. 중복 미션 ID와 존재하지 않는 미션은 서버가 거절한다. 목록 로딩·저장·시작 실패 시 재시도 경로를 유지한다. 과거 시즌의 빈 `missionIds`는 기본 3개 호환을 유지한다. 미션 교체 후보가 없으면 기존과 같이 설명된 오류를 보인다.
- 반응형: 기존 카테고리별 2열/모바일 1열과 체크박스 라벨 전체 클릭을 유지한다. 10개 선택·긴 사용자 미션 문장, 320/390/768/1280px과 키보드 초점, 200% 확대를 구현 후 확인한다.

## 문제·조치·확인

| ID/등급 | 문제 → 근거 → 사용자 영향 | 수정안 → 확인 방법 |
|---|---|---|
| M1/P1 | 3개 고정·서버 대체·시작 쓰기 수 → H2/H5와 저장 불변 조건 → 10개 시즌을 만들거나 시작할 수 없음 | 1~80개 검증, 시즌 미션 계획 한 번만 원자적 저장, 학생 개인 상태 지연 기록 → 4명/40명×10개·1개·기존 시즌 통합 시험 |
| M2/P2 | `학생·입장 카드`와 인쇄물 명칭 불일치 → H4 → 메뉴 목적 파악 지연 | 메뉴·제목·인쇄 제목을 `입장 카드`로 통일 → 브라우저와 인쇄 미리보기 확인 |
| M3/P1 | 체험 학급 부재 → H7/H9 → 교사·학생 흐름을 사용자가 직접 확인할 수 없음 | 개발 프로젝트의 가상 학급·10개 미션 시즌·가상 카드, 실제 양쪽 로그인 확인 → 권한·접속·삭제 가능성 확인 |

사전 판정: 여섯 관점 모두 위 설계로 통과했다. 미해결 P0·P1은 없다. 구현 후 확대·화면 읽기 도구·실제 교사/학생 과업 관찰이 남으면 각 관점과 시점을 명시한다.

## 구현 후 재검토

수행: Codex 한 에이전트가 여섯 가상 관점을 다시 적용했다. 로컬 `demo-manitto` 가상 교사·학생 4명과 15일 시즌에서 미션 10개 선택·저장·매칭 시작·학생 로그인·10개 목록·1개 완료를 Chrome에서 확인했다. 교사 확인 화면은 1512px에서 10개가 2열 요약으로 줄바꿈됐고, 390px 교사 입장 카드와 학생 활동에는 가로 넘침이 없었다. 카드 체크박스는 키보드 Space로 선택돼 선택 출력 수가 0→1로 바뀌었다. 함수 단위 10건, Rules 12건, 통합 3건(40명×10개 포함), TypeScript·Vite 빌드가 통과했다.

| 역할 | 구현 후 독립 판단·근거 | 남은 확인 |
|---|---|---|
| WD-01 | `입장 카드` 메뉴·제목과 인쇄 제목을 통일했다. 10개 미션 확인 화면은 수량과 목록의 위계가 보였고, 학생 화면도 첫 과업이 앞에 놓였다. | 실제 A4 인쇄물의 새 제목 확인 |
