## 1. 사전 요구사항 및 문제 진단

### 문제점 1: 학급 코드 수정 위치 부재
- **진단**: 학급 코드가 '입장 카드' 화면 상단에 크게 보이지만 편집 버튼이 없어 수정이 불가능하다고 인식됨. 실제 수정 기능은 '설정' 탭 깊숙이 있어 발견하기 어려움.
- **해결안**: 입장 카드 상단 학급 코드 영역에 `[코드 변경]` 버튼을 추가하고 인라인/모달 폼으로 즉시 변경 가능하도록 개선.

### 문제점 2: 기존 개설 학급 삭제 기능 부재
- **진단**: 교사 메인 학급 목록(`classes` 화면)에 학급 선택 버튼만 있고 삭제 버튼이 없음. 학급을 지우려면 해당 학급으로 들어간 뒤 '설정' 탭에서 학급 이름을 똑같이 타이핑해야 하는 높은 장벽 존재.
- **해결안**: 학급 목록 카드에 명확한 `[삭제]` 버튼을 배치하고, 안전한 확인 다이얼로그를 통해 원클릭 삭제 지원.

### 문제점 3: 시즌 설정 시 학생 명단 입력 누락 및 단절된 워크플로우
- **진단**: 새 학급 개설 후 시즌 설정으로 진입하면 학생 명단을 넣는 곳이 없어 진행 불가. 학생을 등록하려면 다시 '입장 카드' 메뉴로 돌아가야 하는 워크플로우 단절 발생.
- **해결안**:
  1. 시즌 설정 2단계(참가자·제외)에 **학생 명단 등록/가져오기 기능**을 직접 통합.
  2. 텍스트 복사-붙여넣기뿐만 아니라 엑셀(`.xlsx`, `.xls`, `.csv`), PDF, 한글(`.hwp`, `.hwpx`), 텍스트(`.txt`) 파일을 드래그앤드롭하여 자동으로 학생 이름을 추출·정리하는 스마트 파서 구현.
  3. 명단 등록 완료 시 자동으로 시즌 참가자로 선택되어 필수 제외 관계 설정으로 매끄럽게 연결.

## 2. 6개 관점 개별 검토 및 판단

### WD-01 · 시각 구성과 브랜드
- **판단**: 통과 (개선안 반영)
- **근거**:
  - 학급 목록의 삭제 버튼은 위험 작업이므로 `danger outline` 스타일로 구분하여 실수 방지.
  - 학생 명단 스마트 임포터는 점선 테두리의 드롭존과 부드러운 파일 아이콘, 추출된 이름 태그 그리드를 제공하여 전문적이고 친근한 교사 도구 감성 전달.

### WD-02 · 반응형 레이아웃과 타이포그래피
- **판단**: 통과 (개선안 반영)
- **근거**:
  - 학급 목록 아이템이 모바일 화면(360px)에서 학급 정보와 삭제 버튼이 어색하게 겹치지 않도록 flex-wrap 및 버튼 터치 영역 44px 이상 확보.
  - 파일 업로드 및 텍스트 파싱 영역이 모바일과 데스크톱 모두에서 유연하게 반응하도록 설계.

### UX-01 · 정보 구조와 과업 흐름
- **판단**: 통과 (개선안 반영)
- **근거**:
  - **시즌 설정 워크플로우 완성**: [1. 기본 정보] → [2. 학생 명단 등록 및 참가자·제외] → [3. 미션] → [4. 쪽지] → [5. 확인·저장].
  - 학생이 없는 상태에서 시즌을 만들 때 외부 메뉴로 이탈하지 않고 그 자리에서 파일이나 붙여넣기로 명단을 즉시 등록하고 다음으로 직진할 수 있음.

### UX-02 · 인지 부담과 사용자 이해
- **판단**: 통과 (개선안 반영)
- **근거**:
  - 나이스(NEIS)나 엑셀 명렬표에서 복사했을 때 섞여 들어오는 출석번호, 공백, 쉼표, 기호 등을 정규식 엔진이 자동으로 정제하여 교사가 일일이 타이핑하거나 오타를 지우는 번거로움 해소.
  - 파싱 결과 미리보기 태그를 교사가 눈으로 확인하고 제외/추가할 수 있어 안심감 제공.

### UI-01 · 조작과 컴포넌트 상태
- **판단**: 통과 (개선안 반영)

  - 파일 드래그앤드롭(dragover, dragleave, drop) 시각 피드백.

## 4. 구현 후 6인 전문가 재검토 및 검증 결과

### WD-01 · 시각 구성과 브랜드
- **확인 결과**: 통과
- **근거**: 드롭존의 점선 보더와 아이콘, 파일 확장자 뱃지(`XLSX`, `CSV`, `PDF`, `HWP`, `TXT`) 디자인이 브랜드 시스템의 보라색 테마와 조화롭게 어우러짐. 학급 목록 카드의 삭제 버튼도 위험도를 나타내는 소프트 레드 스타일로 배치되어 시각적 위계가 잘 유지됨.

### WD-02 · 반응형 레이아웃과 타이포그래피
- **확인 결과**: 통과
- **근거**: 추출된 학생 이름 태그 그리드가 `flex-wrap` 및 최대 높이(`max-height: 220px`) 스크롤을 적용하여 명단이 40명까지 늘어나도 레이아웃이 깨지지 않음. 모바일 좁은 화면에서도 드롭존과 탭 버튼이 적절한 터치 타겟 크기를 유지함.

### UX-01 · 정보 구조와 과업 흐름
- **확인 결과**: 통과
- **근거**: 새 학급을 만들고 곧바로 시즌 설정을 진행할 때, 2단계에서 즉시 명단을 붙여넣거나 파일을 넣어 등록할 수 있게 되어 워크플로우 단절이 완전히 해소됨. 등록 직후 자동으로 참가자 명단에 반영되어 체크박스로 제외 관계를 설정할 수 있음.

### UX-02 · 인지 부담과 사용자 이해
- **확인 결과**: 통과
- **근거**: 나이스 명렬표 번호(예: `1. 김민준`, `2 이서연`), 탭/줄바꿈 구분, 엑셀 셀 등 다양한 형식의 입력값을 정확히 파싱함. 파싱된 명단을 번호 태그로 직관적으로 보여주며 교사가 손쉽게 잘못 들어간 항목을 삭제(`×`)하거나 개별 추가할 수 있어 심리적 통제감이 높음.

### UI-01 · 조작과 컴포넌트 상태
- **확인 결과**: 통과
- **근거**: 드래그앤드롭 반응(hover, dragover), 파일 파싱 중 상태 피드백, 학급 삭제 시 오동작 방지를 위한 2차 확인 모달(`ConfirmDialog`), 인라인 학급 코드 수정 취소/저장 상태가 안정적으로 동작함.

### UI-02 · 접근성과 화면 품질
- **확인 결과**: 통과
- **근거**: 키보드 탭 이동으로 파일 선택 버튼 및 탭 전환 가능. 입력 필드에 적절한 `placeholder`와 `aria-label` 제공. Vite 프로덕션 빌드 및 함수 단위 테스트 전체 100% 통과.
