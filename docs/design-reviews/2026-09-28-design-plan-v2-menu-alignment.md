# 디자인 계획 v2.0과 변경된 메뉴 정렬 검토

## 검토 정보

- 날짜/대상: 2026-09-28, 현재 `main`의 교사 상태 확인·정보 요청·삭제 메뉴와 학생 홈·미션·우편함 화면.
- 수행: Codex 한 에이전트가 저장소의 6개 **가상** 전문가 프로파일로 코드·계획서 기반 사전 검토. 실제 외부 전문가나 교사·학생 참여는 없다.
- 자료: `docs/design-revision-plan.md` v2.0, `docs/experts/*`, `web/src/main.tsx`, `TeacherRounds.tsx`, `TeacherStudentStatus.tsx`, `StudentRound.tsx`, `StudentMail.tsx`, `style.css`, 최신 작업일지.

## 사용자와 설계안

- 사용자 과업: 교사는 상태 확인에서 한 학생의 기록을 읽거나 도움 요청·쪽지 문제·접속 지원 중 하나를 빠르게 처리한다. 학생은 홈에서 다음 행동을 찾고 미션·쪽지에서 읽고 조작한다.
- 확인한 문제: 현재 교사 상태 확인은 학생 카드 최대 40개 뒤에 도움·대화·접속 업무가 한 페이지에 이어진다. 위쪽 바로가기는 먼 위치로 스크롤시키지만 현재 업무 경계는 보이지 않는다. 학생 CSS에는 범용 모바일 `.action-row button{flex-grow:1}`과 카드 버튼의 추가 margin이 남아 계획서 §4의 버튼 그룹 gap 원칙과 충돌한다. 미션 상세 제목의 초점 outline도 제거돼 있다. 계획서 §9는 최신 `상태 확인`·`정보 요청·삭제` 메뉴와 배정 확인을 기술하지 않는다.
- 구성: 교사 메뉴 `운영 요약 → 시즌 설정 → 배정 확인 → 입장 카드 → 상태 확인 → 지난 활동 → 정보 요청·삭제`를 유지한다. 상태 확인 내부는 `학생 기록 / 도움 요청 / 쪽지 관리 / 접속 지원`의 과업 선택 버튼과 한 번에 하나의 패널로 나눈다. 도움 요청이 있으면 첫 진입은 도움 요청, 없으면 학생 기록이다. 운영 요약에서 도움·쪽지 카드를 누르면 상태 확인의 해당 업무를 열게 한다. 서버 조회·안전 작업은 기존 계약을 유지한다.
- 학생: 공통 760px 읽기 폭·24px 섹션 간격을 유지하고, 모바일의 주 버튼은 한 행 전체 폭, 보조 버튼은 다음 행에서 내용 길이대로 흐르게 한다. 학생 카드 안 버튼의 별도 margin을 없애고 부모 gap으로 통일한다. 미션 상세 제목의 프로그램 초점은 보이게 한다. 작은 화면에서 문장 줄바꿈을 유지한다.
- 상태: 교사 과업 선택의 `aria-pressed`와 제목·로딩/오류/빈 상태를 각 패널에서 알린다. 안전 원문은 탭 이동 시 가린다. 탭 이동 후 초점을 해당 패널 제목으로 이동한다. 모바일은 과업 선택 2열, 320 CSS px/확대에서는 한 열 허용. 학생의 기존 제출·저장 동작은 그대로 둔다.

## 발견 사항과 조치

| ID·심각도 | 문제 → 근거 → 영향 | 수정안 → 확인 방법 |
|---|---|---|
| DP-01 P1 | 한 화면에 학생 카드·안전·쪽지·접속을 이어 붙임 → H6/H8 → 40명에서 업무 탐색에 긴 스크롤 | 과업별 한 패널, 운영 요약에서 정확한 패널로 이동 → 40명 가상 화면·키보드·전환 확인 |
| DP-02 P1 | 안전 원문이 상태 내부 이동 후 남음 → 비밀 유지/H5 → 옆 업무에서 원문 노출 | 패널 이동 시 원문 상태 초기화 → 열람 후 탭 전환 확인 |
| DP-03 P2 | 모바일 버튼이 같은 행에서 임의로 늘고 카드 버튼 margin이 gap과 중첩 → H4/H8 → 행동 위계·간격 불안정 | 학생 전용 버튼 그룹 규칙 → 320/390/768px 긴 버튼 확인 |
| DP-04 P2 | 미션 상세 제목의 focus outline 0 → UI-02/H3 → 키보드 위치를 잃음 | 보이는 프로그램 초점 복원 → Enter/Tab/닫기 경로 확인 |
| DP-05 P2 | 계획서 §9의 교사 메뉴 기술이 현재와 다름 → H2/H4 → 이후 구현 기준 혼동 | 본 계획서 하단에 변경된 메뉴·화면·검증 결과 누적 → 문서/화면 대조 |

- 의견 충돌: 도움 요청을 별도 상위 메뉴로 다시 만들면 발견성은 좋지만 사용자가 안전 확인 메뉴 삭제를 요청했다. 운영 요약 카드와 상태 확인 첫 진입 우선 선택으로 해결한다.
- 착수 판정: 여섯 관점 모두 위 설계 통과. DP-01/02의 P1은 설계에서 해결했고 구현 전 미해결 P0/P1 없음. DP-03~05 P2는 이번 수정에서 처리·검증한다.

## 구현 후 검토

실제 변경: 상태 확인의 네 업무 버튼은 한 패널만 표시하고 운영 요약의 도움·쪽지 카드가 해당 업무를 선택한다. 업무를 바꾸면 열어 둔 민감 쪽지 원문과 도움/검토 상세를 가린다. 학생 화면의 모바일 주 버튼·보조 버튼 폭과 카드 버튼 간격을 학생 영역에서 조정하고 미션 상세 제목의 초점 테두리를 복원했다. 사용자·서버 데이터 계약은 바꾸지 않았다.

| 환경·폭·입력 방식 | 경로·상태·재현 순서 | 결과와 증거 | 남은 확인 |
|---|---|---|---|
| 로컬 Vite 첫 화면 | `/` 새 탭 로드 | 학생 카드 로그인 입력 2개와 주요 버튼 표시, 빈 화면·Vite 오버레이·브라우저 콘솔 오류 0 | Firebase 인증 후 전체 흐름 |
| 가상 콘텐츠 320/360/390/768/1280px | 교사 40명 카드와 네 업무 선택, 학생 홈/미션 상세 | 문서 가로 넘침 0. 교사 카드 1/1/1/2/3열, 업무 선택 1/1/2/4/4열, 학생 메뉴 2/2/2/4/4열. 320~390px에서 학생 주 버튼이 카드 읽기 폭을 채움 | 실제 기기·200% 글자 확대 |
| 로컬 가상 미션 상세·키보드 | 제목을 프로그램 방식으로 초점 이동 | 실제 H3 초점의 outline이 `solid`이고 다음 Tab이 주 행동으로 이동 | 인증 후 상세 진입·닫기 복귀, VoiceOver |
| 코드·자동 확인 | TypeScript/Vite, 함수 단위, Rules, 통합 | 빌드와 함수 단위 12건, Rules 13건, 가상 두 시즌·40명 통합 3건 통과 | 배포된 승인 교사 화면 |

| 프로파일 | 구현 후 개별 판단 | 판정 |
|---|---|---|
| WD-01 | 한 업무 선택과 한 본문 패널로 시선 순서를 단순화했다. 학생 모바일의 주 버튼은 보조 버튼보다 넓고 일관된다. | 로컬 통과 |
| WD-02 | 가상 40명·긴 문장과 다섯 폭에서 열 수와 가로 넘침을 확인했다. 고정 높이로 문장을 자르지 않았다. | 로컬 통과 |
| UX-01 | 운영 요약→도움/쪽지 정확한 업무 진입, 상태 확인의 네 과업 경계를 구현했다. 종전 안전 업무를 삭제하지 않았다. | 코드·로컬 통과 |

- 완료 판정: 변경 범위의 P0/P1/P2 설계·로컬 화면 결함은 해결. 실제 승인 교사 인증 화면에서 네 업무 전환과 원문 가리기, 200% 확대·VoiceOver·현장 사용성은 미확인으로 별도 검증한다.
