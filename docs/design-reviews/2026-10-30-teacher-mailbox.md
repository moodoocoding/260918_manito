# 전문가 검토 기록: 교사에게 보내는 비밀 우체통과 단계별 사건 신고

## 검토 정보

- 날짜: 2026-10-30. 사용자 명시 요청으로 서브 에이전트를 활용한다.
- 수행: `/root`가 여섯 가상 프로파일을 적용하고 `/root/teacher_mail_ui`가 학생 UI, `/root/teacher_mail_inbox`가 교사 UI, `/root/teacher_mail_backend`가 데이터/권한을 별도로 검토한다. 외부 인간 전문가 참여/승인은 없다.
- 자료: 사용자 요구, `StudentClassroom`, `main`, `StudentMail`, `StudentRound`, `TeacherRounds`, Firebase 인증/학생 세션 검증/교사 소유권/삭제·공개 함수, 스키마·API·개발 계획, 운영 지침과 6개 프로파일.
- 범위: 마을 ‘비밀 우체통’은 담당 교사에게 보내는 편지/신고 두 선택으로 바꾼다. 기존 마니또 친구 간 쪽지 API/역사 기록은 별도 보존한다. 회차와 무관한 학급 수신함을 추가하며 교사 답장·미디어·다른 학급 연락은 추가하지 않는다.

## 요구사항·사용자 과업·화면 구성

- 학생: 우체통 앞 이동/상호작용 → 편지 보내기 또는 신고하기 → 입력 → 확인/수정 → 담당 교사에게 제출 → 접수 결과 → 마을 복귀.
- 편지: 제목(선택80자), 내용(필수4000자), 마지막 확인. 수신자를 학생이 선택하지 않는다.
- 신고: (1) 누가: 관련 학생 모두, 자유입력 복수 이름 최대40명 (2) 언제: 자유입력200자 (3) 어디200자 (4) 무엇을/어떻게: 사건 상황 필수6000자, 줄바꿈 보존 (5) 왜: 선택1000자, 이유를 몰라도 괜찮다는 문구 (6) 목격학생 최대40명: 이름/다른반 여부/다른반이면 반 필수 (7) 현재 감정1000자 (8) 원하는 조치1000자 (9) 필요한 도움1000자 → 최종 확인. 나머지 항목은 모름/없음/건너뛰기를 허용한다. 명부 조회/다른 학생 선택 목록을 노출하지 않는다.
- 첫 선택은 두 큰 카드, 입력은 한 단계 한 과업, 단계번호/간결한 진행 표시, 이전/다음과 검토 시 항목별 수정 제공. 9개 탭을 가로 나열하지 않는다.
- 교사: 학급 메뉴 ‘학생 편지·신고’ → 기본 신고/접수 목록 → 원문 확인(감사 조회) → 처리 기록/완료. 시즌이 없어도 사용할 수 있다. 편지/신고, 접수/처리 완료를 필터로 분리하고 원문·제목은 요약 목록에 미리 표시하지 않는다.
- 작성 중 이탈은 버리기 확인, 단계 이동은 메모리 초안 보존. 브라우저 저장소/URL/로그에 이름·원문·감정을 기록하지 않는다. 학생 전환/로그아웃에서 초안과 요청 상태 제거. 보내기 전까지 서버 저장 없음.

## 계약·상태·권한

- 학급 하위 서버 전용 `teacherMailSecrets`, 멱등 명령, 학생 영수증을 분리한다. 수신 담당 교사는 서버에서 학급 소유권으로 결정한다. 직접 Firestore 읽기/쓰기 권한을 추가하지 않는다.
- `createTeacherMail({kind,letter?:{subject,body},report?:{relatedStudents,occurredAt,location,incident,reason,witnesses:[{name,otherClass,className?}],feelings,desiredAction,neededHelp},requestId}) → {mailId,status:'received'}`. 정규화된 전체 payload의 fingerprint와 요청ID를 묶어 중복 제출/내용 바꾼 재사용을 막는다.
- `listMyTeacherMail({cursor?}) → {items,nextCursor}`: 본인 영수증만, 이름/원문 없음. `listTeacherMail({classId,kind,status,cursor?}) → {items,nextCursor}`: 담당교사 감사 요약20건. `getTeacherMail({classId,mailId})`: 별도 감사 원문 조회. `resolveTeacherMail({classId,mailId,resolution,requestId})`: 내부 처리 기록(최대1000자), 멱등 완료. 상태는 `received|resolved`다. 읽었음을 사건 해결로 간주하지 않는다.
- 모든 쓰기는 현재 유효 카드/학생 소속·sessionVersion 또는 확인된 교사·학급 소유권을 트랜잭션에서 재검증한다. 타학생/타학급/타교사 차단. 명단의 학생 UID를 입력받아 수신자를 임의 선택하지 않는다.
- 회차를 벗어난 신고도 미처리이면 해당 학급 정체 공개 전에 확인/처리하도록 공개 검사에 포함한다. 학생 화면에는 신고자/신고 수/낙인 정보가 없다. 학급 삭제의 recursiveDelete 범위에 신규 컬렉션 포함을 확인한다.
- 상태: 선택/입력/검토/전송 중/접수 성공/오류/교사 목록 로딩·빈 목록·조회 실패·상세·처리 중/완료. 실패하면 원문을 보존하고 같은 내용의 재시도는 같은 요청ID로 보낸다. 입력을 고치면 새 요청ID 사용. 미리보기 전송은 실제 제출과 혼동하지 않도록 명시하며 실제 API를 호출하지 않는다.
- 반응형: 학생 최대860px 한 과업 카드, 390px 한 열·48px 조작, 긴 이름/본문 줄바꿈. 교사도 목록/상세를 세로 읽기 순서로 배치. 360/390/768/1280px 실제 화면과 키보드·오류·재시도·최대 입력 확인.

## 구현 후 검토

- 실제 구현자: 학생 컴포넌트/CSS는 `/root/teacher_mail_ui`, 교사 컴포넌트/CSS는 `/root/teacher_mail_inbox`, Functions/규칙/인덱스/서버 시험은 `/root/teacher_mail_backend`, 실제/예시 라우트·초안/종료 방어·문서·브라우저 검증은 `/root`다. 공유 프런트 타입은 대소문자 파일 해석 충돌을 피하도록 `teacherMailTypes.ts`로 정리했다.
- 기존 친구 쪽지는 `/student/friend-mail`에서 같은 `StudentRound view=mail`로 보존한다. 실제 우체통은 `/student/mail`, 회차와 무관하게 신규 Callable에 연결한다. 교사 수신함은 학급 메뉴 `mailbox`다. 로그아웃/학생 전환은 신규 초안과 busy ref도 초기화한다. 권한/인증 만료는 안전한 재입장 안내와 종료로 처리한다.
