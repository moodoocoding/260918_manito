# 오늘 할 일 실제 Schooldoc 연동 검증

## 범위와 수행

2026-10-30 사용자가 실제 검증을 요청하고 사용할 학생 한 명을 직접 지정했다. 이름은 이 기록·URL·스크린샷 파일명에 보존하지 않는다. Codex가 기존 Schooldoc 공개 페이지와 실제 client/컴포넌트를 대조한다. 기존 서버·DB 구조·설정·인증 정책을 변경하지 않는다. 이름과 학생 정보는 화면 메모리만 사용한다.

실제 앱은 학생 로그인이 없어 카드로 로그인할 경로를 사용자에게 안내했다. 이와 별개로 학생 자격이 이름인 기존 Schooldoc 공개 API의 조회/저장 검증을 진행한다. 임시 로컬 전용 검사 진입점은 실제 `StudentTodayTasks`와 `schooldocMissionsClient`를 사용하고 수동 이름 입력을 받는다. 이 페이지는 Schooldoc 공개 권한만 검사하며 Firebase 로그인·자동 이름 전달 검증과 구분한다. localhost·개발 모드에서만 열고 완료 뒤 임시 진입점 파일을 제거한다. 가상 client를 실제 연동으로 보고하지 않는다.

## 검사 절차와 결과

1. 원본 공개 페이지에서 지정 학생 조회: 성공. 현재 할 미션1건·전체12건·완료표시3건, 현재 미션은 미표시 상태를 확인했다.
2. 우리 실제 client/컴포넌트 조회: 성공. 원본과 현재 미션/기간/현재1·전체12·완료3이 일치했다. mock이 아닌 기존 공개 함수 응답이다.
3. 우리 화면 완료 표시 → 원본 새로고침 대조: 성공. reported 저장 뒤 우리 화면/원본 모두 현재0·완료4를 표시했다.
4. 원본에서 완료 취소 → 두 화면 재조회: 성공. 두 화면 모두 현재1·완료3과 해야 할 일 상태로 돌아왔다.
5. 기존 Firebase 카드 로그인과 이름 자동 연결: cloud 연결을 수정한 뒤 사용자가 기존 카드로 ‘로그인 성공’을 확인했다. 실제 `/student` 마을에서 건물 이동/상호작용 → `/student/today-tasks`로 진입해 추가 입력0개·지정 학생 일치·실제 미션 자동 표시를 확인했다.
6. 실제 로그인 화면에서 완료→내용·취소→취소→새로고침: 성공. 매 요청 getStudentHome 재검증을 거친 상태에서도0/4→1/3으로 돌아왔고 서버 재조회 뒤 해야 할 일 상태가 유지됐다. 완료/취소 후 미션 제목, 새로고침 후 새로고침 버튼으로 초점이 복귀했다.

검증 동안 완료/취소 왕복은 공개 client 검사1회와 실제 학생 로그인 검사1회, 총2회다. 최종 미션 상태와 요약을 복원했다. 정상 서버 변경 이력은 삭제하거나 덮어쓰지 않았다. 다른 학생·지난 미션 상태는 수정하지 않았다.

처음 원본 진입은 검증 학생이 특정되지 않아 자동 승인 검토가 차단했다. 사용자가 학생을 직접 지정한 뒤 원본 진입/조회가 허용되어 성공했다. 차단을 우회하지 않았다.

## 기존 마니또 카드 로그인 연결 오류

사용자가 기존 카드로 로그인되지 않는다고 보고하고, 기존 마니또 DB/카드 인증을 그대로 사용하라고 명시했다. 원인은 로컬 Vite가 `.env.local`의 `VITE_USE_EMULATORS=true`, `VITE_FIREBASE_PROJECT_ID=demo-manitto`를 사용했고9099/8080/5001 에뮬레이터가 실행되지 않은 것이었다. 기존 DB의 카드가 틀렸다는 근거는 없다. 서버 코드의 loginStudent/classCodes/studentCredentials 검증 경로를 변경하지 않는다.

수정안: 기존 개발 클라우드 manito-938cc의 공개 Firebase 웹 앱 설정을 공식 CLI로 확인하고, git 제외된 cloud 모드 설정으로5175 서버만 재시작한다. 에뮬레이터 설정은 보존하고 DB 생성/이전·함수/Rules 배포·카드 재발급은 하지 않는다. API 키 값/카드 코드/학생 이름은 기록에 출력하지 않는다.

| 관점 | 개별 사전 판단 | 판정 |
|---|---|---|
| WD-01 | 시각 변경 없음. 승인 UI와 검사 표면이 그대로인지 실제 로그인 화면으로 확인한다. | 통과 |
| WD-02 | 레이아웃 변경 없음. 서버 재시작으로 사용자 입력이 사라질 수 있으므로 한 번 명시하고 이후 화면 크기 변경을 멈춘다. | 통과 |

6개 관점 통과, 미해결 P0/P1 없음. 로컬 연결 설정 변경이며 기존 클라우드 DB나 접근 권한 변경이 아니다.

재발 방지를 위해 `dev:web:cloud`/`dev:cloud` 실행 명령과 cloud 모드의 프로젝트·Emulator 미사용 검사를 추가한다. WD-01/WD-02는 화면 비변경, UX-01/UX-02는 같은 카드로 접속할 실행 경로의 명확성, UI-01/UI-02는 잘못된 프로젝트로 실행될 때 빠르게 차단되는 근거로 각각 통과했다. cloud 설정이 없거나 demo 설정이 섞이면 서버가 실행되지 않도록 확인한다.

다른 채팅의 main 수정이 Vite 전체 재로드를 일으키는 것이 서버 출력에 확인됐다. 사용자의 로그인 입력을 보존하기 위해5175는 cloud 모드의 고정 빌드 스냅샷을 별도 임시 디렉터리에서 제공한다. 위 여섯 관점은 화면 변경 없이 기존 로그인/초점을 보존하고 테스트 중 자동 재로드를 막는 조치로 각각 재확인했다. 부모의 dist/다른 포트 빌드와 충돌하지 않는다.
