- 날짜 / 대상 설계 버전 또는 커밋: 2026-10-30 / 사전 설계 v1

## 사용자와 설계안

- 대상 사용자·이용 환경·핵심 과업: Google 계정으로 인증된 초등 교사가 공용 데스크톱/태블릿/모바일에서 기존 학급을 선택·관리하고 서비스별 운영으로 이동한다.
- 현재 문제와 재현 조건: 사용자 보고상 메인에 ‘선생님 방’ 진입점은 있으나 기존 교사 화면은 마니또 관리 중심이다. 코드상 `/teacher`에 학급 목록과 기능이 이미 있고, 클래스별 메뉴에 학생 카드·시즌·쪽지·배정·상태·지난 활동·설정이 있다. 서비스 모음 구조와 기능 준비 상태 표현은 확인되지 않았다.
- 페이지·섹션 구성과 이동 경로:
  1. `/teacher`: Google 로그인/승인 상태 또는 선생님 방 홈. 첫 화면에서 학급 목록·만들기와 선택된 학급 요약을 보여준다.
  2. 학급 공통 관리: 학급 정보·코드, 학생 명부, 입장 카드 기능을 기존 구현 그대로 제공한다.
  3. 서비스 모음: 마니또는 운영 가능 카드, 비밀 우체통·오늘 할 일·우리반 게시판/자리바꾸기는 각 구현 상태를 조사해 연결 가능/준비 중을 구분한다. 미연결 관리 기능은 눌러도 준비 상태 및 범위를 알 수 있게 한다.
  4. 서비스 운영: 현재 마니또 기존 회차·안전·기록 화면으로 연결한다. 학급 선택과 서비스 선택은 별도 단계로 인지시킨다.
- 각 화면의 목적·주요 행동·저장 범위: 기존 Firestore 학급/학생/카드/시즌 데이터를 재사용한다. 신규 서비스 사용 여부 저장이나 기존 학생 영향은 구현하지 않는다.
- 기본·빈 상태·로딩·오류·완료와 취소·복귀: 로그인, 승인 대기/정지, 학급 없음, 로딩, 권한/네트워크 오류를 구분한다. 복귀는 학급/서비스 홈으로 제공하고 기존 미저장 시즌 이탈 확인을 보존한다.
- 반응형·긴 텍스트·최대 항목·키보드 설계: 공통 월드 프레임·헤더·종이·버튼 토큰을 교사 업무 밀도에 맞춰 사용한다. 배경 풍경을 남기고 프레임 최대 1200px, 모바일 한 열/헤더 재배치, 긴 학급명 줄바꿈, 학급 목록 검색, 키보드 초점 표시를 적용한다.

## 구현 후 실제 검증

### 학급 개설 위치 보완 사전 검토 · 사용자 추가 요청

- 요구사항·현재 문제: 사용자는 마니또가 하위 서비스가 된 뒤에도 학급 개설의 소속이 마니또처럼 보인다고 지적했다. 현재 개설 폼은 `/teacher`에 있지만 내부 메뉴에는 학급 목록·개설이 없고, 개설 직후 서비스 모음으로 이동해 공통 준비와 서비스 운영의 경계가 약하다.
- 과업·구성: 선생님 방의 `학급 공통 관리 → 내 학급 / 새 학급 개설 → 학생·입장 카드`를 공통 준비 흐름으로 둔다. 마니또 메뉴는 회차 운영만 유지한다. 서비스 모음은 별도 `학급 서비스` 그룹으로 표시한다. 기존 createClass 입력·저장 경로·classId는 보존한다.
- 상태·반응형: 개설/목록을 한 번에 펼치지 않고 전환하며 취소는 내 학급 목록으로 복귀한다. 기존 오류·진행 중·멱등 요청을 유지한다. 좁은 화면에는 버튼을 줄바꿈하고 폼 한 열, 키보드로 전환·취소·입력을 확인한다.

- 발견 P1-4(개설 소속 혼동)는 공통 메뉴·분리된 개설 폼·생성 후 학생 등록 착지로 조치했다. P2-1은 검색/긴 이름/반응형 검증으로 처리했다. P2-3/4는 단일 h1과 공통 서비스 레지스트리로 처리했다.
- React 검토: 정적 서비스 목록은 컴포넌트 밖에 유지했고 새 구독/영구 저장소를 추가하지 않았다. 가상 fixture는 DEV 조건으로만 활성화하며 저장·민감 조회를 차단한다. 독립 조회는 기존 Promise.all을 유지한다. TypeScript/Vite 빌드는 통과했으며 기존 큰 JS 청크 경고는 남는다.
- 현재 판정: 공통 학급 개설 재배치와 가상 화면 구현/브라우저 확인 완료. 전체 운영 검증 완료로 보지 않는다. 실제 Google 로그인/복원·현장 접근성·실제 교사의 최대 명부 조작은 미확인이며 UI-02의 전체 판정은 보류한다.
- 남은 항목: UI-02가 후속 접근성 검증에서 200% 확대·화면 읽기·실기기 입력을 확인한다. Google provider 보강 배포와 실제 Google 계정 회귀는 별도 승인된 배포/검증에서 수행한다. Firebase/Vercel 배포·GitHub 푸시는 수행하지 않았다.
