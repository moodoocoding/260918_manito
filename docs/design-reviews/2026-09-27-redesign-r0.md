- 대상: [디자인 수정 계획서 v1.0](../design-revision-plan.md)의 R1~R3. 기준 코드 `0e9275c`.
- 수행: Codex 한 에이전트가 [6개 가상 전문가 프로파일](../experts/README.md)을 각각 적용한 역할 기반 설계 검토. 외부 자문이나 실제 사용자 시험은 아니다.
- 입력: 현행 코드, [이전 진단](2026-09-27-ui-ux-audit.md), 실제 교사 40명 가상 화면의 배치 관찰, 서버 함수 계약. 이 기록은 **구현 전 설계**에 대한 판단이며 구현 검수는 뒤에 별도로 남긴다.

## 과업과 화면 구성 확정

교사는 `내 학급 → 운영 요약 → 학생·카드 / 회차 / 안전 확인 / 지난 활동 / 학급 설정`으로 이동한다. 학급 선택 후 첫 화면은 운영 요약이다. 안전 확인은 명시적 메뉴이며, 회차 화면은 목록과 준비·운영 상세로 구분한다. 학생은 `오늘 / 우편함 / 지난 활동`을 기본 메뉴로 사용한다. `선생님 도움`과 `활동 마치기`는 어느 화면에서든 헤더에서 찾을 수 있다. 정보 요청은 도움 화면의 독립 섹션이다. 메뉴 전환으로 이름·쪽지 원문·카드 코드가 다른 과업 화면에 남지 않도록 각 상세는 전환 시 닫고, 새로고침은 인증·서버 권한을 다시 확인한다.

### 교사 운영 요약 · 1280px 내용 시안

```text
우리 반 비밀친구  [가상 검증 학급 ▾] 2026 · 5~6학년                   로그아웃
운영 요약 │ 학생·입장 카드 │ 회차 │ 안전 확인 │ 지난 활동 │ 학급 설정
────────────────────────────────────────────────────────────────────────
운영 요약                         진행 중인 활동: 가상 배려 작전 2
먼저 확인해 주세요
[도움 요청 1건 · 안전 확인으로]       [검토할 쪽지 0건 · 안전 확인으로]
접속·활동 지원                     일정
학생별 비공개 현황 보기             9월 28일~10월 9일, 수업일 5일
[진행 회차 자세히 보기]
```

390px에서는 브랜드/학급/로그아웃 아래에 `학급 메뉴` 버튼과 현재 페이지 제목을 두고, 도움·쪽지 두 카드를 세로로 쌓는다. 본문 첫 화면에 명부·설정 폼을 펼치지 않는다. 회차가 없으면 ‘학생 등록 후 새 활동을 준비해 주세요’와 한 개의 다음 행동을 보여준다. 조회 실패를 `0건`으로 위장하지 않고 이 영역에서 재시도한다.

### 교사 회차 준비 · 390px 및 1280px 내용 시안

```text
새 활동 준비 · 아직 저장 전            (데스크톱: 본문 폭 최대 840px)
1 기본 정보 / 2 참가자·제외 / [3 미션·쪽지] / 4 확인·저장
이번 활동에서 사용할 미션을 3개 골라 주세요.                       선택 2/3
[☑ 친구의 의견을 듣고 이해한 내용을 되짚어 말하기]
[☐ 친구가 부담스럽지 않은 방식으로 도움 제안하기]
쪽지는 어떻게 쓸까요?
(●) 준비된 문구로만 보내기
( ) 직접 쓰기도 허용하기 · 선생님 검토 후 전달
[이전] [확인 단계로]
```

390px에서는 미션 한 열, 1280px에서도 긴 문장을 고려해 최대 두 열이다. 한 선택 항목은 `label` 전체가 클릭 영역이며 체크박스는 첫 줄 앞에 12px 이상 크기로 놓고 텍스트와 8~12px 간격을 둔다. 행은 문장 길이에 따라 늘어난다. 참가자는 짧은 별도 그리드다. 4/23/40명과 긴 이름·문장으로 검증한다. 수업일은 `date` 입력으로 하루씩 추가·제거하고 5/10일을 표시한다. 마지막 단계에서만 서버에 전체 설정을 저장하며, 앞 단계의 `다음`은 메모리 이동이다. 이전/다음/이탈 취소로 입력을 보존한다. 새로고침 전에는 저장되지 않은 입력이 사라질 수 있음을 명시한다. 새 초안 생성 후 조회로 복귀하고, 저장된 초안은 다시 선택해 편집한다.

### 학생 오늘 · 390px 및 1280px 내용 시안

```text
우리 반 비밀친구            [선생님 도움] [활동 마치기]
안녕, 가람! · 가상 검증 학급
내가 챙겨줄 친구  [친구 보기]  (기본은 •••, 탭 복귀도 가림)
이번 활동의 미션
친구의 말을 끝까지 들어 보기
[해냈어요] [다른 미션] [쉬기]
오늘 ●       우편함       지난 활동
```

1280px에서도 학생 콘텐츠는 가운데 약 640px 열이다. 한 과업의 설명·행동은 같은 카드에 둔다. 학생용 ‘회차’ 대신 ‘활동’을 쓴다. 일시정지: ‘지금은 활동을 잠깐 쉬고 있어요.’, 공개 대기: ‘활동이 끝났어요. 선생님이 친구 공개를 준비하고 있어요.’, 수업일이 아님: ‘오늘은 쪽지를 쉬는 날이에요.’를 각 관련 위치에 보여준다. 서버가 다음 허용 날짜를 주지 않는 동안 날짜를 임의 추정하지 않는다. 도움 사유는 ‘걱정되는 일 / 쪽지 때문에 불편해요’를 먼저 선택하고 설명은 선택 사항이다. 1~2학년의 회고는 검토된 짧은 선택 문구, 3~4학년은 문장 틀, 5~6학년은 선택적 자유 입력으로 설계한다. 현재 API가 학년군을 내려주지 않으므로 연령별 표현 활성화는 안전한 학년군 응답이 구현된 뒤에 한다.

## 상태·저장·안전 동작

| 상황 | 화면 행동 | 데이터·복구 |
|---|---|---|
| 저장 전 회차 준비 이탈 | ‘계속 작성 / 입력 버리고 이동’ 확인, 안전한 쪽에 기본 초점 | 서버 저장 아님. 다른 학급 내용과 혼합 금지 |
| 설정 저장 성공/실패 | 마지막 검토 단계의 해당 버튼 아래 결과 표시 | 서버 성공 후에만 ‘저장됨’; 실패 시 입력 유지·같은 작업 ID 재시도 |
| 공개·취소·중단·카드 재발급 | 대상·영향·되돌릴 수 있는지 확인 창, 취소가 먼저 선택됨 | 확인 전 서버 호출 없음; 성공 후 재조회/정리 |
| 처리 성공 후 목록 재조회 실패 | ‘처리는 완료됐어요. 최신 목록을 다시 불러와 주세요.’ | 같은 명령을 무심코 재전송하지 않음 |
| 미션·쪽지·도움 | 작업 중 중복 제출 차단, 결과를 같은 카드에 표시 | 서버 상태를 재조회; 정상 빈 상태와 오류 구분 |
| 교사 안전 원문·배정표 | 별도 열기, 닫기, 탭 이탈·회차 전환 때 즉시 가림 | 조회에는 기존 감사 기록 유지 |
| 공개된 학생 관계 | 보기 전 가림, ‘다시 가리기’, 탭 복귀·과거 기록 재진입 때 가림 | 접근 권한과 화면 가림을 따로 관리 |
| 인증 만료·로그아웃 | 비어 있는 입장 화면과 짧은 설명 | 기존 메모리 상태·구독·화면 정보 제거 |

사용자 과업과 서버 계약을 구분한다. 요약 첫 화면은 `listRounds`의 제목·상태·날짜와 선택 회차의 `getTeacherRoundOverview`만 사용하며 다른 회차 원문을 일괄 적재하지 않는다. 상태 사유·학년군·회고 복원·감사 완료처럼 응답이 부족한 항목은 별도 API 변경과 테스트 뒤에만 표시한다. 학생의 활동일은 서버가 준 `activityDates`로 표시하되 기기 시간을 권한 근거로 사용하지 않는다. 서버가 허용한 최종 판단이 우선이다.

## 6개 관점의 사전 재판정

| 프로파일 | 이번 설계 판단과 근거 | 남은 구현 확인 | 판정 |
|---|---|---|---|
| WD-01 | 교사는 안전 업무를 첫 화면에 두고 학생은 봉투·현재 미션을 우선 표시한다. 강한 코랄은 주요 행동에만 사용하고 본문/설명/빈 상태의 위계를 명시했다. H1·H8. | 실제 390/1280 화면의 시각 균형·빈/오류 상태 | 통과 |
| WD-02 | 미션 1~2열·내용 높이·라벨 전체 클릭, 참가자 별도 그리드와 320~1280 재배치 규칙을 확정했다. H4·H6·H8. | 긴 문장·40명·200% 확대·인쇄 실측 | 통과 |
| UX-01 | 업무별 메뉴, 회차 4단계, 저장 범위, 복귀·재인증, 요약의 현행 API 조회 범위를 확정했다. H2·H3·H7. | 브라우저 뒤로가기·학급 전환·저장 실패 재현 | 통과 |
| UX-02 | 학생의 ‘활동’ 용어, 상태별 안내, 도움 이유·학년군 표현과 교사의 선택 개수를 구체화했다. H2·H5·H10. | 실제 아동·교사 이해도 시험과 학년군 응답 확인 | 통과 |
| UI-01 | 위험 작업 확인, 미저장 이탈, 작업별 로딩·성공·실패·재조회, 선택 행 상태를 명시했다. H1·H4·H5·H9. | 키보드·느린 응답·중복 제출·초점 복귀 실기 | 통과 |
| UI-02 | native 입력·명시적 라벨·44/48px 터치 목표·대비 4.5:1·가림·확대와 폭별 검수를 요구한다. H1·H3·H5. | 실제 키보드·VoiceOver·확대·대비 측정 | 통과 |

**착수 판정:** 위 사전 설계에서 미해결 P0·P1이 없고 6개 관점이 통과했다. DR-01~22는 현행 코드 결함이므로 R1~R3에서 해결하고 R4에서 재현 조건으로 확인한다. 이 판정은 설계에 한정하며, 코드가 아직 해결됐다는 뜻이 아니다. 서버 계약 의존 항목은 해당 구현 전에 범위와 데이터 노출을 다시 검토한다. P2도 변경 범위 안에서 완료 전 해결한다.
