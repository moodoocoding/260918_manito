## 1. 요구사항 및 현재 문제 진단

1. **학급 코드 난수 고정(8자리)**:
   - 현재는 학급 생성 시 무조건 8자리 난수(예: `7K9X2M4P`)로 발급되어 초등학생이 타이핑하기 어렵고 선생님이 기억하기 힘듦.
   - 선생님이 우리 반에 맞게 기억하기 쉬운 영문·숫자 코드(예: `SUN2026`, `HAPPY2`, `2026GRADE2` 등 4~12자)로 직접 설정하고 필요 시 수정할 수 있어야 함.
2. **학생 개인 카드 코드 길이 과다(12자리 `XXXX-YYYYYYYY`)**:
   - 초등학생(특히 1~4학년)이 교실 PC나 태블릿에서 12자리 영문 코드를 직접 입력하는 데 많은 시간과 오타가 발생함.
   - 학급 코드를 통해 학급 내에서 인증이 이루어지고 5회 실패 시 15분 잠금 장치가 있으므로, 4자리 영문/숫자 난수($32^4 = 1,048,576$가지)로도 완벽한 보안성을 확보할 수 있음.
   - 기존에 발급된 12자리 카드도 계속 로그인할 수 있도록 하위 호환성을 유지해야 함.

## 2. 6인 전문가 관점별 사전 검토

### WD-01 · 시각 구성과 브랜드
- **판단**: 통과 (P0/P1 없음)
- **근거**:
  - 학급 생성 모달 및 기본 정보 수정 폼에 추가되는 `학급 코드` 입력 필드는 기존 폼 컨트롤의 스타일과 배치를 계승하여 시각적 위계를 방해하지 않는다.
  - 학생 로그인 화면의 개인 카드 입력창은 4자리 입력에 맞춰 플레이스홀더를 `"카드에 적힌 4자리 코드 (예: 7K9X)"`로 정돈하여 학생에게 입력 분량에 대한 심리적 안정감을 준다.

### WD-02 · 반응형 레이아웃과 타이포그래피
- **판단**: 통과 (P0/P1 없음)
- **근거**:
  - 4자리 카드 코드는 인쇄 카드 및 화면 표시 시 글자 수가 적어 320px 모바일 화면에서도 폰트가 잘리거나 줄바꿈되지 않고 선명하게 노출된다.
  - 학급 코드(4~12자) 입력 필드 역시 모바일 폼 그리드(`form-grid` 또는 단일 열)에서 가로 넘침 없이 안정적으로 동작한다.

### UX-01 · 정보 구조와 과업 흐름
- **판단**: 통과 (P0/P1 없음)
- **근거**:
  - **학급 생성**: 선생님이 일일이 코드를 고민하지 않아도 되도록 기본 6자리 추천 코드를 미리 입력창에 채워두고, 원하는 경우 자유롭게 수정할 수 있게 한다.
  - **학급 정보 수정**: `정보 요청·삭제` 탭의 `학급 기본 정보 수정`에서 학급 코드도 수정할 수 있게 하되, "학급 코드를 변경하면 기존에 인쇄한 카드의 학급 코드도 함께 바뀌므로 학생들에게 새 코드를 안내해야 합니다"라는 주의 문구를 명시한다.
  - **학생 과업**: 12자리에서 4자리로 축소되어 학생 로그인 입력 시간이 70% 이상 단축된다.

### UX-02 · 인지 부담과 사용자 이해
- **판단**: 통과 (P0/P1 없음)
- **근거**:
  - 학급 코드 중복 시 `"이미 다른 학급에서 사용 중인 코드예요. 다른 코드를 입력해 주세요."`라는 명확한 한국어 오류 메시지를 반환한다.
  - 학생 로그인 시 4자리 코드든 이전 12자리 코드든 시스템이 자동으로 길이를 인식해 처리하므로 학생이나 교사가 버전을 구분할 필요가 없다.

### UI-01 · 조작과 컴포넌트 상태
- **판단**: 통과 (P0/P1 없음)
- **근거**:
  - 학급 코드 및 학생 카드 코드 입력 시 소문자를 자동으로 대문자로 변환하고 공백 및 하이픈을 자동 제거(`normalizeCode`)하여 입력 실패율을 최소화한다.
  - 중복 학급 코드 검증은 Firestore 트랜잭션에서 원자적으로 처리되어 동시 생성 시 충돌을 방지한다.
  - 학생 4자리 코드는 `scrypt` 해시(`secretHash`)와 단방향 색인(`studentCredentialLookups`) 및 Secret Manager 암호화(`encryptedCardCode`) 구조를 100% 동일하게 유지한다.

### UI-02 · 접근성과 화면 품질
- **판단**: 통과 (P0/P1 없음)
- **근거**:
  - 새로 추가되는 `학급 코드` 입력 필드에 명시적 `<label>`과 유효성 검사 안내(`4~12자 영문·숫자`)를 제공한다.

## 3. 종합 결론 및 구현 후 6인 전문가 재검토
- **사전 검토 결론**: 6개 전문가 관점 사전 검토 결과 미해결 P0·P1 문제 없음.
- **구현 후 재검토 결과**:
  - **WD-01 / WD-02**: 새 학급 만들기 폼 및 학급 기본 정보 수정 폼의 학급 코드 필드가 기존 폼 레이아웃과 일관되게 정렬되며, 학생 로그인 폼의 4자리 카드 플레이스홀더 안내가 모바일·데스크톱 화면에서 잘림 없이 노출됨을 확인.
  - **UX-01 / UX-02**: 교사가 학급 코드를 직접 지정할 수 있어 학생들에게 알기 쉬운 반 코드를 배부할 수 있고, 학생 개인 카드가 4자리로 축소되어 1~2학년도 5초 이내에 타이핑할 수 있게 됨. 또한 기존 12자리 카드도 `parseStudentCard`에서 자동 인식되어 기존 카드 소지 학생의 입장이 차단되지 않음을 확인.
  - **UI-01 / UI-02**: 중복 학급 코드 입력 시 트랜잭션 충돌 방지 및 친절한 안내 메시지가 동작하고, 학생 카드는 `scrypt` 해시 및 15분 잠금 보호 체계를 온전히 유지함.
  - **검증**: `git diff --check`, `npm run build`, `npm run test:functions`(12/12 통과, 4자리 파싱 및 12자리 구 카드 파싱 하위 호환성 검증 포함), `node --test tests/entry-card-qr.test.mjs`(1/1 통과) 완료.
