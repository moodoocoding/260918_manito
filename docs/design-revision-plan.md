## 1. 이번 개정에서 바꾸는 것

학생 화면은 버튼과 메뉴를 일부 조정했지만 **일관된 간격, 명확한 다음 행동, 많은 미션의 탐색, 시즌 전체의 맥락**을 함께 설계하지 못했다. 사용자의 ‘완성도가 떨어지고 불편하다’는 지적을 이번 개정의 출발점으로 삼는다. 기능 테스트 통과를 디자인·학생 이해도 통과로 대신하지 않는다.

이번 수정은 학생 화면의 외형과 정보 구조를 함께 다룬다.

1. 공통 헤더·본문 정렬, 제목·설명·카드·버튼의 간격을 학생 전용 규칙으로 정리한다.
2. `홈 / 미션 / 우편함 / 우리 반`으로 목적을 구분하고, 도움·활동 마치기는 공통 위치에 둔다.
3. 홈에서 시즌 일정, 내가 한 활동, 다음에 할 미션을 바로 이해하게 한다.
4. 다른 학생들의 실천은 **이름 없는 학급 활동 요약과 배려 아이디어**로 알려 준다. 개인별 완료 수·순위·미수행 명단은 제공하지 않는다.
5. 실제 내용과 모든 주요 상태를 넣은 시안 → 6개 관점 재검토 → 구현 → 실제 브라우저·학생 과업 검증 순서로 진행한다.

이 문서는 v1.0의 실행 계획을 최신 정책에 맞게 재편한 것이다. 최초 DR-01~22 진단의 근거와 당시 판정은 [최초 검토](design-reviews/2026-09-27-ui-ux-audit.md), 수정 결과는 [R1~R4 기록](design-reviews/2026-09-27-redesign-implementation.md)에 남아 있다. 과거 수치·화면 결함을 현재에도 재현된 것처럼 사용하지 않는다.

### 1.1 현재 구현과 이번 계획의 경계

| 구분 | 확인한 내용 | 이번 개정의 판단 |
|---|---|---|
| 이미 적용한 학생 UI | 오늘·우편함·지난 활동 분리, 도움 화면, 학생 본문 폭 제한, 일부 버튼 크기·색·패널 조정 | 조정 이력은 있으나 전체 완성도 충족의 근거는 아님 |
| 현행 기능 | 시즌당 미션 1~80개, 완료·교체·쉬기, 즉시 전달 쪽지·익명 답장, 도움·공개·회고 | 이 정책을 유지하며 사용 흐름 개선 |
| 현행 비밀 유지 | 공개 전 관계 이름 비노출. [별도 검토](design-reviews/2026-09-28-student-friend-secrecy.md)·최신 작업일지 기준 | 진행 중 이름·봉투 열기를 새 홈의 중심 요소로 되살리지 않음 |
| 이번 신규 계획 | 시즌 홈 요약, 개인 진행 요약, 미션 필터·탐색, 우리 반 소식, 교사 안내 | 개발 예정. 존재하는 API나 배포 기능으로 표시하지 않음 |
| 검증 범위 | 현재 작업 트리의 `main.tsx`, `StudentRound.tsx`, `style.css`, 활동 조회 코드, 작업일지·6개 프로파일 | 코드 기반 진단과 사용자 보고. 이번 턴에는 브라우저 재현·픽셀 실측·아동 관찰을 수행하지 않음 |

검토 시작 시 공개 전 비밀 유지와 관련된 별도 미커밋 변경이 있었고 이를 보존했다. 문서 작성 중 해당 작업의 커밋 `c0798d0`·배포 결과가 별도 작업일지에 기록됐다. 이번 문서 작업이 그 구현·배포를 수행한 것은 아니다. 2026-09-27의 버튼 대비 2.90:1, 교사 화면 6,637px, 깨진 체크 행은 **과거 관찰값**이며 이번 학생 화면의 현재 측정값이 아니다.

## 3. 정보 구조와 화면별 수정안

### 3.1 학생 탐색

```text
입장 → 활동 약속 → 홈
공통: [선생님 도움] [활동 마치기]
기본 메뉴: [홈] [미션] [우편함] [우리 반]
홈 → 지난 활동 → 지난 시즌 상세
홈/미션 → 미션 상세 → 완료·쉬기·교체 → 원래 위치
우편함 → 받은 쪽지 상세 → 답장·숨김·도움 → 원래 목록
우리 반 → 함께한 배려 요약 / 배려 아이디어 / 선생님 안내
도움 → 도움 요청·진행 상태 / 내 정보 요청
```

탐색 메뉴는 페이지 이동 링크로 구현하고 현재 페이지를 알린다. `우리 반`에는 학생 명단·관계·개인 프로필로 이동하는 링크를 만들지 않는다. 지난 활동은 홈에서 항상 같은 위치의 명시적 링크로 제공한다. 이름·관계·본문·개인 코드는 URL에 넣지 않는다. 기존 `/student/history`와 도움 진입 경로는 유지하고 이전 오늘 경로는 새 홈으로 연결한다.

### 3.2 홈 — 지금 할 일 이해하기

위에서부터 공통 탐색 → 짧은 인사·시즌명 → 상태/기간 → 내 기록 한 줄 → 선택한 미션 → 우리 반 소식 미리보기 → 지난 활동 링크 순서다. 큰 인사 카드와 별도 페이지 제목을 중복 배치하지 않는다. 우편함 쓰기 폼·도움 폼·회고 폼을 홈에 모두 붙이지 않는다.

```text
우리 반 비밀친구       [선생님 도움] [활동 마치기]
[홈]       [미션]       [우편함]       [우리 반]

안녕! 오늘도 편하게 참여해요.
함께 듣는 가을 · 활동 중
9월 28일 ~ 10월 12일 / 다음 쪽지 활동일 9월 30일

내 미션     해봤어요 3 · 골라볼 미션 5 · 쉬었어요 2

이번에 해볼 미션
친구의 이야기를 끝까지 들어 봐요.
[해냈어요]
[미션 골라보기]   [이 미션 쉬기]

우리 반 소식
9월 29일 아침까지 배려를 30번 이상 기록했어요.
기록하지 않은 배려도 소중해요.       [더 보기]

[지난 활동 보기]
```

위 수치는 **설계용 예시**다. 서비스에서 데모 수치를 실제 데이터처럼 표시하지 않는다. 미선택 상태의 주 버튼은 `미션 고르기`, 수행할 미션이 없는 상태는 `내 기록 보기`다. 390×844 기본 글자 크기의 진행 상태에서 첫 미션의 주요 행동까지 도달할 수 있도록 인사·설명 높이를 제한하되, 긴 텍스트나 확대에서는 자연스러운 세로 스크롤을 허용한다.

### 3.3 미션 — 1~80개 중 원하는 활동 고르기

- 위쪽: 내 기록 요약 → `골라볼 미션 / 해봤어요 / 쉬었어요` 상태 선택 → `전체 / 인사와 칭찬 / 경청과 대화 / 협력과 배려 / 감사와 응원 / 학급 미션` 범주. 좁은 화면에서는 범주를 연결된 라벨의 native select로 제공한다.
- 초기 8개, `8개 더 보기`로 확장. 총 결과 수와 펼친 범위를 표시한다. 결과 0개는 `다른 범주 보기`를 제공한다. 미션을 인기순·수행자 수순으로 정렬하지 않는다.
- 목록에는 짧은 범주·미션 문구·본인 상태·`이 미션 보기`만 둔다. 목록의 모든 카드에 완료/교체/쉬기 3개 버튼을 반복하지 않는다.
- 상세에는 문구, 안전한 예시, `이번에 해볼래요`, `해냈어요`, `이 미션 쉬기`를 문맥에 맞게 둔다. `이 미션 바꾸기`는 별도 보조 행동으로 두고 교체 횟수·가능 여부·원래 항목이 바뀐다는 안내와 확인을 제공한다.
- 골라보기·상세 열기는 활동 기록을 바꾸지 않는다. 이번에 할 미션 선택은 개인 선택 상태만 바꾸며 완료로 집계하지 않는다. 필터·스크롤·초점은 같은 세션의 목록 복귀 때 복원한다.
- ‘쉬기’는 해당 미션의 선택이고 시즌 참여 중단이 아님을 알려 준다. 되돌리기를 제공하려면 서버 상태 전이 계약을 먼저 추가한다. 현재 지원하지 않는 되돌리기 버튼을 먼저 만들지 않는다.

### 3.4 우리 반 — 서로의 실천을 알아보기

주요 콘텐츠는 `함께한 배려` 요약 1개, `이렇게 해볼 수 있어요` 예시 최대 2개, `선생님 안내` 1개다. 집계는 이름 없는 누적 기록의 거친 단위로 보여주고 기준 날짜를 함께 표시한다. 상세 규칙·표본 제한은 개발 계획서 §6.9를 따른다.

- 허용 예: ‘9월 29일 아침까지 배려를 30번 이상 기록했어요.’, ‘이야기를 끝까지 듣는 연습을 해볼까요?’
- 금지 예: ‘민수 8개’, ‘아직 3명이 안 했어요’, ‘우리 반 완료율 80%’, ‘방금 누군가 성공!’, 학급·시즌 간 우열 비교.
- 배려 예시는 검토된 콘텐츠다. 실제 집계가 없는 예시를 ‘친구들이 많이 성공한 미션’이라고 소개하지 않는다. 개별 미션 성공 순위·희소한 학급 미션 원문 자동 피드는 초기 범위에서 제외한다.
- 숫자 요약을 제공할 수 없는 4~9명 학급이나 기록 부족 상태에도 아이디어와 교사 안내를 보여준다. `0명`, `참여가 부족해요`, 더 참여하라는 안내를 대체 화면으로 쓰지 않는다.
- 이모티콘 투표·공개 칭찬 수·개인 반응은 추가하지 않는다. 교사 안내는 정해진 한 건을 읽는 기능이며 학생 게시판이 아니다.

### 3.5 우편함·도움·지난 활동

| 화면 | 수정안 | 주요 상태 |
|---|---|---|
| 우편함 | 받은 쪽지 기본, 보낸 쪽지 별도 보기, 쓰기 별도 단계. 첫 쪽지와 받은 쪽지 답장을 문구로 구분 | 전송 중/전달됨/이전 검토 대기/숨김/한도/비활동일 |
| 쪽지 상세 | 답장 주 행동, ‘고마워요’ 반응 보조, ‘숨기기’와 ‘선생님께 알리기’ 상시 명시. 답장 입력은 해당 원문 아래 | 200자 안내, 입력 보존, 오류·성공, 교사 숨김 즉시 반영 |
| 도움 | 사유 선택 → 선택 입력 → 접수. 내 요청 상태와 정보 요청 분리 | 접수됨/선생님 확인 중/처리됨; 즉시 응답 약속 없음 |
| 공개 결과 | 관계별 제목과 개별 눌러 보기·다시 가리기. 감사·회고는 결과 확인 뒤 별도 영역 | 승인 전 없음, 중단 관계 없음, 재진입·탭 복귀 시 가림 |
| 지난 활동 | 시즌 제목+기간+상태, 상세는 읽기 중심, 허용된 숨김·도움 유지 | 현재 시즌과 확실히 구별, 다음 시즌 기록 혼합 없음 |

새 쪽지 배지는 읽음/미확인 계약이 준비된 뒤 제공한다. 받은 쪽지 총수를 새 쪽지 수로 쓰지 않는다. 초기에는 홈의 우편함 링크만 제공해도 되며 읽음 확인을 상대에게 공개하지 않는다. 다량의 쪽지는 별도 목록 페이지 구분과 서버 페이지 조회를 함께 설계한다.

## 4. 학생 전용 시각 체계

### 4.1 간격과 정렬

색상을 바꾸기 전에 다음 규칙을 컴포넌트로 적용한다. 값은 프로젝트 설계값이며 모든 상황의 정답이라는 뜻은 아니다.

| 관계 | 320~599px | 600px 이상 | 적용 규칙 |
|---|---|---|---|
| 바깥 여백 | 16px, 320px은 12px 허용 | 24px | 헤더·탐색·본문의 시작선 일치 |
| 서로 다른 큰 섹션 | 24px | 32px | 부모 Stack의 gap만 사용 |
| 카드 안쪽 | 20px, 320px은 16px | 24px | 패딩과 외부 간격을 혼동하지 않음 |
| 제목↔설명 | 8px | 8px | 제목의 브라우저 기본 margin 초기화 |
| 설명↔본문/입력 | 16px | 16px | 안내와 입력을 하나의 그룹으로 유지 |
| 내용↔주 행동 | 24px | 24px | 버튼 margin과 부모 gap의 중복 금지 |
| 같은 그룹의 버튼/칩 | 8px | 8px | 균일한 gap, 글자 길이에 따른 줄바꿈 |
| 목록 항목 사이 | 12px | 12px | ul/li 기본 margin 초기화, 목록 자체 padding 명시 |

학생 헤더·메뉴·본문은 동일한 최대 폭 **760px**로 맞춘다. 넓은 화면에서도 글이 긴 미션과 쪽지는 1열로 읽게 한다. 미션 목록 카드만 충분한 폭과 실제 문장 길이가 확보될 때 최대 2열을 허용한다. 홈의 숫자 요약을 3개의 큰 카드로 늘려 여백을 채우지 않는다.

### 4.2 글자·색·캐릭터

- 페이지 제목 24~28px, 카드 제목 20px, 본문 17~18px, 보조 정보 14~16px, 본문 줄높이 1.55~1.7을 시작값으로 한다. 저학년 모드는 본문 18px와 짧은 문장·예시를 우선한다. 작은 화면이라고 핵심 글자를 축소하지 않는다.
- 크림 바탕+흰 과업 카드+코랄 주요 행동을 유지한다. 민트·하늘색은 범주나 부드러운 정보 배경에 제한한다. 하나의 카드 안에 여러 강조색·그림자·테두리를 중첩하지 않는다.
- 주요 버튼 기본 후보 `#B94440`/흰 글자 유지, 나머지 색·hover·disabled·focus는 실제 조합에서 별도 측정한다. 색 외에도 상태 글자·아이콘을 제공한다.
- 봉투 캐릭터는 환영·빈 상태·활동 완료에 작게 사용한다. 내용 높이를 밀어내는 큰 히어로, 자동 재생 축하 효과, 성과에 따른 캐릭터 성장·보상은 넣지 않는다.
- 모서리는 카드 20px, 입력·버튼 12px를 기본으로 정리한다. 간격 토큰은 학생 영역에 한정하고 교사 밀도를 함께 바꾸지 않는다.

### 4.3 버튼·폼

학생 주요 조작은 최소 48×48 CSS px, 일반 보조 조작은 44×44를 프로젝트 목표로 둔다. 긴 문구는 줄바꿈하고 높이는 늘어난다. 모바일 주 행동은 독립된 전체 폭 행, 보조 행동은 다음 행에서 같은 중요도끼리 배치한다. 빨간색은 일반 ‘쉬기’에 쓰지 않는다.

입력은 라벨·도움말·오류가 연결된 native 요소를 사용한다. 체크박스·라디오는 첫 텍스트 줄과 가까이 정렬하며 전체 라벨을 누를 수 있게 한다. 모든 label/input에 일괄 폭·패딩을 주는 선택자를 제거한다. 이는 최초 DR-01의 회귀 방지 기준도 겸한다.

위 44/48px는 자체 목표이며 WCAG AA 최소값으로 인용하지 않는다. 공식 기준은 예외를 포함한 24×24 CSS px이다. [W3C Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

## 5. 상태·복귀·오류 명세

| 상태 | 보이는 내용·행동 | 금지할 오해 |
|---|---|---|
| 최초 로딩 | 현재 과업 영역의 로딩 문구·자리 확보 | 다른 학생의 이전 카드 잠깐 노출 |
| 회차 없음/미참가 | 준비 안내 또는 이번 활동 쉬기, 도움·마치기 | 깨진 빈 카드, 다른 시즌의 집계 |
| 진행 중 | 서버 일정, 내 미션·요약, 사용 가능한 행동 | 완료 수가 실제 배려의 평가라는 표현 |
| 쪽지 비활동일 | 다음 쪽지 활동일, 허용된 미션은 계속 제공 | 쪽지 제한을 모든 미션 금지로 확대 |
| 일시정지 | 잠시 쉬는 중, 기록 읽기·숨김·도움 | 정지 이유·해당 학생 추정, 비활성 이유 누락 |
| 종료/공개 대기 | 활동 종료, 선생님이 마무리 중 | 자동 정체 공개 약속, 기기 시간으로 제출 허용 |
| 집계 미제공 | 배려 예시와 안내로 대체 | 기록 0 또는 참여 부족으로 단정 |
| 집계 조회 실패 | 해당 영역만 재시도, 나머지 개인 과업 유지 | 마지막 값을 현재 수치로 표시, 오류를 0으로 대체 |
| 저장 중/실패 | 실행 카드에 상태, 요청 ID 유지·결과 확인·재시도 | 성공으로 선반영한 도장을 확정처럼 유지 |
| 저장 성공+재조회 실패 | 저장은 완료됨, 화면 새로 확인 안내 | 중복 완료·쪽지 전송 유도 |
| 권한 상실/유휴 | 세션·구독·메모리 정리, 입장으로 복귀 | 브라우저 저장소에 초안/개인 상태 잔존 |

쪽지 작성 중 일반 페이지 이동에는 이탈 확인·취소를 제공한다. 입력은 현재 세션 메모리에만 보존한다. 로그아웃·권한 상실·5분 유휴 시에는 초안보다 세션 정리를 우선하며 자동 보존을 약속하지 않는다. 메뉴 이동 뒤 제목, 상세 닫기 뒤 원래 항목, 더 보기 뒤 새 항목 시작으로 초점을 예측 가능하게 둔다. 상태 알림은 과도하게 반복하지 않는다.

| SV-05 학급 정보 | 인원·기여자·기록 경계, 비공개/삭제/정지/이전 시즌 | 공개 가능한 집계만 전송, 대체 문구, 시점·학급·시즌 격리 |
| SV-06 쪽지 | 다수 수신·발신·답장·숨김·200자·한도 | 발신자 비노출, 원문과 답장 문맥, 입력 복구·결과 표시 |
| SV-07 접근성 | 키보드 전 경로, VoiceOver, 200%, 320 CSS px | 이름/역할/상태·초점·읽기 순서·대비·줄바꿈 확인. 자동 검사와 수동 결과 별도 |
| SV-08 공용기기 | 학생 A → 탭 복귀 → 로그아웃 → 학생 B → 뒤로 | 개인 요약·선택·초안·공개 이름·구독 모두 이전 사용자 잔존 없음 |
| SV-09 학생 과업 | 1~2/3~4/5~6학년 각 3명 이상을 계획값으로 모집, 교사 2명 | 미션 찾기/쉬기/도움/학급 수치 의미/마치기 관찰; 학년군별 혼란 재설계 |

관찰은 학교·보호자 안내와 참여 절차 확정 후 진행한다. 실제 학생에게 ‘익명 집계를 보고 누군지 맞혀 보라’는 식의 시험을 시키지 않는다. 정보 추론 검증은 가상 학급으로 먼저 한다. 위 표본은 초기 질적 점검 규모이며 교육 효과나 전체 아동 사용성의 통계적 입증이 아니다.

디자인 완료는 색상 만족도 투표로 결정하지 않는다. 실제 화면의 시각 판단과 학생이 다음 행동을 찾고 결과를 이해하는지를 함께 본다. 체류 시간·메시지 수·완료 수 증가를 개선의 성공 지표로 사용하지 않는다.

## 9. 기존 교사 계획과 재검증 의무 유지

교사 영역은 이번 변경의 직접 구현 범위가 아니지만 기존 개선 요구를 없애지 않는다. 다음 변경에서 아래 상태와 [작업일지](work-log.md)의 최신 근거를 확인한다.

- 운영 요약은 도움 요청 → 쪽지 대화 모니터링 → 접속·활동 지원 → 일정 순서. 이름별 성공 경쟁이나 미수행 낙인 없음.
- 시즌 준비는 기본 정보 → 참가자·제외 → 미션 → 쪽지 → 확인·저장 **5단계**. 미션 1~80개, 날짜 5/10/15/20 달력일 빠른 선택, 수업일은 현재 평일 자동 선택.
- 쪽지는 즉시 전달·익명 답장·합계 하루 10건·200자. 예전 대기 건만 검토. 최초 계획의 사전 승인·하루 1건 정책은 적용하지 않는다.
- 입장 카드는 감사된 복호화 재출력, 구 카드만 명시적 재발급. ‘발급 직후 1회 출력’ 가정으로 되돌리지 않는다.
- DR-01·04 선택 행/대비, DR-07·08 저장/위험 행동, 인쇄·민감 열람·초점·오류 복구는 실제 변경 범위에서 회귀 확인한다. 200% 확대·VoiceOver·물리 인쇄 등 미확인 항목은 완료로 처리하지 않는다.
- 신규 교사 업무는 우리 반 소식의 미리보기·숫자 공개 제어·안내 작성으로 제한한다. 기존 안전 업무보다 앞에 별도 통계 대시보드를 추가하지 않는다.

## 10. 설계 근거와 판정 한계

처음에는 핵심 정보만 보여주고 필요할 때 상세를 열게 하는 구조를 적용했다. 다만 도움·쉬기·숨김은 발견하기 어렵게 숨기지 않는다. [NN/g Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)

간격·열 수·학급 집계의 최소 표본 수는 이 프로젝트의 제안값이다. 외부 문서가 아동에게 최적이라고 검증한 값으로 표현하지 않는다. 접근성 기준의 근거는 §4·6에 연결했고, 실제 검증과 미확인 범위는 [이번 검토 기록](design-reviews/2026-09-28-student-experience-plan.md)에 구분한다.

## 11. 2026-09-28 후속 적용 — 변경된 메뉴와 화면 간격

이 절은 v2.0 작성 뒤 구현된 메뉴를 기준으로 추가했다. 위 §1.1의 `이번 신규 계획 · 미구현`과 §9의 `신규 교사 업무` 문장은 **작성 당시의 상태**다. 현재 구현·검증 범위는 [작업일지](work-log.md)와 아래 표를 기준으로 읽는다. 학생 서비스 전체 디자인 완료나 실제 아동 사용성 통과를 선언하지 않는다.

### 11.1 현재 메뉴와 과업

| 서비스 | 메뉴·진입 | 한 화면의 목적 |
|---|---|---|
| 교사 | 운영 요약 | 도움 요청 → 쪽지 대화 → 접속·활동 → 일정의 우선순위와 바로가기 |
| 교사 | 시즌 설정 | 기본 정보 → 참가자·제외 → 미션 → 쪽지 → 확인·저장, 시즌 운영 |
| 교사 | 배정 확인 | 감사된 경로로 시즌의 일대일 매칭을 확인 |
| 교사 | 입장 카드 | 명부·개인 코드·전체/선택 인쇄·차단/재발급 |
| 교사 | **상태 확인** | 학생 기록 / 도움 요청 / 쪽지 관리 / 접속 지원 중 한 업무를 선택해 처리 |
| 교사 | 지난 활동 | 공개·보관된 시즌 확인과 다음 시즌 준비 |
| 교사 | **정보 요청·삭제** | 학생의 정보 요청 **접수 내역**과 학급 전체 영구 삭제를 구분. 자동 정정·삭제 기능은 없음 |
| 학생 | 홈 / 미션 / 우편함 / 우리 반 | 본인 다음 행동 / 내 미션 / 두 관계별 쪽지 / 배려 예시·교사 안내 |
| 학생 공통 | 선생님 도움 / 활동 마치기 | 페이지와 관계없이 찾을 수 있는 안전·공용기기 종료 경로 |

종전 `안전 확인` 메뉴를 삭제한 뒤 안전 업무를 숨기지 않기 위해 `상태 확인`의 도움 요청·쪽지 관리로 이동했다. 상태 확인 첫 진입에 처리할 도움 요청이 있으면 그 업무를 먼저 보여주고, 운영 요약의 카드에서는 해당 업무로 직접 이동한다. 40명 학생 카드와 쪽지·접속 업무를 한 세로 목록에 모두 늘어놓지 않는다. 학생별 집계는 지원용 비공개 정보이고 순위·평가 표로 만들지 않는다. 학생 관계와 쪽지 원문을 학생 화면에 추가하지 않는다.

### 11.2 이번 디자인 수정 결과

| 항목 | 이전 상태 → 이번 수정 | 확인 기준 |
|---|---|---|
| 교사 정보 구조 | 상태 확인에 학생 카드 최대 40개, 도움, 대화, 접속이 순서대로 이어짐 → 네 업무 선택과 한 패널 표시 | 선택한 업무 제목·상태가 보이고 다른 업무까지 긴 스크롤을 요구하지 않음 |
| 안전 원문 | 상태 화면의 다른 영역으로 이동해도 열린 원문이 남을 수 있음 → 업무 전환 시 원문·열림 상태를 가림 | 원문 열기→다른 업무 전환→복귀에서 다시 명시적으로 열어야 함 |
| 학생 간격 | 공통 카드 버튼의 margin과 부모 gap, 모바일 버튼 자동 확장이 혼재 → 학생 영역에서 그룹 gap과 주요 버튼 폭을 지정 | 320/360/390/768/1280px에서 긴 문장·버튼의 무게·줄바꿈 확인 |
| 초점 | 미션 상세 제목의 focus outline 제거 → 프로그램 초점에도 테두리를 표시 | 키보드로 상세 진입 시 현재 읽기 위치가 보임 |
| 메뉴 문서 | 구 `안전 확인`·`학급 설정` 위주 설명 → 위의 현재 메뉴와 실제 기능 설명 | 메뉴 문구와 페이지 목적을 화면·문서에서 일치시킴 |

이번 범위는 [6개 가상 전문가 관점의 사전·사후 검토](design-reviews/2026-09-28-design-plan-v2-menu-alignment.md)를 따른다. 가상 콘텐츠 브라우저에서 320·360·390·768·1280px의 가로 넘침 0, 교사 상태 업무 선택의 1/2/4열, 학생 메뉴의 2/4열, 미션 상세 초점 표시를 확인했다. 개발 서버 첫 화면은 빈 화면·오류 오버레이·콘솔 오류 없이 로드됐다. 이는 로컬 화면 근거이며 배포 인증 후 교사 실제 흐름, 200% 확대, VoiceOver, 학교·보호자 절차를 거친 학생/교사 사용성 관찰은 별도 검증 대상이다.

## 12. 2026-09-28 후속 적용 — 학생 첫 과업과 복귀

§3~6의 학생 화면 설계를 현재 두 관계별 대화와 비밀 유지 정책에 맞춰 다시 적용했다. [사전·사후 6개 가상 역할 검토](design-reviews/2026-09-28-student-design-plan-implementation.md)에 각 판단과 검증 범위를 적는다.

| 계획 항목 | 반영 결과 |
|---|---|
| 화면 이동 | 학생의 네 메뉴를 실제 경로 링크로 표시하고 현재 화면을 `aria-current`로 알린다. 메뉴·보조 이동 후 페이지 제목에 키보드 초점을 둔다. |
| 홈의 첫 과업 | 시즌 상태·기간, 내 미션 한 줄 요약, 이번 미션·완료 버튼을 첫 카드로 묶었다. 390×844px의 가상 긴 문장 화면에서 완료 버튼이 첫 화면에 들어온다. |
| 미션 탐색 | 필터 결과 0건에서 전체 미션으로 돌아간다. 8개 더 보기 뒤 새로 추가된 첫 항목에 키보드 초점을 둔다. 상세 닫기 뒤 원래 목록 버튼 복귀는 유지한다. |
| 우편함 | 사용자 요청에 따른 ‘내가 맡은 친구/나를 맡은 친구’ 두 대화를 유지한다. 긴 대화 위에서 해당 관계의 작성 영역으로 이동하는 버튼을 추가했다. 보내는 대상 한 명과 이름 비공개 정책은 그대로다. |
| 지난 활동 | 기존 `listStudentRounds`의 시작 시각을 한국 날짜로 표시하고 공개·보관 상태와 열림 상태를 붙였다. 서버 계약은 변경하지 않았다. |
| 오류·제목 | 저장 성공 후 최신 조회가 실패하면 성공 알림을 지우고 재조회 안내를 보여 준다. 우편함·도움·지난 활동의 페이지 제목을 최상위 제목으로 정리했다. |

가상 콘텐츠 로컬 브라우저에서 320/360/390/768/1280px과 320px의 200% 글자 확대를 확인했다. 전체 가로 넘침과 검사한 텍스트 잘림은 0이다. 실제 인증된 학생 화면과 키보드 동작의 종단 간 검증, VoiceOver, 실제 학급 사용성 관찰은 별도 확인이 필요하다. §3.4의 수치형 학급 집계는 서버 공개 계약과 추론 위험 검증이 준비되지 않아 여전히 구현하지 않는다. 우리 반 화면은 검토된 배려 예시와 교사 안내를 제공한다.
