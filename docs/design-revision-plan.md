## 1. 결론과 이번 작업의 범위

현재 화면은 기능을 실행할 수 있는 초기 구현이지만, 교사와 초등학생이 수업 중 편하게 사용하는 서비스의 디자인 완료 기준을 충족하지 못한다. 핵심 문제는 **업무 단위가 없는 긴 화면, 선택 요소의 실제 배치 결함, 안전 업무와 주요 행동의 낮은 발견성, 상태·오류 안내 부족**이다. 색상과 둥근 모서리만 조정해서 해결할 수 없다.

기존 빌드·함수·Rules·통합 테스트의 통과는 해당 기능과 권한 조건에 대한 결과다. 로그인 화면 렌더링, 버튼 높이, 일부 화면의 가로 넘침 검사는 정보 구조·시각적 완성도·학생 이해도에 대한 통과 근거가 아니다. 이번 검토에서 기존 화면의 디자인 완료 판정은 **수정 필요**로 기록한다.

이번 산출물은 문제 목록, 역할별 개편안, 화면 배치·상태 명세, 수정 순서와 검수 기준이다. 제품 코드·배포 설정·클라우드 학급 데이터를 수정하는 작업은 포함하지 않는다. 가상 전문가 프로파일을 Codex 한 에이전트가 역할별로 적용했으며, 외부 전문가 6명이 실제 자문하거나 실제 교사·학생이 사용성 시험을 마친 것으로 표현하지 않는다.

### 1.1 유지할 제품 원칙

- 대한민국 초등학교 교사와 1~6학년 학생, 교사·학생 서비스 분리, 같은 학급의 반복 회차 운영.
- 학생 이메일·SNS 가입 없음, 개인 카드 입장, 친구 이름 기본 가림, 공용기기 로그아웃.
- 서버 매칭·권한·안전 검토·감사 기록 유지. 화면 분리 때문에 전체 배정표를 클라이언트에 미리 적재하지 않는다.
- 도움 요청, 쪽지 숨김, 미션 교체·쉬기에 불이익 없음. 순위·인기·완료율 경쟁을 추가하지 않는다.
- React·TypeScript·Vite, Firebase 백엔드, Vercel 웹 배포 유지.

### 1.2 검토한 자료와 한계

| 구분 | 이번 확인 범위 | 해석 |
|---|---|---|
| 사용자 보고 | 전체 UX/UI 불만, 한 페이지 집중, 선택 목록 깨짐 | 검토의 출발점이며 모든 문제의 재현을 대신하지 않음 |
| 코드 | `0e9275c`의 `main.tsx`, `TeacherRounds.tsx`, `StudentRound.tsx`, `RightsRequests.tsx`, `style.css`, 계획서·작업일지·6개 프로파일 | 조건부 화면과 미실행 상태는 코드 근거로 구분 |
| 실제 브라우저 | Chrome, 로컬 `demo-manitto`, 1512×889 CSS px. 가상 교사·40명 학급의 새 회차 선택 목록과 진행 회차, 로그인 전 학생 화면 | 화면 길이·위치·계산 스타일·체크박스 선택 및 초점 표시 확인 |
| 수치 | 기본 활성 버튼 색 대비, 교사 페이지 높이와 섹션 위치, 선택 행과 input 폭 | 수치는 해당 콘텐츠·폭의 관찰값이며 모든 기기에 일반화하지 않음 |
| 미확인 | 학생 인증 후 전체 흐름, 320·360·390·768·1280 실제 렌더링, 200% 확대, VoiceOver, 실제 인쇄, 실패·복구 전 시나리오, 교사·학생 사용성 시험 | 이번 디자인 검토에서 통과로 계산하지 않음 |

반응형 도구에 크기를 지정했지만 실제 `innerWidth`가 1512px로 유지되어 해당 시도를 모바일 검증으로 인정하지 않았다. 학생 역할 테스트용 인증 준비에서도 학생 홈에 정상 진입한 증거를 얻지 못했다. 학생 인증 후 화면의 지적은 아래에서 명시한 **코드 분석** 근거다. 이는 제품의 학생 카드 로그인이 실패했다는 판정과 다르다.

검토 화면에는 새로 만든 로컬 가상 데이터만 조작했다. 배포 화면에 열려 있던 실제 학급은 수정하거나 카드·배정표를 추가 열람하지 않았다. 개인정보와 카드 원문은 이 문서나 증거 파일에 복사하지 않는다.

## 2. 대표 문제와 재현 근거

### 2.1 먼저 해결할 구조적 결함

**DR-01 · P1 · 선택 항목의 체크박스와 라벨이 분리됨**

- 근거: [교사 선택 폼](../web/src/TeacherRounds.tsx)의 참가 학생·미션·자유 쪽지 설정, [스타일](../web/src/style.css). 브라우저에서 미션 라벨의 계산 `display`가 `block`, 항목과 input 폭이 각각 250px로 같았다. 체크박스 그림은 가운데, 문장은 다음 줄에서 시작했고 Tab 초점 테두리가 문장 위를 지나갔다.
- 원인: 후반의 `.teacher-layout>.panel label`이 `.stack label.check-line`의 flex 배치를 덮어쓴다. `.teacher-layout>.panel label input`의 높은 명시도가 체크박스에도 전체 폭·패딩을 적용한다. 미션 그리드만의 문제가 아니므로 참가자·자유 쪽지도 함께 수정해야 한다.
- 영향·근거: 근접성, H4·H5·H6. 어떤 문장에 체크했는지 다시 확인하게 만들고 초점 식별을 방해한다. 다만 확인한 체크박스의 실제 선택은 가능했다. 이를 ‘모든 체크박스가 클릭 불가능’이라고 확대하지 않는다.
- 수정: `CheckboxRow`를 텍스트 입력과 별도로 정의한다. native checkbox, 첫 줄 정렬, 8~12px 간격, 라벨 전체 클릭, 선택 배경과 체크 표시, 내용만큼 늘어나는 높이. 광범위한 후손 선택자에 덧칠하지 않는다.
- 완료 확인: 참가자·미션·자유 쪽지 각각에서 문장 클릭과 Space가 같은 항목만 변경하고, 초점이 문장을 가리지 않으며 320~1280px·긴 문장·200% 확대에서 연결이 유지된다.

**DR-02 · P1 · 교사 운영 업무가 긴 명부 뒤에 묻힘**

- 근거: [교사 메인 구성](../web/src/main.tsx)의 `teacher-columns` 뒤에 `TeacherRounds`, 정보 요청, 학급 삭제가 순서대로 배치된다. 40명 가상 학급의 새 회차 화면은 높이 **6,637px**, ‘회차 운영’ 제목은 문서 상단에서 **약 3,784px** 아래였다. 학급을 선택해도 기본 회차 선택값은 ‘새 회차’여서 진행 회차로 다시 이동해야 했다.
- 영향·근거: H2·H6·H7·H8. 수업 중 도움 요청을 확인하려는 교사가 학급 생성·학생 등록·카드 40행을 지나가야 한다. 화면 상단에 안전 업무 순서를 문장으로 적는 것만으로는 우선순위가 구현되지 않는다.
- 수정: 학급 선택 후 ‘운영 요약’을 첫 화면으로 제공한다. 학생·카드, 회차, 안전 확인, 기록, 학급 설정을 과업별 페이지로 나눈다. 도움 요청·검토할 쪽지는 항상 접근 가능한 메뉴와 요약의 첫 영역에 둔다.
- 완료 확인: 40명·진행 회차·대기 도움 1건에서 명부를 스크롤하지 않고 운영 요약 첫 화면에서 요청을 발견하고 상세에 들어간다. 긴 명부 페이지의 세로 스크롤 자체는 결함으로 보지 않는다.

**DR-03 · P1 · 학생 화면도 여러 과업을 한 번에 요구함**

- 근거: [학생 홈](../web/src/main.tsx)은 인사·약속·친구·`StudentRound`·지난 회차·새 소식·정보 요청·종료를 이어 붙인다. [학생 활동](../web/src/StudentRound.tsx)은 미션·쪽지 작성·보낸 상태·받은 쪽지·도움 폼을 함께 렌더링한다. 코드 분석이며 인증 후 화면의 실제 길이는 이번에 측정하지 않았다.
- 영향·근거: H8·H10, 한 화면 한 과업. 학생에게 지금 할 일보다 설명과 양식이 먼저 많아지고, 도움이 필요한 순간 긴 화면을 탐색하게 한다.
- 수정: 학생 기본 탐색은 ‘오늘 / 우편함 / 지난 활동’으로 줄인다. ‘선생님 도움’과 ‘활동 마치기’는 공통 영역에 고정한다. 오늘 화면에는 가린 친구 봉투와 현재 미션 1개를 우선 표시하고 나머지는 명확한 ‘다른 미션 보기’로 접근한다.
- 완료 확인: 390px에서 현재 할 일과 도움 진입점을 찾기 위해 여러 업무 폼을 지나지 않는다. 도움은 모든 활동 상태에서 한 번의 명시적 진입으로 열리며, 개인정보 관련 요청은 도움 화면 안에서 계속 접근 가능하다.

**DR-04 · P1 · 주요 버튼의 글자 대비 부족**

- 근거: 기본 활성 버튼 `#F46D67` 위 `#FFFFFF`의 대비는 **2.90:1**이다. 학생 입장·설정 저장 등 16px 수준의 버튼에 적용된다. CSS 색으로 상대 휘도를 계산했으며 브라우저의 동일 색도 확인했다.
- 영향·근거: 읽기 어려움, UI-02. 일반 텍스트의 목표 4.5:1에 미달한다. 버튼 높이를 48px로 키워도 글자 대비 문제는 해결되지 않는다.
- 수정: 코랄은 브랜드 장식에 유지하고 활성 버튼은 더 진한 색을 쓴다. 시작 후보 `#B94440` + 흰 글자는 **5.30:1**이다. hover·focus·disabled까지 실제 배경에서 별도 검토한다.
- 완료 확인: 일반 버튼 문구 4.5:1 이상, 상태·초점을 색만으로 전달하지 않음. 이 한 쌍의 개선을 WCAG 전체 준수로 보고하지 않는다.

## 3. 새 정보 구조와 이동 방식

### 3.1 교사: 학급 맥락 안에서 업무별로 이동

```text
선생님 로그인 / 승인 대기
└─ 내 학급 선택
   └─ 선택한 학급 [학년도 · 학년군 · 진행 회차 상태]
      ├─ 운영 요약       도움 → 검토 쪽지 → 지원할 활동 → 일정
      ├─ 학생·입장 카드  명부 / 등록 / 카드 발급·인쇄·재발급
      ├─ 회차            진행 회차 / 준비 중 / 새 회차 준비
      ├─ 안전 확인       도움·신고 / 검토할 쪽지 / 안전 열람
      ├─ 지난 활동       공개·보관 회차 / 회고 / 설정 복사
      └─ 학급 설정       학급 정보 / 정보 요청 / 위험 작업
```

메뉴 수를 줄이기 위해 안전 확인을 ‘더 보기’ 아래에 숨기지 않는다. 학생·입장 카드는 반복적인 수업 준비 업무이므로 별도 페이지다. 회차 준비는 순서가 있는 단계형 폼, 안전 검토는 반복 처리에 맞는 목록과 상세, 회차 기록은 읽기 중심 페이지로 구성한다. 모든 기능을 하나의 큰 탭 안에 그대로 넣는 변경은 해결로 인정하지 않는다.

| 화면 | 목적·첫 주요 행동 | 섹션 순서와 저장 범위 | 복귀 |
|---|---|---|---|
| T-R01 내 학급 | 학급 선택 / 처음이면 학급 만들기 | 학급 목록, 새 학급은 별도 폼. 생성 1건 저장 | 선택 후 운영 요약 |

## 4. 핵심 과업별 수정 설계

### 4.1 새 회차 준비: 네 단계와 명확한 저장

1. **기본 정보:** 주제, 기간, 수업일 5/10일. 한국 시간 기준을 명시하고 달력과 선택 날짜 목록을 함께 제공한다. 휴일을 자동으로 안다고 가정하지 않고 교사가 제외·대체할 수 있게 한다.
2. **참가자·제외:** 4~40명, 선택 인원과 미선택 인원 표시, 전체 선택/해제와 이름 검색. 입장 제한 학생은 이유와 함께 선택 불가. 제외 관계는 참가자로 범위를 제한하고 두 학생을 선택한 뒤 양방향 제외임을 확인한다. 임의 UID 뒷자리를 사용자 식별자로 노출하지 않는다. 동명이인 구분 방법은 기존 표시 이름 정책과 함께 확정한다.
3. **미션·쪽지:** 학년군과 선택 개수 `0/3` 표시. 3개 선택 후 나머지는 이유와 함께 선택 제한하되 기존 항목 해제는 가능. ‘선택형만’과 ‘선생님 검토 후 직접 쓰기도 허용’을 하나의 선택 구조로 보여준다. 자유 쪽지의 일일 합산 한도·검토 책임을 선택 바로 옆에 안내한다.
4. **검토·시작:** 주제·기간·수업일·인원·제외 관계 수·미션 3개·쪽지 정책을 요약하고 각 항목에 ‘수정’을 제공한다. 서버 조건 확인 결과를 보여준 뒤 ‘매칭하고 시작’을 최종 확인한다. 시작 후 재추첨 불가와 안전 문제 시 일시정지·취소 후 새 회차 운영을 안내한다.

**저장 계약:** 현재 `createRound/updateRound`는 완전한 설정을 받는다. 처음 세 단계의 ‘다음’은 브라우저 메모리의 입력 이동이며 서버 저장 성공처럼 표시하지 않는다. 마지막 유효 설정을 ‘준비 내용 저장’으로 저장하고 서버 성공을 받은 뒤에만 저장됨으로 표시한다. 이미 저장된 회차의 수정도 마지막 검토에서 한 번 저장한다. 단계마다 서버 초안을 저장하려면 별도 부분 초안 계약을 먼저 설계해야 하며 이 계획만으로 해당 API가 존재한다고 가정하지 않는다.

미저장 상태의 메뉴 이동에는 ‘계속 작성 / 입력 버리고 이동’을 제공한다. 새로고침 시 메모리 입력은 복원되지 않을 수 있음을 알린다. 학생 이름·제외 관계를 localStorage나 URL에 보관해 복원하는 방식은 사용하지 않는다. 네트워크 재시도는 같은 작업 ID로 처리하고, 저장 실패와 조건 확인 실패를 구분한다.

### 4.2 교사 안전 확인과 공개

- 운영 요약 최상단의 ‘도움 요청 1건 확인’이 상세 목록으로 연결된다. 세부 원문은 필요할 때만 감사 기록을 남기며 조회한다.
- 대기 쪽지는 발신·수신·원문·현재 상태를 읽은 뒤 승인/반려한다. 완료 후 상태를 해당 카드에 표시하며 다음 건을 처리할 수 있게 한다. 실패한 카드를 성공 목록으로 옮기지 않는다.
- ‘활동 종료’는 새 제출을 닫고 공개 대기로 이동한다. ‘정체 공개’는 별도 단계다. 두 버튼에 같은 설명·성공 문구를 쓰지 않는다.
- 공개 준비 화면은 미처리 도움·신고·대기 쪽지를 나열하고 해결할 화면으로 연결한다. 공개 불가 버튼만 회색으로 만들지 않는다. 최종 서버 검증이 우선이며, 화면을 읽은 뒤 새 요청이 생기면 다시 안내한다.
- 확인 대화상자는 학급·회차, 대상과 결과, 되돌릴 수 있는지, 확인/취소를 포함한다. 기본 초점은 안전한 행동에 둔다. 모든 평범한 저장에 확인 창을 추가하지 않고 공개·취소·중단·재발급·삭제처럼 영향이 큰 동작에 한정한다.

### 4.3 학생 미션과 쪽지

- 오늘 화면의 첫 과업은 현재 가능한 미션이다. 완료·교체·쉬기는 같은 카드 안에 놓고 쉬기를 숨기거나 실패 색으로 표시하지 않는다. 완료 후에는 작은 상태 변화와 다음 선택을 제공하고 횟수 경쟁·연속 보상을 넣지 않는다.
- 현재 API의 미션에는 개별 배정일 정보가 없다. 날짜 기반 오늘 미션을 서버가 정하지 않는 동안에는 제목을 **‘이번 활동의 미션’**으로 표시한다. 화면이 임의로 미션 날짜를 추정하지 않는다. 일차별 배정은 별도 계약 보완 후 적용한다.
- 우편함은 ‘받은 쪽지’와 ‘보내기/보낸 상태’로 구분한다. 선택형과 직접 쓰기를 동시에 긴 폼 두 개로 펼치지 않는다. 먼저 작성 방식을 정하고 한 장의 쪽지로 전송한다.
- 반려 후에는 ‘오늘은 다시 보낼 수 없어요. 다음 활동일에 새로 전할 수 있어요’와 다음 가능한 날짜를 안내한다. ‘다시 써볼까요’만 보여 당일 재전송을 유도하지 않는다.
- 도움은 이유 선택 → 선택 설명 → 접수 확인의 짧은 흐름으로 한다. 쪽지에서 진입하면 해당 쪽지 맥락을 서버 ID로 이어 주되 URL에는 원문·발신자·이름을 넣지 않는다.

### 4.4 반복 운영·카드·공용기기

- 지난 회차에는 기간·주제·상태를 함께 표시한다. ‘설정 복사’는 복사되는 항목과 복사되지 않는 기록을 설명하고 다음 회차의 날짜 검토 단계로 이동한다.
- 신규 카드 발급 후 ‘인쇄할 카드 확인 → 인쇄 → 명부로 돌아가기’를 제공한다. 원문이 메모리에서만 보관된다는 제약을 떠나기 직전에 안내한다. 일괄 인쇄는 이번 발급·선택한 카드에 한정하고 원문을 서버에 새로 저장하지 않는다.
- 학생 인증 만료·5분 유휴 종료에는 이유를 짧게 알리고 메모리·화면·구독을 정리한다. 유휴 종료 30초 전 선택적 연장 안내를 제공하더라도 5분 종료 정책을 자동으로 늘리지 않는다. 경고 없이 계속 사용하는 학생을 로그아웃시키지 않도록 활동 이벤트 범위를 검토한다.
- 개인 로그아웃과 회차 종료는 다른 용어·위치·스타일로 구분한다. 개인 카드 보기, 학생 친구 보기, 안전 원문 보기에는 모두 명시적 ‘가리기/닫기’가 있어야 한다.

## 5. 시각 디자인과 대표 배치

### 5.1 방향: 학생은 따뜻한 활동 공간, 교사는 정돈된 운영 화면

기존 [UI 콘셉트](ui-concept.md)의 크림색·코랄·봉투 모티프는 유지한다. 다만 모든 콘텐츠를 큰 둥근 카드에 넣거나 모든 버튼을 코랄로 강조하지 않는다. 학생에게는 친구 봉투·활동 완료처럼 의미 있는 순간에 그림과 작은 움직임을 사용하고, 교사에게는 현재 업무·상태·목록 가독성이 먼저 보이게 한다. 이모지 모양은 운영체제마다 달라지므로 핵심 아이콘은 일관된 스타일로 정하고 반드시 텍스트를 함께 제공한다.

아래는 검토용 디자인 기준안이다. 아직 완성 시안이나 구현된 컴포넌트가 아니며, 실제 한국어 콘텐츠를 넣은 시안에서 6개 관점이 재검토해야 한다.

| 항목 | 기준안 | 적용 이유·검수 |
|---|---|---|
| 기본 배경 | 따뜻한 크림 `#FFF8ED`, 콘텐츠 흰색 | 장식의 대비를 줄이고 읽는 영역 구분 |
| 본문 | `#283449`, 보조 문구는 명도만 과도하게 낮추지 않음 | 흰색·크림 위 대비 확인 |
| 주요 행동 | 진한 코랄 `#B94440` + 흰 글자 후보 | 계산 대비 5.30:1. 실행 버튼과 장식 코랄을 분리 |
| 보조 행동 | 중립 테두리·본문색 또는 목적 있는 청색 | 모든 보조 버튼을 위험 작업처럼 붉게 표현하지 않음 |
| 위험 행동 | 경고 아이콘+명확한 동사+결과 설명 | 색만으로 위험을 전달하지 않음 |
| 글자 | 교사 본문 16px, 학생 본문 18px를 기본 후보로 검토. 설명은 원칙적으로 14px 이상 | 학생 본문 행간 1.5~1.7. 제목 24~32px, 인사보다 과업을 크게 |
| 간격 | 4·8·12·16·24·32·48px 단계 | 관련 요소는 가깝게, 과업은 제목·여백으로 분리 |
| 모서리·그림자 | 입력 10~12px, 교사 패널 16px, 학생 강조 카드 20~24px 후보 | 30px 카드와 큰 그림자를 모든 영역에 반복하지 않음 |
| 버튼 | 교사 주요 터치 영역 44×44px 이상, 학생 48×48px 이상 | 글자·포커스·터치 영역을 함께 확인; 높이만 측정하지 않음 |
| 학생 본문 폭 | 데스크톱 최대 약 640px, 모바일 가용 폭 | 짧은 과업의 읽기 거리 유지 |
| 교사 본문 폭 | 전체 최대 약 1280px, 폼 읽기 영역 약 720~840px | 넓은 표와 좁은 폼을 같은 폭으로 강제하지 않음 |

### 5.2 교사 운영 요약 배치 명세

```text
┌──────────────────────────────────────────────────────────┐
│ 우리 반 비밀친구     [가상 학급 ▾]  2026 · 5~6학년  로그아웃 │
├─────────────┬────────────────────────────────────────────┤
│ 운영 요약 ● │ 운영 요약                                  │
│ 학생·카드   │ 진행 회차 주제 · 진행 중 · 종료일            │
│ 회차        │                                            │
│ 안전 확인 2 │ 가장 먼저 확인해 주세요                    │
│ 지난 활동   │ [도움 요청 1건 보기] [검토할 쪽지 1건 보기]   │
│ 학급 설정   │                                            │
│             │ 접속·활동 지원          이번 활동 일정       │
│             │ 비공개 목록 바로가기    기간 / 다음 활동일   │
│             │                                            │
│             │ [진행 회차 자세히 보기]                     │
└─────────────┴────────────────────────────────────────────┘
```

- 첫 화면에는 새 학급 폼·명부 40행·회차 설정 폼·삭제 양식을 넣지 않는다.
- 안전 건수 0이면 ‘지금 확인할 요청이 없어요’로 표시하며 학생 수행률을 대신 강조하지 않는다.
- 진행 회차가 없으면 ‘새 회차 준비’와 ‘지난 설정으로 준비’를 제공한다. 처음 학급은 학생 등록→카드→회차의 다음 단계 한 가지를 안내한다.
- 태블릿에서는 탐색을 상단 메뉴로, 모바일에서는 ‘학급 메뉴’ 버튼과 현재 페이지 제목으로 바꾸되 안전 확인 바로가기는 유지한다.

```text
새 회차 준비                         준비 내용: 아직 저장 전
1 기본 정보 ─ 2 참가자 ─ [3 미션·쪽지] ─ 4 검토·시작

┌─────────────────────────────────────────────────┐

│    말하기 · 교실에서 할 수 있어요                │
└─────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────┐
│ ☐  친구가 부담스럽지 않은 방식으로 도움 제안하기 │
│    돕기 · 원하지 않으면 멈춰요                   │

쪽지는 어떻게 쓸까요?
(●) 준비된 문구로만 보내기
( ) 직접 쓰기도 허용하기 — 선생님 검토 후 전달

[이전]                              [검토 단계로]
```

설명·태그는 검토된 콘텐츠가 있을 때만 사용한다. 없는 콘텐츠를 임의로 생성해 넣지 않는다. 선택 요약과 다음 행동은 서로 가까이 배치하고 모바일에서 고정 하단을 쓰면 마지막 선택 행이 그 아래 숨지 않게 한다. 고정 하단이 가상 키보드와 충돌하면 일반 문서 흐름으로 전환한다.

## 6. 공통 UI와 상태 계약

### 6.1 컴포넌트 단위

`TeacherShell`, `StudentShell`, `PageHeader`, `StatusBadge`, `TaskSummary`, `FormField`, `CheckboxRow`, `MissionChoice`, `StudentRow`, `MessageCard`, `ConfirmDialog`, `EmptyState`, `InlineFeedback`를 우선 정의한다. 이름은 구현 후보이며 새 라이브러리 도입을 의미하지 않는다. 기존 코드를 분리하면서 광범위한 `.panel label input` 같은 규칙을 역할 있는 컴포넌트 스타일로 교체한다.

| 상태 | 화면 표시 | 조작·접근성 | 복구·저장 |
|---|---|---|---|
| 기본 | 현재 과업과 허용 행동 | 명시적 라벨·제목 순서 | 읽기와 쓰기 구분 |
| 초점 | 일관된 대비의 테두리, 잘림 없음 | Tab 순서·Space/Enter 유지 | 페이지 이동 후 제목/본문 시작, 대화상자 종료 후 트리거 복귀 |
| 선택 | 체크/라디오와 텍스트·배경 함께 변경 | 이름·역할·선택 상태 전달 | 선택 개수·제약 즉시 갱신 |
| 조건 미충족 | 버튼 근처에 필요한 조건 | 모든 비활성 버튼에 `cursor:wait`를 쓰지 않음 | 조건 충족 경로 제공 |
| 처리 중 | ‘저장 중’, ‘보내는 중’처럼 대상 행동 표시 | 해당 작업 중복 제출 방지, 관련 영역 `aria-busy` | 입력 보존, 작업 ID 유지 |
| 성공 | 해당 항목에서 실제 결과 설명 | `role=status` 등 과도하지 않은 상태 알림 | 서버 성공 후에만 이동·초기화 |
| 입력 오류 | 필드별 원인·예시와 오류 요약 | 오류와 입력 연결, 첫 오류로 초점 | 다른 정상 입력 보존 |
| 통신/서버 오류 | 짧은 원인과 재시도 | 기술 코드·원문 로그 노출 금지 | 같은 요청 재시도, 권한 오류는 재로그인 경로 |
| 빈 상태 | 데이터가 없는 이유 | 다음 행동이 있으면 하나 제시 | 실패를 빈 상태로 처리하지 않음 |
| 취소/이탈 | 저장 여부·영향 설명 | Escape·뒤로·취소, 초점 복귀 | 민감 데이터 브라우저 저장소에 남기지 않음 |

### 6.2 교사 회차 상태별 행동

| 상태 | 주요 표시 | 가능한 주요 행동·제약 |
|---|---|---|
| 준비 중 | 저장된 준비 내용 / 수정 중 여부 | 수정, 조건 확인, 취소 |
| 시작 준비 완료 | 최종 요약·조건 확인됨 | 확인 후 매칭 시작. 수정하면 준비 상태 재확인 |
| 진행 중 | 기간·안전 요청·제출 가능 상태 | 안전 처리, 일시정지, 활동 종료. 취소는 별도 위험 작업 |
| 일시정지 | 학생 제출 중단과 이유 안내 | 안전 처리, 정책상 가능한 재개. 원래 종료 시각 전일 때만 연장 |
| 공개 대기 | 공개를 막는 도움·쪽지 건수 | 안전 정리와 공개 준비. 신규 제출·재개 없음 |
| 공개 완료 | 감사·회고 진행 상태 | 기록 확인, 보관, 다음 회차 준비 |
| 보관/취소 | 종료된 기록임을 명시 | 설정 복사와 정책상 허용 조회. 과거 도움·신고의 안전 처리 경로 유지 |

### 6.3 학생 상태별 문구와 다음 행동

| 상태 | 권장 문구 예시 | 가능한 행동 |
|---|---|---|
| 회차 없음 | ‘선생님이 다음 활동을 준비하고 있어요.’ | 지난 활동·도움·로그아웃 |
| 진행 중·활동 가능 | ‘이번 활동의 미션을 하나 골라 해 봐요.’ | 친구 보기, 미션, 허용된 쪽지, 도움 |
| 수업일 아님 | ‘오늘은 쪽지를 쉬는 날이에요.’ | 가능한 조회·도움, 다음 활동일 안내 |
| 일시정지 | ‘지금은 활동을 잠깐 쉬고 있어요.’ | 비밀·기록 조회는 권한에 따라, 도움·로그아웃 |
| 공개 대기 | ‘활동이 끝났어요. 선생님이 친구 공개를 준비하고 있어요.’ | 허용된 기록·도움. 새 전송 없음 |
| 참여 중단/접근 철회 | ‘선생님께 활동 안내를 받아 주세요.’ | 서버 권한에 맞는 최소 화면; 다른 학생 관계 표시 없음 |
| 공개 완료 | ‘나를 챙겨 준 친구를 확인할 수 있어요.’ | 이름은 눌러 보기, 허용 관계의 감사·회고 |
| 보관 | ‘지난 활동의 기록이에요.’ | 읽기, 과거 쪽지 숨김·도움. 회고 수정 없음 |
| 유휴 로그아웃 | ‘잠시 쉬는 동안 활동을 안전하게 닫았어요.’ | 비어 있는 카드 입장 화면 |

문구는 후보이며 실제 저학년 이해도는 관찰이 필요하다. ‘공개’, ‘회차’, ‘열람·정정’ 같은 운영 용어를 학생에게 그대로 반복하지 않는다. ‘내 기록 보기 / 잘못된 내용 알리기 / 지워 달라고 요청하기’처럼 행동 중심으로 바꾸고, 요청 접수가 즉시 삭제 완료가 아니라는 점은 유지한다.

## 7. 반응형·접근성·내용 길이 규칙

| 폭 | 교사 레이아웃 | 학생 레이아웃 | 선택 목록 |
|---|---|---|---|
| 1280px 이상 | 학급 맥락+사이드 탐색+본문. 폼 폭 제한 | 가운데 과업 열, 장식은 부차적 | 참가자 최대 3~4열은 실제 이름 길이로 판단. 미션 최대 2열 |
| 768px | 상단 탐색, 본문 1열. 필요한 표만 영역 내 스크롤 | 과업 1열 유지 | 참가자 2열 후보, 미션 1열 우선 |
| 390·360px | 현재 페이지 제목+메뉴, 모든 폼 1열 | 16px 안팎 외곽 여백, 도움·마치기 접근 유지 | 참가자·미션 1열, 라벨 전체 클릭 |
| 320 CSS px 상당 | 핵심 문장·버튼 손실 없이 재배치 | 하단 메뉴와 본문 겹침 금지 | 긴 단어도 줄바꿈, 고정 최소 폭 제거 |

- 긴 한국어 문장은 자연스럽게 줄바꿈하고 텍스트 박스에 고정 높이·말줄임을 적용하지 않는다. 미션의 핵심 문구를 줄여서 화면 검사를 통과시키지 않는다.
- 이름·회차 제목은 서버의 최대 입력 길이, 띄어쓰기 없는 문자열, 두 줄 이상을 포함해 검사한다. 목록이 비어 있을 때와 4·23·40명일 때를 모두 확인한다.
- 기본 입력은 native 요소와 연결된 라벨을 사용한다. 체크박스 그림 크기와 라벨 포함 터치 영역은 별도로 측정한다.
- 페이지 제목 구조, 현재 메뉴 `aria-current`, 대화상자 이름·설명·초점, 결과 알림을 확인한다. 스크린리더의 실제 출력 검증 없이 접근성 완료라고 하지 않는다.
- 확대 200%와 320 CSS px 상당의 재배치는 별개로 확인한다. 메뉴·고정 하단·가상 키보드 때문에 초점과 오류가 가려지는지 포함한다.
- 봉투 열기·완료 효과에는 움직임 감소 설정을 반영한다. 소리·진동·복잡한 애니메이션을 과업 이해의 필수 조건으로 쓰지 않는다.
- 카드 인쇄는 A4, 한 장/여러 장, 긴 표시 이름, 인쇄 취소를 확인한다. 개인 카드가 잘리거나 다른 학생 카드와 섞이지 않도록 경계와 이름을 유지한다.

API·필드·권한이 바뀌면 `docs/functions-api.md`, `docs/firestore-schema.md`, Rules와 관련 테스트를 함께 갱신한다. 현재 단계에서 위 필드를 이미 제공한다고 문서화하거나 프런트엔드 임시 값으로 ‘저장 완료’를 연출하지 않는다.

## 10. 통과 기준과 검증 방식

### 10.1 자동 확인과 사람이 보는 검토를 분리

| 확인 | 자동 확인의 역할 | 추가로 필요한 실제 검토 |
|---|---|---|
| 빌드·단위·Rules·통합 | 컴파일, 권한, 매칭·상태·한도 회귀 | 메뉴 이해·화면 위계·문구·가독성은 증명하지 못함 |
| 화면 크기·넘침 | 의도치 않은 전체 가로 이동과 누락 후보 찾기 | 체크박스-문장 연결, 여백, 열 수, 실제 클릭·초점 |
| 접근성 자동 검사 | 라벨·일부 대비·구조 오류 탐지 | 키보드 과업, VoiceOver의 이름·순서·오류 전달 |
| 화면 캡처 비교 | 승인한 상태의 배치 변화 확인 | 변경이 더 나은지, 상태가 실제로 저장되는지 판단 |
| 사용자 시험 | 과업 수행·오해·도움 요구 관찰 | 소수 표본으로 교육 효과·전체 학생 이해를 일반화하지 않음 |

| V08 | 선택형/자유 쪽지 → 검토·반려·한도·받은 쪽지 | 상태와 다음 가능일, 수신자 임의 지정 없음, 숨김·도움·반응 |
| V09 | 학생 도움·정보 요청 → 재진입 | 설명 없이도 진입점 발견, 접수 상태, 요청과 처리 완료 구분 |
| V10 | 공개·감사·회고·지난 활동 | 기본 가림, 감사 전송 상태, 저장 회고 복원, 보관 후 수정 제한 |
| V11 | 같은 학급 두 회차와 공용기기 전환 | 설정만 복사, 기록 분리, 탭 복귀 가림, 5분 유휴·로그아웃 뒤 이전 정보 0건 |
| V12 | 모바일·태블릿·데스크톱·확대 | 320·360·390·768·1280 및 폭 사이, 200% 글자/브라우저 확대, 실제 스크린샷과 입력 결과 |
| V13 | 키보드·VoiceOver·실패 상태 | 로그인·회차 준비·도움·위험 확인 수행, 초점 복귀, 오류 낭독, 느린 응답·오프라인 재시도 |

초기 합격 목표는 핵심 과제의 진행자 대신 조작 0회, 의도치 않은 공개·삭제·다른 학생 노출 0건, 모든 필수 경로의 완료 가능이다. 시간 목표는 교사 운영 요약에서 도움 상세 찾기 10초 이내, 학생 도움 진입점 찾기 10초 이내를 **잠정 설계 목표**로 삼고 관찰 후 조정한다. 이를 이미 측정한 성공률로 쓰지 않는다.

첫 사용성 확인은 교사 3명 이상, 학생은 1~2·3~4·5~6학년군 각각 2명 이상을 목표로 제안한다. 실제 아동 참여는 학교·보호자 절차를 갖춘 뒤 가상 이름·가상 쪽지로 진행한다. 숫자는 통계적 대표성을 보장하는 기준이 아니다. ‘도움 찾기’, ‘쉬기’, ‘내가 챙길 친구와 나를 챙긴 친구 구분’에서 혼란이 나오면 완료율 평균과 무관하게 설계를 재검토한다.

### 10.3 완료 판정

1. [검토 기록](design-reviews/2026-09-27-ui-ux-audit.md)에 작업 범위별 6개 관점의 사전 판단을 갱신한다. 지금의 계획서 작성 완료는 제품 개발 착수 승인이나 구현 검수 통과가 아니다.
2. 변경 범위의 P0·P1·P2를 해결하고 재현 조건 그대로 확인한다. P3를 남기면 담당·시점·영향을 명시한다.
3. 구현 후 6개 관점이 실제 화면·상태·입력 결과로 모두 통과해야 한다. 확인하지 않은 기기·보조기기·흐름은 ‘미확인’으로 남긴다.
4. 기존 인증·권한·매칭·쪽지·회차 분리 테스트를 변경 범위에 맞게 회귀 실행한다. 배포 전에는 저장소 지침의 필수 테스트를 수행한다.
5. 검수 보고는 `기능 검증 / 디자인 검토 / 접근성 수동 검증 / 사용자 관찰 / 배포 확인`을 구분한다. 하나의 ‘전체 테스트 통과’ 문장으로 합치지 않는다.

## 11. 근거 자료

- [Nielsen의 사용성 휴리스틱](https://www.nngroup.com/articles/ten-usability-heuristics/): 상태 인지·사용자 언어·실수 예방·오류 복구와 과업 중심 검토 기준.
- [W3C Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html): 일반 텍스트 대비 4.5:1의 근거. 이번 활성 코랄 버튼의 2.90:1 계산에 적용.
- [W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html): 320 CSS px 상당의 재배치와 정보·기능 손실 확인. 모든 표의 가로 스크롤을 금지하는 기준으로 해석하지 않음.
- [W3C Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html): AA의 24×24px 및 예외 기준. 이 서비스의 44/48px는 더 크게 잡은 자체 설계 목표.
- [W3C APG Dialog (Modal)](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/): 대화상자 이름·키보드·초점·복귀 설계 참고.

공식 자료는 2026-09-27에 확인했다. 외부 기준은 설계 근거이며 이 서비스 전체의 접근성 인증·아동 이해도·교육 효과를 보증하지 않는다.
